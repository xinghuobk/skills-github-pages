## 一、专业面试题（30道）

### 1. 数据结构与算法

**1. 什么是时间复杂度和空间复杂度？举例说明。**

时间复杂度描述算法运行时间随输入规模增长的变化趋势，空间复杂度描述所需内存空间的变化。

常见复杂度级别：
- **O(1)**：访问数组元素、哈希表查找
- **O(logn)**：二分查找、平衡二叉树操作
- **O(n)**：遍历数组、线性查找
- **O(nlogn)**：快速排序平均、归并排序、堆排序
- **O(n²)**：冒泡排序、选择排序、插入排序
- **O(2ⁿ)**：指数级（如递归斐波那契）

**出处**：深大复试常考题

**2. 数组和链表有什么区别？适用场景？**

| 特性 | 数组 | 链表 |
|------|------|------|
| 内存分配 | 连续内存块 | 分散内存块，指针连接 |
| 访问方式 | 随机访问O(1) | 顺序访问O(n) |
| 插入删除 | 中间插入O(n) | O(1)（只需修改指针） |
| 空间利用 | 固定大小，可能浪费 | 动态分配，按需分配 |
| 缓存友好 | 连续内存，缓存命中率高 | 分散内存，缓存命中率低 |

**适用场景**：
- **数组**：元素数量已知、频繁随机访问、顺序遍历
- **链表**：频繁插入删除、元素数量动态变化、实现栈/队列/图

**出处**：深大2024年复试面试题

**3. 栈和队列有什么区别？各有什么应用？**

| 特性 | 栈(Stack) | 队列(Queue) |
|------|-----------|-------------|
| 操作方式 | 后进先出(LIFO) | 先进先出(FIFO) |
| 插入删除 | 仅在栈顶操作 | 队尾插入，队头删除 |

**栈的应用**：表达式求值与括号匹配、函数调用栈、DFS、撤销操作、递归转非递归

**队列的应用**：BFS、任务调度、缓冲区管理、层次遍历

**扩展**：双端队列(Deque)、优先队列(Priority Queue)

**出处**：深大2023年复试面试题

**4. 二叉树、BST、AVL树、红黑树的区别？**

- **二叉树**：每个节点最多两个子节点。查找/插入/删除 O(n)
- **二叉搜索树(BST)**：左子树所有值 < 根节点值 < 右子树所有值。平均O(logn)，最坏O(n)
- **AVL树**：严格平衡BST，任意节点左右子树高度差 ≤ 1。通过旋转维护平衡。插入删除旋转开销大。
- **红黑树**：近似平衡BST。通过颜色约束保证最长路径不超过最短路径2倍。旋转比AVL少，性能更好。

**应用**：C++ std::map/std::set → 红黑树；Linux进程调度CFS → 红黑树

**出处**：深大2024年复试面试题

**5. 什么是哈希表？如何解决哈希冲突？**

哈希表通过哈希函数将关键字映射到数组索引，实现O(1)平均查找时间。

**解决哈希冲突的方法**：
1. **链地址法**：每个槽位维护一个链表。优点：简单，无二次冲突。Java HashMap, C++ unordered_map
2. **开放地址法**：在表内寻找下一个空槽（线性探测/二次探测/双重哈希）
3. **再哈希**：准备多个哈希函数

**负载因子**：元素数/槽位数，通常0.75是经验值，超过则扩容

**出处**：深大2023年复试面试题

**6. 图的存储方式？BFS和DFS的实现和应用？**

**图的存储**：
- **邻接矩阵**：二维数组，O(V²)空间。检查边O(1)，适合稠密图
- **邻接表**：每个顶点的邻居列表。O(V+E)空间，适合稀疏图

**BFS（广度优先搜索）**：使用队列，逐层扩展。应用：最短路径（无权图）、层序遍历

**DFS（深度优先搜索）**：使用栈（或递归调用栈）。应用：拓扑排序、检测环、连通分量

**出处**：深大2022年复试面试题

**8. 什么是动态规划？和贪心的区别？**

动态规划通过把原问题分解为相对简单的子问题的方式求解复杂问题。适用于有**重叠子问题**和**最优子结构**的问题。

**动态规划三要素**：定义状态、状态转移方程、初始化边界

**动态规划 vs 贪心**：
- **动态规划**：考虑全局最优，当前选择依赖子问题的解
- **贪心**：每步选择当前局部最优，不回溯，不能保证全局最优

**经典DP问题**：背包、LIS、LCS、编辑距离、打家劫舍、最小路径和

**出处**：深大2023年复试面试题

**9. 什么是快速排序？时间复杂度？最差情况如何避免？**

**快排思想**：选择一个基准元素(pivot)，将数组分为小于和大于pivot的两部分，递归排序。

**复杂度**：平均O(nlogn)，最坏O(n²)（已排序且每次选首元素为pivot），空间O(logn)递归栈

**避免最坏情况**：1) 随机选择pivot 2) 三数取中 3) 小数组用插入排序

**出处**：深大2024年复试面试题

---

**10. 什么是归并排序？和快排的区别？**

**归并排序**：将数组分成两半，递归排序后合并。稳定排序，O(nlogn)时间，O(n)空间。适合外部排序。

**和快排的区别**：快排不稳定，原地排序，最坏O(n²)；归并稳定，需额外空间，最坏仍O(nlogn)

**出处**：深大复试常考题

**11. 进程和线程的区别？**

| 特性 | 进程 | 线程 |

**12. 什么是死锁？四个必要条件？如何避免？**

**四个必要条件**：1) 互斥 2) 请求与保持 3) 不可剥夺 4) 循环等待

**15. 什么是文件系统？inode是什么？**

**16. 什么是缓冲区溢出？如何预防？**

**缓冲区溢出**：向缓冲区写入超过容量的数据，覆盖相邻内存，可能被用于执行恶意代码。

**预防措施**：使用安全函数(strncpy)、栈保护(Stack Canary)、地址空间随机化(ASLR)、数据执行保护(DEP/NX)、边界检查语言、fuzzing测试

**17. 什么是IO多路复用？select/poll/epoll区别？**

IO多路复用让单个线程监听多个文件描述符，当某个描述符就绪时通知程序处理。

| 特性 | select | poll | epoll |
|------|--------|------|-------|
| 数据结构 | fd_set位图 | pollfd数组 | 红黑树+链表 |
| 最大连接数 | 通常1024 | 无限制 | 无限制 |
| 工作模式 | LT | LT | LT + ET |
| 拷贝方式 | 每次调用都拷贝 | 每次调用都拷贝 | 通过共享内存 |
| 就绪通知 | 遍历所有fd | 遍历所有fd | 回调机制，只返回就绪fd |
| 时间复杂度 | O(n) | O(n) | O(1)获取就绪 |
| 适用场景 | 连接少且活跃 | 连接少 | 大量连接但只有少数活跃 |

**出处**：深大2024年复试面试题

### 3. 计算机网络

**18. TCP三次握手和四次挥手？**

**三次握手**：
1. Client → SYN(seq=x) → Server
2. Server → SYN+ACK(seq=y, ack=x+1) → Client
3. Client → ACK(ack=y+1) → Server

为什么三次不是两次：确认双方收发能力正常、防止历史滞留连接请求建立无效连接、同步初始序列号

**四次挥手**：
1. Client → FIN → Server
2. Server → ACK → Client
3. Server → FIN → Client
4. Client → ACK → Server（TIME_WAIT等待2MSL）

**TIME_WAIT作用**：确保最后一个ACK能到达，让本次连接的所有报文段消失。

**出处**：深大2024年复试面试题

**20. HTTP和HTTPS的区别？HTTPS工作原理？**

**区别**：HTTP明文传输，HTTPS加密传输（TLS/SSL）；HTTP端口80，HTTPS端口443；HTTPS需要CA证书；HTTPS性能略低。

**TLS握手过程**（简化）：
1. Client Hello：发送支持的加密套件、随机数
2. Server Hello：选择加密套件，发送证书、服务器随机数
3. 客户端验证证书，生成预主密钥，用服务器公钥加密发送
4. 双方通过三个随机数计算出会话密钥
5. 发送Finished消息，验证通道正常

**HTTPS提供**：机密性（对称加密）、完整性（MAC）、身份认证（证书+非对称加密）

**出处**：深大2024年复试面试题

**21. TCP拥塞控制的四个算法？**

1. **慢启动**：cwnd从1MSS开始指数增长，探测网络容量
2. **拥塞避免**：达到ssthresh后线性增长（每个RTT+1MSS）
3. **快重传**：收到3个重复ACK立即重传，不等超时
4. **快恢复**：3个重复ACK时cwnd减半进入拥塞避免，不骤降为1

**现代拥塞控制**：CUBIC（Linux默认）、BBR（Google提出，基于带宽和RTT模型）

**出处**：深大2023年复试面试题

**28. 什么是视图？和表的区别？**

**30. 什么是CAP定理？**

**CAP定理**（Brewer定理）：分布式系统中，一致性(Consistency)、可用性(Availability)和分区容错性(Partition Tolerance)三者不可兼得，最多同时满足两个。

- **一致性(C)**：所有节点在同一时间具有相同的数据
- **可用性(A)**：每个请求都能收到一个响应（不一定是最新数据）
- **分区容错性(P)**：系统在网络分区（节点间通信中断）情况下仍能继续运行

**三种组合**：
- **CP**：保证一致性和分区容错性，牺牲可用性。例如：MongoDB、HBase
- **AP**：保证可用性和分区容错性，牺牲一致性（最终一致）。例如：Cassandra、CouchDB、大多数NoSQL
- **CA**：保证一致性和可用性，无法容忍分区。实际上分布式系统必然存在网络分区，所以CA在实际中意味着单节点系统或放弃P。例如：传统关系型数据库（单节点）

**扩展**：BASE理论（Basically Available, Soft state, Eventually consistent）是对CAP的延伸和补充，强调可用性优先，最终一致性。

**14. 如果你被录取但分配的导师方向和你的兴趣不一致怎么办？**

**参考回答**：

> 这个问题我有考虑过，我认为应该这样处理：
>
> **第一，保持开放和学习的心态**。计算机学科是相通的，不同方向之间的基础知识是共用的。先打好基础比一开始就限定方向更重要。
>
> **第二，积极尝试和了解**。主动和导师沟通，了解这个方向的研究内容和意义。很多时候我们对一个方向不感兴趣只是因为了解不够。
>
> **第三，寻找交叉和结合点**。计算机学科的很多创新都在交叉领域。可以寻找自己原有兴趣和导师研究方向的结合点。比如如果对人工智能感兴趣，但导师研究数据库，可以研究人工智能在数据库优化中的应用。
>
> **第四，如果确实有困难，积极沟通**。经过一段时间尝试，确实发现研究方向不太合适，会坦诚和导师沟通，讨论是否有调整的可能性或者跨方向合作的机会。深大的学术氛围比较开放，相信有沟通的渠道。
>
> **第五，自我驱动学习**。即使研究方向不同，也可以在课余时间自学自己感兴趣的方向。深圳有丰富的学习资源和技术社区。
>
> 总之，会以积极的心态面对各种可能性，把各种经历都视为学习和成长的机会。
