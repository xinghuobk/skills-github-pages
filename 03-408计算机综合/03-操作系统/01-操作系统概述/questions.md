### 题 1

**题干**：下列关于操作系统的说法中，错误的是

**选项**：
(A) 操作系统是计算机系统中最基本的系统软件
(B) 操作系统的主要作用是管理和控制计算机系统的软硬件资源
(C) 操作系统只能为用户提供命令行接口
(D) 操作系统是用户与计算机硬件之间的接口

**标准答案**：$\boxed{C}$

**答案解析**：操作系统不仅提供命令行接口（CLI），还提供图形用户接口（GUI）以及程序一级的系统调用接口。因此 C 选项错误。A、B、D 都是对操作系统地位和作用的正确描述。

**出处**：王道《操作系统》第一章 操作系统概述

### 题 2

**题干**：（2021年408统考第23题）下列关于操作系统的叙述中，错误的是

**选项**：
(A) 操作系统是对硬件系统的第一次扩充
(B) 操作系统管理着系统软件和硬件资源
(C) 操作系统运行时，需要调用CPU的管态/目态等机制
(D) 操作系统是计算机系统中最底层的软件

**标准答案**：$\boxed{D}$

**答案解析**：操作系统并不是最底层的软件。在操作系统之下，还有BIOS/UEFI固件、设备微码等更底层的软件。操作系统是直接运行在裸机之上的第一层系统软件，是对硬件的第一次扩充。A、B、C 描述正确。

**出处**：2021年全国硕士研究生招生考试计算机学科专业基础综合试题第23题

### 题 3

**题干**：操作系统提供给应用程序的接口是

**选项**：
(A) 系统调用
(B) 中断
(C) 库函数
(D) 原语

**标准答案**：$\boxed{A}$

**答案解析**：操作系统通过系统调用（System Call）向应用程序提供服务接口。应用程序运行在用户态，需要操作系统服务时通过陷入（trap）指令进入内核态执行相应的系统调用。库函数是对系统调用的封装，本身不是操作系统直接提供的接口。中断是硬件到操作系统的机制。原语是内核中的原子操作。

**出处**：汤子瀛《计算机操作系统》第一章

### 题 4

**题干**：在单CPU系统中，关于并发性与并行性的说法，正确的是

**选项**：
(A) 并发性和并行性是完全相同的概念
(B) 单CPU系统中不可能实现并发性
(C) 并发性是指多个事件在同一时间间隔内发生，并行性是指多个事件在同一时刻发生
(D) 并发性要求多核CPU支持

**标准答案**：$\boxed{C}$

**答案解析**：并发性（Concurrency）指多个事件在同一时间间隔内发生，通过分时切换实现，单CPU也可实现并发。并行性（Parallelism）指多个事件在同一时刻发生，需要多个CPU或多核支持。因此 C 正确，A、B、D 错误。

**出处**：王道《操作系统》第一章

### 题 5

**题干**：（2019年408统考第23题）下列关于中断和异常的说法中，正确的是

**选项**：
(A) 中断是由CPU内部事件引起的
(B) 异常是由CPU外部事件引起的
(C) 异常的发生与当前执行的指令有关
(D) 中断的响应必须在当前指令执行完成之后

**标准答案**：$\boxed{C}$

**答案解析**：中断是由CPU外部事件（如I/O设备请求）引起的，与当前执行指令无关；异常（内中断）是由CPU内部事件（如除法错误、缺页、系统调用trap）引起的，与当前执行指令有关。因此 A、B 错误，C 正确。D 选项，对于外部中断一般需要在当前指令执行完响应，但异常可在指令执行中途响应，故 D 表述过于绝对，不是最佳答案。

**出处**：2019年全国硕士研究生招生考试计算机学科专业基础综合试题第23题

### 题 6

**题干**：系统调用的目的是

**选项**：
(A) 提供用户进程与内核之间的服务接口
(B) 加快系统的运行速度
(C) 增强系统的可靠性
(D) 提供应用程序之间的通信机制

**标准答案**：$\boxed{A}$

**答案解析**：系统调用是操作系统内核提供给用户进程的服务接口。用户进程通过系统调用请求操作系统完成其自身无法完成的特权操作（如文件读写、进程创建、内存分配等）。

### 题 8

**题干**：在操作系统中，管态（核心态）和目态（用户态）的主要区别是

**选项**：
(A) 管态下可以执行所有指令，目态下只能执行非特权指令
(B) 管态下速度更快
(C) 管态只能由操作系统进入
(D) 目态下不能访问内存

**标准答案**：$\boxed{A}$

**答案解析**：CPU设置管态和目态的目的是为了保护操作系统。在管态（核心态/内核态）下，CPU可以执行全部指令（包括特权指令），可以访问所有内存和寄存器。在目态（用户态）下，CPU只能执行非特权指令，访问受限制的内存区域。当用户程序需要执行特权操作时，必须通过系统调用进入管态。

**出处**：王道《操作系统》第一章

### 题 17

**题干**：某计算机系统采用时间片轮转调度算法实现分时系统。设系统中有 n 个用户进程，每个进程的时间片为 q，CPU 进行进程上下文切换的开销为 s。请回答下列问题：

（1）若忽略用户的"思考时间"，即进程在一个时间片用完后立即再次就绪等待调度。求 CPU 的有效利用率（即用于执行用户进程代码的时间占比）。

（2）若 q 趋近于 0，CPU 的有效利用率会如何变化？这对系统意味着什么？

（3）若 q 无限大（即 q → ∞），该调度算法退化成什么算法？此时 CPU 有效利用率为多少？

（4）从系统设计的角度，说明时间片 q 的大小应如何合理选择。

**标准答案**：

（1）有效利用率 = q / (q + s)

（2）当 q → 0 时，有效利用率 → 0，系统几乎全部时间用于上下文切换，实际效率极低。

（3）退化为先来先服务（FCFS）调度算法；有效利用率 → 1（或 100%）。

（4）q 应综合考虑响应时间要求、切换开销、进程平均CPU运行时间等因素，通常设置为略大于大多数进程一次典型计算所需的时间。

**答案解析**：

（1）**周期分析**：在连续调度下，每一轮调度周期的时间构成 = 一个用户进程执行时间 q + 一次上下文切换时间 s。由于有 n 个进程，完成一轮调度的总时间为 n(q + s)，其中实际用于执行用户进程的时间为 n·q。因此：

$$\text{CPU 有效利用率} = \frac{n \cdot q}{n(q + s)} = \frac{q}{q + s}$$

（2）**q → 0 的极限**：$$\lim_{q \to 0} \frac{q}{q + s} = 0$$

这意味着时间片过小，系统频繁发生进程切换，绝大部分CPU时间被消耗在保存和恢复进程上下文（如PC、寄存器、页表基址等）上，用户几乎得不到响应。此时系统开销远大于有效工作。

（3）**q → ∞ 的退化**：当时间片远大于任意进程的一次CPU执行时间时，每个进程都会在一个时间片内完成其CPU区间，时间片轮转算法退化为先来先服务（FCFS）调度。此时：

$$\lim_{q \to \infty} \frac{q}{q + s} = 1$$

即CPU利用率趋近100%（不考虑I/O等待时），但短作业可能被长作业阻塞，响应性变差。

（4）**时间片选择的权衡**：

- **响应时间需求**：交互式系统要求响应时间 T 不超过人可感知的阈值（如 2-3 秒）。若有 n 个活跃用户，则每个用户的响应时间约为 n·q，因此 q 应满足 q ≤ T/n。
- **上下文切换开销**：q 过小则 s/q 比例过大，系统开销高。经验上 q 应使 s ≤ q/10 甚至更小。
- **进程CPU burst特性**：q 应略大于绝大多数进程一次CPU burst的时间长度，使大多数进程能在一个时间片内完成当前计算（减少不必要的切换）。
- **现代系统参考**：Linux 的 CFS 调度器中，时间片随系统负载动态调整，典型值在毫秒级。

**出处**：王道《操作系统》模拟题（综合题）；汤子瀛《计算机操作系统》处理机调度章节

### 题 18

**题干**：某批处理系统中，有 3 个作业，其提交时刻和估计运行时间如下表所示：

| 作业 | 提交时刻（h） | 估计运行时间（min） |
| :--: | :-----------: | :----------------: |
|  A   |     8.00      |         40         |
|  B   |     8.20      |         30         |
|  C   |     8.40      |         20         |

系统在 8.00 时刻开始调度。分别采用：

（1）先来先服务（FCFS）调度算法
（2）短作业优先（SJF，抢占式）调度算法

计算每种算法下各作业的周转时间、带权周转时间，以及系统的平均周转时间和平均带权周转时间。

**标准答案**：

（1）FCFS：执行顺序 A→B→C；平均周转时间 = 60 min，平均带权周转时间 ≈ 2.39

（2）SJF（抢占式）：平均周转时间 = 46.67 min，平均带权周转时间 ≈ 1.97；SJF 优于 FCFS

**答案解析**：

**（1）FCFS 调度**

执行顺序按提交顺序：A（8:00-8:40）→ B（8:40-9:10）→ C（9:10-9:30）

- A：完成时间 8:40，周转时间 = 40 min，带权 = 40/40 = 1.00
- B：完成时间 9:10，周转时间 = 9:10 − 8:20 = 50 min，带权 = 50/30 ≈ 1.67
- C：完成时间 9:30，周转时间 = 9:30 − 8:40 = 50 min，带权 = 50/20 = 2.50

平均周转时间 = (40 + 50 + 50) / 3 = **60 min**

平均带权周转时间 = (1.00 + 1.67 + 2.50) / 3 ≈ **1.72**

**（2）抢占式 SJF 调度（SRTF，最短剩余时间优先）**

时间点分析：

- 8:00：只有 A，A 开始运行（剩余 40 min）。
- 8:20：B 到达（需 30 min），A 剩余 20 min。A 更短，A 继续。
- 8:40：A 完成（运行 40 min）；同时 C 到达（需 20 min）。就绪队列：B(30)、C(20)。选 C 运行。
- 9:00：C 完成（运行 20 min）。就绪队列：B(30)。B 开始运行。
- 9:30：B 完成（运行 30 min）。

各作业：

- A：完成 8:40，周转 = 40 min，带权 = 40/40 = 1.00
- C：完成 9:00，周转 = 9:00 − 8:40 = 20 min，带权 = 20/20 = 1.00
- B：完成 9:30，周转 = 9:30 − 8:20 = 70 min，带权 = 70/30 ≈ 2.33

平均周转时间 = (40 + 20 + 70) / 3 = 130/3 ≈ **43.33 min**

平均带权周转时间 = (1.00 + 1.00 + 2.33) / 3 ≈ **1.44**

**结论**：SJF（SRTF）在平均周转时间和平均带权周转时间上均优于 FCFS，这也验证了短作业优先算法是平均等待/周转时间最优的算法。但 B 作为长作业被 C 抢占后延后，存在"饥饿"风险（本题未出现，但长作业可能长期得不到调度）。

**出处**：王道《操作系统》第二章模拟题；408统考历年同类题型改编

### 题 19

**题干**：请从实现机制和应用场景两个方面，简述中断（interrupt）与异常（exception）的区别，并各举 2-3 个典型例子。

**标准答案**：

中断是由外部硬件事件触发，与当前执行指令无关，用于响应异步I/O等事件；异常是由CPU执行当前指令时内部产生的同步事件，用于处理指令执行错误或特殊请求。典型中断：I/O中断、时钟中断、外部设备中断；典型异常：缺页、除法溢出、trap访管指令。

**答案解析**：

**一、实现机制区别**

| 维度 | 中断（Interrupt） | 异常（Exception） |
| :--: | :--: | :--: |
| 触发源 | CPU 外部（I/O设备、定时器、外部信号） | CPU 内部（指令执行过程中） |
| 与当前指令关系 | 异步，与当前指令无关 | 同步，由当前指令执行直接引起 |
| 响应时机 | 一般在当前指令执行完毕后响应 | 可在指令执行中响应并可能重放该指令 |
| 现场恢复后 | 继续执行"下一条"指令 | 通常重新执行"当前"故障指令（fault）或跳过（trap） |
| 是否可屏蔽 | 可屏蔽中断（INTR）可被 IF 位屏蔽；NMI不可屏蔽 | 异常不可屏蔽，必须立即处理 |

**二、应用场景与典型例子**

**典型中断**：
1. **时钟中断**：定时器周期触发，用于抢占式调度、时间片轮转、计时。
2. **磁盘I/O中断**：磁盘控制器完成读写后通知操作系统，CPU可以将等待进程唤醒。
3. **键盘/鼠标中断**：用户按键/移动鼠标时触发，操作系统读取输入并转发给应用程序。

**典型异常**：
1. **缺页异常（Page Fault）**：执行访存指令时，发现目标页不在物理内存中（页表项 P=0），MMU触发缺页异常，操作系统将所需页从磁盘调入内存后，重新执行引发异常的那条访存指令。
2. **除法溢出/算术异常**：执行 DIV 指令时除数为 0 或结果溢出；或浮点运算非法操作。操作系统通常向进程发送信号（如 SIGFPE）终止该进程。
3. **访管指令（trap/syscall）**：用户程序主动执行的特殊指令，用于请求系统调用。它将CPU从用户态切换到内核态，并跳转到系统调用处理程序。
4. **地址越界 / 保护异常**：用户进程访问非法地址或无权限的内存段（如写只读代码段）。

**三、系统中的处理流程**

两者最终都会进入CPU的中断向量表（或IDT）查询对应处理程序，完成现场保存、执行处理程序、恢复现场等步骤，但中断处理程序返回后执行下一条指令，而 fault 类异常返回后重新执行当前指令，trap 类异常（如系统调用）返回后执行下一条指令。

**出处**：王道《操作系统》第一章；汤子瀛《计算机操作系统》第一章

### 题 20

**题干**：什么是核心态（管态）和用户态（目态）？为什么要区分这两种状态？从用户态切换到核心态有哪些途径？至少列举三种。

**标准答案**：

核心态下CPU可执行所有指令并访问所有资源；用户态下只能执行非特权指令。目的是保护操作系统不被用户程序破坏。切换途径：系统调用、中断、异常。

**答案解析**：

**一、两种运行模式的定义**

- **核心态（Kernel Mode / Supervisor Mode / 管态）**：操作系统内核代码运行时所处的模式。CPU可以执行全部指令（包括特权指令，如关中断、设置页表基址、I/O指令等），可以访问全部内存和寄存器。
- **用户态（User Mode / 目态）**：用户应用程序运行时所处的模式。CPU只能执行指令集中的一个子集（非特权指令），只能访问受限制的内存区域（进程自己的地址空间），对I/O设备和系统资源的操作必须通过操作系统间接完成。

状态区分由CPU中的一个模式位（如 x86 的 CPL 字段）实现，该位是程序状态字（PSW）的一部分。

**二、为什么要区分两种状态（保护机制）**

1. **保护操作系统本身**：防止用户程序直接修改操作系统的关键数据结构（如进程表、页表、文件系统元数据），防止用户程序破坏内核代码。
2. **保护用户进程之间互不干扰**：用户态下每个进程只能访问自己的虚拟地址空间，不能读写其他进程的内存。
3. **保护I/O设备**：用户程序不能直接操纵硬件设备，所有I/O操作都由操作系统统一调度管理，避免冲突和滥用。
4. **提供统一抽象接口**：通过系统调用提供统一的高层服务，屏蔽硬件细节，便于移植和维护。

若没有态的区分，任何程序都可以直接关中断、改写页表、破坏其他进程数据，系统将极其脆弱。

**三、从用户态切换到核心态的途径**

1. **系统调用（System Call / trap）**：用户程序主动执行 trap 指令（如 x86 的 `int 0x80` 或 `syscall`），请求操作系统服务。这是用户态主动进入核心态最常用的方式。

2. **外部中断（Interrupt）**：外部硬件（如时钟、磁盘、网卡）向CPU发出中断请求。CPU在当前指令执行完毕后响应中断，保存现场，转入中断处理程序（位于内核）。例如：时钟中断触发调度器、磁盘I/O完成中断通知操作系统。

3. **异常（Exception）**：CPU执行当前指令过程中检测到错误或特殊条件，如缺页（Page Fault）、除零错误、地址越界、浮点异常等。CPU自动切换到核心态执行相应异常处理程序。例如，缺页异常是虚拟内存机制的核心驱动。

4. **调试陷阱（Debug Trap，可选）**：调试工具（如 gdb）设置的断点或单步执行也会触发特殊异常进入内核态，由调试子系统处理。

**四、切换的关键操作**

无论哪种途径进入核心态，硬件层面通常会完成以下操作：
- 将 PSW（含模式位）和 PC 压入内核栈；
- 将模式位置为核心态；
- 根据中断向量表跳转到对应的处理程序入口；
- 保存通用寄存器等现场（通常由软件在内核处理程序开头完成）。

从中断/异常返回时（如 x86 的 `iret`）恢复用户态 PSW 和 PC，回到用户态继续执行。

### 题 21

**题干**：请回答下列关于操作系统基本特征的问题：

（1）简述操作系统的四个基本特征，并指出哪个特征是最重要、最基本的特征。

（2）解释并发性与并行性的区别，并说明在单CPU系统中是如何实现并发的。

（3）解释"虚拟"是如何通过"分时"和"空分"技术实现的，各举一例。

（4）解释"异步性"为什么会带来不确定性，并说明操作系统如何保证程序在相同初始条件下能得到确定结果。

**标准答案**：

（1）四大特征：并发、共享、虚拟、异步；并发是最基本特征。
（2）并发指同一时间间隔内多个程序交替推进，并行指同一时刻多个程序同时执行；单CPU通过分时切换实现并发。
（3）分时（如CPU虚拟化，多个进程轮流使用CPU）、空分（如内存虚拟化，多个进程各自拥有独立虚拟地址空间映射到同一块物理内存的不同区域）。
（4）异步指进程推进速度不可预测，但只要初始条件相同，程序的最终结果应确定，操作系统通过同步互斥等机制保证正确性。

**答案解析**：

**（1）操作系统的四个基本特征**

- **并发性（Concurrency）**：指系统中同时存在多个可运行的活动（进程/线程），它们在同一时间间隔内交替推进。并发使得CPU和I/O设备可以并行工作，提高系统资源利用率和吞吐量。**并发是操作系统最基本、最重要的特征**，它是其他特征存在的前提——没有并发，就谈不上对资源的共享争夺、对CPU和内存的虚拟复用、以及对进程执行顺序的异步不确定性。

- **共享性（Sharing）**：系统中的资源（CPU、内存、I/O设备、文件等）可以被多个并发进程共同使用。共享有两种方式：
  - **互斥共享**：一段时间内只允许一个进程使用（如打印机、临界区）；
  - **同时访问**：一段时间内允许多个进程"同时"访问（如磁盘文件、只读代码段，宏观上同时，微观上可能交替）。

- **虚拟性（Virtuality）**：通过分时复用或空分复用技术，把一个物理实体变成多个逻辑上的对应物。例如虚拟处理器（让每个用户觉得有一个自己的CPU）、虚拟内存（让每个进程觉得自己独占整个内存空间）、虚拟设备（SPOOLing技术把独占打印机虚拟化成可排队共享设备）。

- **异步性（Asynchronism）**：进程以不可预知的速度向前推进。进程何时被创建、何时因I/O阻塞、何时被调度抢占、何时完成都取决于系统状态和其他进程的活动，因此同一程序多次运行的"时间轨迹"可能不同。

**（2）并发性 vs 并行性**

| 维度 | 并发性（Concurrency） | 并行性（Parallelism） |
| :--: | :--: | :--: |
| 时间关系 | 多个事件在**同一时间间隔**内发生，微观上交替执行 | 多个事件在**同一时刻**发生，微观上同时执行 |
| 硬件要求 | 单CPU即可实现（通过调度器分时切换） | 需要多CPU、多核或多机系统支持 |
| 关注点 | 程序结构（可分解为多个可独立推进的活动） | 执行加速（把任务分解到多个执行单元） |

在单CPU系统中，并发通过**时间片轮转**实现：操作系统把CPU时间分割成小的时间片（如 10-100 ms），按某种调度策略轮流分给各个就绪进程。每个进程在获得时间片时执行，时间片用完或发生I/O时被换下，另一个进程被调度执行。从宏观上看，多个程序在一段时间内都在"运行"；从微观上看，任一时刻只有一个进程在CPU上执行。

**（3）虚拟性的实现：分时与空分**

- **分时复用（时分多路复用）**：一个物理设备在时间上被多个用户/进程轮流使用。每个用户在自己的时间段内独占设备。
  - **例**：虚拟CPU。一个物理CPU通过调度器轮流执行多个进程的指令，每个进程被分配一个时间片。从每个进程的视角看，它在"自己的CPU"上连续运行。

- **空分复用（空分多路复用）**：资源在空间上被划分为多个部分，同时被多个用户/进程使用。
  - **例**：虚拟内存。通过分页/分段机制，每个进程拥有独立的虚拟地址空间（如 32 位系统中的 4 GB），操作系统通过页表将不同进程的虚拟页映射到物理内存的不同页框。多个进程的虚拟地址空间共同"瓜分"一块物理内存，彼此隔离。
  - **另一例**：磁盘分区。一块物理磁盘被划分为多个分区（如 C:、D:）或挂接到不同挂载点，用户感觉在使用多个独立的"磁盘"。

**（4）异步性与程序确定性**

**异步性带来不确定性的原因**：进程执行的相对速度受以下因素影响：
- 调度器的调度时机与策略；
- 中断/异常发生的时刻（如I/O完成、时钟中断）；
- 其他进程的行为（是否竞争同一资源、是否发出信号）；
- 进程间的同步交互。

因此同一程序在同一机器上多次运行，其内部指令执行的时间点、等待时间都可能不同。

**操作系统如何保证结果确定**：
虽然执行时间轨迹不确定，但操作系统必须保证在**相同初始条件（输入数据、初始状态）下，程序最终结果相同**，即程序的逻辑正确性与执行速度无关。操作系统通过以下机制实现：

1. **虚拟内存隔离**：每个进程有独立地址空间，不会被其他进程意外修改。
2. **进程同步与互斥**：对临界资源（如共享内存、文件）的访问通过信号量、管程、互斥锁等机制有序化，避免竞态条件。
3. **原子操作与原语**：关键的内核操作以原语形式提供，保证其执行不可分割。
4. **可重入代码与线程安全**：操作系统的服务代码设计为可被多个进程并发调用而不破坏内部状态。
5. **文件系统一致性保障**：通过缓冲区管理、日志（journaling）、事务等机制保证写操作的原子性。

简言之，操作系统保证的是**结果的确定性**，而不是**时间的确定性**（实时系统除外）。

**出处**：王道《操作系统》第一章；汤子瀛《计算机操作系统》第一章
