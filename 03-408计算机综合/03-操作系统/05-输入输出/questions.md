### 题 1

**题干**：（2020年408统考第32题）下列关于 I/O 设备的叙述中，错误的是

**选项**：
(A) 键盘输入信息时，CPU 通过轮询方式读取按键代码
(B) 图形显示器通过显存（frame buffer）存储待显示图像
(C) 磁盘控制器可以把 CPU 从磁盘 I/O 过程中解放出来
(D) 鼠标属于字符设备

**标准答案**：$\boxed{A}$

**答案解析**：现代键盘通常采用中断方式（键盘按键触发 IRQ，中断处理程序读取按键代码），而不是 CPU 轮询。轮询方式对低速 I/O 设备（如键盘）过于浪费 CPU 时间。B、C、D 描述正确。图形显示器使用显存（frame buffer），由 GPU/控制器周期性刷新到屏幕。磁盘控制器（带 DMA）可以在 CPU 不干预的情况下完成整块数据传输。鼠标、键盘、串口等按字节流读写，属于字符设备。

**出处**：2020年全国硕士研究生招生考试计算机学科专业基础综合试题第32题

### 题 2

**题干**：下列关于 I/O 控制方式的叙述中，正确的是

**选项**：
(A) 程序查询方式（轮询）中，CPU 与设备可以并行工作
(B) 中断驱动方式中，每传输一个数据块都需要一次中断
(C) DMA 方式中，数据在内存与设备之间的传输完全由 DMA 控制器控制，不需要 CPU 干预数据传输过程
(D) 通道方式中，通道指令由 CPU 直接执行

**标准答案**：$\boxed{C}$

**答案解析**：

- A 错误：程序查询方式下 CPU 陷入忙等循环，不断读取设备状态位，直到设备就绪才进行数据传输。CPU 与设备串行工作。
- B 错误：中断驱动方式通常每传输一个"数据单位"（字符/字）发生一次中断，而不是"数据块"；"数据块"级别对应 DMA 方式。
- C 正确：DMA（Direct Memory Access）方式由 DMA 控制器直接在内存和设备之间传输整块数据，仅在块传输开始和结束时需要 CPU 参与（发送指令、处理中断）。
- D 错误：通道指令（Channel Command Word, CCW）由通道控制器（I/O 处理器）执行，不是 CPU 直接执行。CPU 只负责构造通道程序并启动通道。

**出处**：王道《操作系统》第五章

### 题 3

**题干**：（2018年408统考第32题）在 DMA 方式下，数据从磁盘传送到内存的路径是

**选项**：
(A) 磁盘 → 数据总线 → 内存
(B) 磁盘 → DMA 控制器 → 内存
(C) 磁盘控制器 → DMA 控制器 → 数据总线 → 内存
(D) 磁盘 → 磁盘控制器 → 数据总线 → 内存

**标准答案**：$\boxed{D}$

**答案解析**：DMA 传输路径：磁盘 → 磁盘控制器 → 数据总线 → 内存。磁盘控制器负责把磁盘上的串行位流转换成并行数据（或反之），DMA 控制器在 CPU 设定好源地址、目的地址和长度后，接管总线控制权，在"磁盘控制器 → 数据总线 → 内存"之间传输数据。选项 C 把 DMA 控制器放在数据通路上是不准确的（DMA 控制器更像"总线裁决者/指挥者"）。标准答案常给出 **D**。

**出处**：2018年全国硕士研究生招生考试计算机学科专业基础综合试题第32题

### 题 4

**题干**：下面关于 Spooling（假脱机）技术的说法中，错误的是

**选项**：
(A) Spooling 把独占设备（如打印机）改造成可被多个进程共享的设备
(B) Spooling 需要磁盘上的输入井和输出井作为缓冲
(C) Spooling 系统由输入/输出进程 + 井管理程序组成
(D) 引入 Spooling 后，打印机等独占设备变成了共享设备，因此不再需要任何互斥机制

**标准答案**：$\boxed{D}$

**答案解析**：Spooling（Simultaneous Peripheral Operations On-Line）把慢速独占设备（打印机、卡片机）与磁盘井结合：用户进程把打印任务写入磁盘输出井（排队），专用的输出守护进程（daemon）按顺序把井中的内容发给打印机。

- A 正确：逻辑上多个用户进程可以"同时"使用打印机（它们都在往输出井写）。
- B 正确：输入井/输出井是磁盘上的专用区域。
- C 正确：输入/输出进程负责与设备交互，井管理程序负责磁盘空间分配与排队。
- D 错误：虽然用户进程不用直接竞争打印机，但它们对输出井的写入仍需互斥（对同一文件/队列的并发写需要同步）；且打印作业本身是顺序发送到打印机的（按提交顺序），这个排队过程也需要互斥与同步。

**出处**：王道《操作系统》第五章；汤子瀛《计算机操作系统》第五章

### 题 5

**题干**：（2017年408统考第32题）系统将数据从磁盘读到内存的过程包括以下操作：
① DMA 控制器发出中断请求
② CPU 执行中断服务程序
③ CPU 向 DMA 控制器发出命令
④ DMA 控制器控制数据在内存与磁盘之间的传输

正确的执行顺序是

**选项**：
(A) ③ → ④ → ① → ②
(B) ③ → ① → ④ → ②
(C) ① → ③ → ④ → ②
(D) ④ → ③ → ① → ②

**标准答案**：$\boxed{A}$

**答案解析**：DMA 标准流程：

1. **③ CPU 向 DMA 控制器发命令**：设置源地址（磁盘控制器）、目的地址（内存缓冲区）、传输字节数、方向等；
2. **④ DMA 控制器控制数据传输**：CPU 继续执行其他程序，DMA 控制器接管总线，在磁盘控制器和内存之间传输数据，直到计数为 0；
3. **① DMA 控制器发中断请求**：通知 CPU 数据传输已完成；
4. **② CPU 执行中断服务程序**：处理后续工作（校验、通知应用程序、释放缓冲区等）。

因此顺序为 ③ → ④ → ① → ②，选 A。

**出处**：2017年全国硕士研究生招生考试计算机学科专业基础综合试题第32题

### 题 6

**题干**：在操作系统中，引入缓冲（Buffer）的主要目的不包括

**选项**：
(A) 缓和 CPU 与 I/O 设备之间速度不匹配的矛盾
(B) 减少 CPU 被中断的频率
(C) 提高 CPU 与 I/O 设备之间的并行程度
(D) 减少对磁盘的读写次数，延长磁盘使用寿命

**标准答案**：$\boxed{D}$

**答案解析**：引入缓冲的主要目的：

1. **缓和 CPU 与 I/O 设备速度不匹配（A 正确）**：CPU 每秒可处理几亿次运算，而键盘每秒输入几个字符；若没有缓冲，CPU 必须被频繁中断。
2. **减少中断频率（B 正确）**：一个缓冲区可以累计一批数据后再中断 CPU，而不是每收到一个字符就中断。
3. **提高 CPU 与 I/O 的并行程度（C 正确）**：双缓冲（缓冲 A 被 CPU 消费时，设备向缓冲 B 写入；然后互换）让 CPU 和设备在大部分时间同时忙碌。
4. **解决 DMA/通道方式下数据对界、单位对齐问题**：设备通常按固定大小传输，缓冲有助于聚合。

D 错误：缓冲（特别是写缓冲）可能"合并写"从而减少磁盘 I/O 次数，这是文件系统缓存（page cache）的功能，属于"系统性能优化"而非基本缓冲机制的"主要目的"。且普通用户态缓冲（如 stdio 的缓冲）对磁盘使用寿命的影响极其间接，不是设计缓冲的主要动机。

**出处**：汤子瀛《计算机操作系统》第五章

### 题 7

**题干**：（2016年408统考第32题）某系统采用双缓冲方式进行输入输出。每个缓冲区大小为 C。CPU 对每块数据的处理时间为 T。输入设备把一块数据写入缓冲区的时间为 M，输出设备把一块数据从缓冲区读出的时间为 N。系统能达到的最大吞吐率（单位时间处理的数据块数）约为

**选项**：
(A) 1 / max(M, N, T)
(B) 1 / (M + N + T)
(C) 1 / (max(M, N) + T)
(D) C / (M + N + T)

**标准答案**：$\boxed{A}$

**答案解析**：双缓冲下，输入设备、输出设备、CPU 可以流水线作业（一个缓冲正被 CPU 处理的同时，另一个缓冲被设备写入/读出）。流水线的最慢阶段决定系统吞吐率：若输入是瓶颈（M 最大），每 M 时间只能处理一块；若输出是瓶颈则由 N 决定；若 CPU 处理是瓶颈则由 T 决定。因此最大吞吐率约为 **1 / max(M, N, T)**。

**出处**：2016年全国硕士研究生招生考试计算机学科专业基础综合试题第32题

### 题 8

**题干**：下列关于 I/O 软件层次结构的说法中，错误的是

**选项**：
(A) 用户层 I/O 软件：为应用程序提供系统调用接口（如 read/write）和库函数（如 printf、fopen）
(B) 设备独立性软件：负责把逻辑设备名映射到具体驱动程序，处理设备命名、保护、分块、缓冲等通用功能
(C) 设备驱动程序：与具体硬件紧密相关，直接操作设备控制器的寄存器
(D) 中断处理程序：与设备驱动程序无关，是通用的硬件抽象层

**标准答案**：$\boxed{D}$

**答案解析**：中断处理程序通常是设备驱动程序的一部分（由驱动程序注册到内核的中断向量表中），它处理特定设备发来的中断信号（如 DMA 完成、字符到达、错误等），与驱动程序紧密相关。A、B、C 描述正确：用户层软件把设备抽象为文件接口；设备独立性软件（如 Linux 的 VFS、tty 核心层）屏蔽不同设备差异；驱动程序直接操作硬件寄存器。

**出处**：王道《操作系统》第五章

### 题 9

**题干**：（2015年408统考第32题）本地用户通过键盘登录系统时，首先获得键盘输入信息的是

**选项**：
(A) 命令解释程序（shell）
(B) 键盘驱动程序
(C) 系统调用服务程序
(D) 文件系统

**标准答案**：$\boxed{B}$

**答案解析**：键盘输入流程：

1. 用户按键 → 键盘硬件产生扫描码并触发 IRQ 中断；
2. CPU 跳转到内核的中断向量表 → **键盘驱动程序的中断处理程序**；
3. 驱动程序把扫描码转换成字符或按键事件，放入内核缓冲区（如 tty 缓冲）；
4. 用户态进程（如 shell）通过 `read()` 系统调用从该缓冲区读取字符。

因此"首先"获得键盘输入信息的是键盘驱动程序。选 B。

**出处**：2015年全国硕士研究生招生考试计算机学科专业基础综合试题第32题

### 题 10

**题干**：设备控制器（I/O Controller）的主要功能不包括

**选项**：
(A) 接收和识别 CPU 发来的命令
(B) 实现数据缓冲，缓解 CPU 与设备速度差异
(C) 识别设备地址，选择哪个 I/O 设备工作
(D) 实现文件系统的目录解析

**标准答案**：$\boxed{D}$

**答案解析**：

- A 正确：控制器有命令寄存器，CPU 通过 I/O 指令写入命令（读、写、寻道等）。

- C 正确：控制器解码 CPU 发来的设备地址，选中对应设备或端口。
- D 错误：目录解析是文件系统软件的功能，属于高层软件，与硬件控制器无关。

### 题 11

**题干**：下列关于通道（Channel）的说法中，错误的是

**选项**：
(A) 通道是一种专门负责 I/O 的处理器，可以执行通道程序
(B) 通道程序由 CPU 在内存中构造，然后通过启动通道指令（SIO）交给通道执行
(C) 一个通道可以控制多个控制器，一个控制器可以控制多个同类型设备
(D) 通道方式下数据传输的每个字节都需要 CPU 干预

**标准答案**：$\boxed{D}$

**答案解析**：通道方式是 DMA 的进一步推广：CPU 构造一串通道命令（CCW）描述要读/写哪些数据，启动通道后整个传输过程由通道独立完成。通道程序结束后才向 CPU 发一次中断。因此数据传输过程中 CPU **完全不干预**，D 错误。A、B、C 描述正确：通道是专门的 I/O 处理器，通道程序在内存中由 CPU 构造（IBM 大型机典型模型），通道-控制器-设备构成三级控制层次。

**出处**：王道《操作系统》第五章

### 题 12

**题干**：（2014年408统考第32题）某文件占 10 个磁盘块，现要把该文件的磁盘块逐个读入主存缓冲区，并送用户区进行分析。假设一个缓冲区与一个磁盘块大小相同，把一个磁盘块读入缓冲区的时间为 100 μs，将缓冲区的数据传送到用户区的时间是 50 μs，CPU 对一块数据进行分析的时间为 50 μs。在单缓冲和双缓冲结构下，系统处理完这 10 块数据的总时间分别约为

**选项**：
(A) 1500 μs 和 1000 μs
(B) 1500 μs 和 1100 μs
(C) 2000 μs 和 1000 μs
(D) 2000 μs 和 1100 μs

**标准答案**：$\boxed{B}$

**答案解析**：

每块操作分三个阶段：磁盘读入缓冲（100 μs）→ 缓冲传送到用户区（50 μs）→ CPU 分析（50 μs）。

**单缓冲**：同一时刻缓冲只能被一个阶段使用，三块操作串行，每块 100+50+50=200 μs？但注意：CPU 分析和下一块的磁盘读可以部分重叠——当一块数据传送到用户区后，缓冲区空出，磁盘可以开始读下一块，同时 CPU 分析当前块。

简化模型（经典教科书中的算法）：
- 第一块：读 100 + 传送 50 + 分析 50 = 200 μs
- 后续每块：读 100 和分析 50 与上一块重叠，每块新增 max(100, 50) = 100 μs？
- 严格模型：单缓冲下"传送 50"期间磁盘不能写该缓冲，CPU 也不能分析；"分析 50"期间磁盘可以读下一块（不同缓冲区位置）。最常见解答：单缓冲每块 = 100+50+50 = 200；10 块 = 2000。但标准答案常给出 10×(100+50) = 1500（把分析与后续读重叠）。这取决于模型细节。

统考题给的**参考答案为 1500/1100（B 选项）**。

**双缓冲**：存在两个缓冲 A、B，磁盘向一个缓冲写入时 CPU 可从另一个缓冲传送并分析。流水线由最长阶段决定。每块处理的新增时间 ≈ max(读 100, 传送+分析=100) = 100 μs。第一块完整处理：100+50+50=200 μs；后续 9 块每块新增 100 μs。总计 200 + 9×100 = 1100 μs。

**参考**：单缓冲 1500（读+传送）× 10 = 1500，分析重叠在读内。双缓冲 1100。选 **B**。

**出处**：2014年全国硕士研究生招生考试计算机学科专业基础综合试题第32题

### 题 14

**题干**：（2013年408统考第32题）用户程序调用 printf() 输出字符，在字符被打印到屏幕之前，不会经过的层次/模块是

**选项**：
(A) 标准 C 库（libc）
(B) 系统调用 write()
(C) 终端设备驱动程序（tty driver）
(D) 磁盘文件系统驱动程序

**标准答案**：$\boxed{D}$

**答案解析**：printf() 的调用链：

1. printf()（A 标准 C 库）把格式化后的字符写入 FILE 内部缓冲区；
2. 缓冲区满或换行时，库调用 `write(fd, buf, n)` 系统调用（B）；
3. `write()` 进入内核，根据 fd 的文件类型（字符设备 tty）调用终端驱动程序（C）的 write 函数；
4. 终端驱动把字符写入内核 tty 缓冲，由终端/显示子系统输出到屏幕或伪终端。

整个过程终端输出无需访问磁盘文件系统。若 printf 输出被重定向到磁盘文件，则会经过磁盘文件系统驱动，但题目默认输出到屏幕（终端），因此 **D 不会经过**。

**出处**：2013年全国硕士研究生招生考试计算机学科专业基础综合试题第32题

### 题 15

**题干**：下列关于设备独立性（Device Independence）的说法中，错误的是

**选项**：
(A) 应用程序使用逻辑设备名请求 I/O，而不直接使用物理设备名
(B) 操作系统负责把逻辑设备名映射到具体的物理设备和驱动程序
(C) 设备独立性使得在增加/更换新设备时不需要修改应用程序
(D) 设备独立性使得所有设备的物理特性都被隐藏，操作系统无需区分字符设备和块设备

**标准答案**：$\boxed{D}$

**答案解析**：

- A、B 正确：应用程序用逻辑名（如 `/dev/tty`、`LPT1`、`stdin`）请求设备，操作系统根据设备分配表映射到物理设备和驱动程序。
- C 正确：新增设备只需配置驱动和逻辑名即可，应用程序无需修改。
- D 错误：设备独立性隐藏的是"哪个具体设备服务请求"，但不能隐藏设备类型差异——字符设备与块设备在读写单位、寻址方式、文件系统挂载等方面有本质差异，操作系统仍需区分。

**出处**：汤子瀛《计算机操作系统》第五章

### 题 17

**题干**：某系统采用中断驱动方式进行字符设备输入。每输入一个字符需要 1 ms。假设每次中断处理的开销包括：保存 CPU 现场 0.01 ms、执行中断服务程序 0.04 ms、恢复现场并返回 0.01 ms。字符被放入内核缓冲区，用户进程通过系统调用 `read()` 从缓冲区读取字符。请回答：

（1）中断处理的总开销是多少？每输入 1 ms 的字符数据，CPU 花在中断处理上的时间占比是多少？
（2）如果改用 DMA 方式，每输入 1000 个字符（1 块，1 ms × 1000 = 1 s）才发生一次 DMA 完成中断，中断处理开销仍按同一次字符中断估算（0.06 ms，包括保存现场、服务、恢复），则 CPU 花在 I/O 处理上的时间占比是多少？
（3）基于（1）（2）的结论，简述 DMA 方式对 I/O 系统性能的影响，并说明为什么对于高速块设备 DMA 方式比中断驱动方式更有效。
（4）如果字符设备输入速度是 1000 字符/秒，缓冲区大小为 2000 字符。用户进程 `read()` 每读取 1000 字符需要 0.1 ms 的 CPU 时间（除 I/O 外的开销）。若用户进程 `read()` 每次都等待缓冲区满 1000 字符再读，在双缓冲+DMA 模型下，CPU 实际花费在 I/O 相关工作上的时间占比是多少？

**标准答案**：

（1）中断处理 = 0.01 + 0.04 + 0.01 = 0.06 ms。每输入一个字符需一次中断，占比 = 0.06/1 ≈ 6%。
（2）DMA 下 1 秒一次中断，中断开销 0.06 ms。占比 = 0.06 / 1000 ≈ 0.006%。
（3）DMA 把中断频率从"每字符一次"降低到"每块一次"，极大减少 CPU 开销；对高速设备，字符级中断会把 CPU 全部时间吞没。
（4）1000 字符/秒；DMA 一次处理 1000 字符耗时 1 s，中断开销 0.06 ms，read 开销 0.1 ms；每 1 s 内 CPU 在 I/O 相关工作上总耗时 ≈ 0.16 ms，占比 ≈ 0.016%。

**答案解析**：

**（1）中断驱动方式**

每次中断开销 = 保存现场 0.01 ms + 中断服务 0.04 ms + 恢复现场 0.01 ms = **0.06 ms**。

每 1 ms 输入一个字符，每字符一次中断，1 ms 内 I/O 相关 CPU 时间 = 0.06 ms。

中断处理时间占比 = 0.06 / 1 = **6%**。

**（2）DMA 方式（每 1000 字符一次中断）**

设备以 1 字符/ms 的速度持续输入，1000 字符填满一个 DMA 缓冲区耗时 1 s。

1 s 内发生一次 DMA 完成中断，中断处理开销仍约 0.06 ms（中断服务程序在此处处理批数据的收尾，如把缓冲区交给上层、设置新缓冲、通知用户进程）。

DMA 中断处理时间占比 = 0.06 ms / 1000 ms = **0.006%**。

**（3）DMA 方式对性能的影响**

- **降低 CPU 开销**：从 6% 降到 0.006%，接近两个数量级的改善。CPU 把时间从逐字节的中断处理中解放出来，用于计算、调度和其他任务。
- **提高吞吐率**：DMA 控制器可以在 CPU 执行其他代码时持续传输数据，CPU 与 I/O 设备高度并行，系统整体吞吐率上升。
- **对高速设备至关重要**：如果设备输入速度提升（例如磁盘 200 MB/s，网络 1 Gb/s），按字符（或按小包）中断会把 CPU 完全吞没——假设 1 字节/包且每包一次中断，200 MB/s 意味着每秒 2 亿次中断，远超 CPU 处理能力。DMA 把数据块凑成整块（4 KB、64 KB 甚至更大）再中断一次，使高速设备得以与 CPU 协同工作。
- **减少缓存污染**：频繁中断会导致 CPU 缓存被中断处理程序的代码/数据"污染"，降低应用程序缓存命中率。DMA 减少中断频次，减少缓存冲刷。
- **实时系统中降低响应抖动**：较少的中断次数意味着较少的上下文切换，用户程序执行更平滑。

**（4）双缓冲 + DMA 模型下的 CPU 占比**

输入速度 = 1000 字符/秒 = 1 字符/ms。
用户 `read()` 每次读取 1000 字符，即每 1 s 读一次。

双缓冲结构：
- 在时间 0~1 s：DMA 把字符写入缓冲 A；
- 在 1 s 时刻：缓冲 A 满，DMA 中断 CPU；CPU 切换 DMA 目标为缓冲 B，同时用户 `read()` 从缓冲 A 读取并处理 1000 字符；
- 在 1~2 s：DMA 继续把字符写入缓冲 B；同时 CPU 处理缓冲 A 的数据；
- 在 2 s 时刻：缓冲 B 满，再次中断；CPU 切换 DMA 目标回缓冲 A，用户 `read()` 从缓冲 B 读取并处理；如此循环。

每 1 s 周期内 CPU 用于 I/O 的时间：
- DMA 中断处理：0.06 ms（保存现场 + 服务 + 恢复）
- 用户进程 `read()`：0.1 ms
- 其他开销（系统调用、调度等）忽略

合计 = 0.06 + 0.1 = 0.16 ms

占比 = 0.16 / 1000 = **0.016%**

可见 CPU 主要时间用于"其他任务"，I/O 系统几乎不占用 CPU。

**出处**：王道《操作系统》第五章；汤子瀛《计算机操作系统》第五章

### 题 18

**题干**：某系统采用程序查询（轮询）方式与某输入设备进行 I/O。CPU 主频 1 GHz。设备每输入 1 字节需 10 μs。每次轮询操作包括：读取设备状态寄存器（2 条指令）、判断是否就绪（1 条指令）、若就绪则读取数据寄存器并存入内存缓冲区（3 条指令）、若未就绪则跳回重新轮询（1 条指令）。每条指令平均执行时间为 1 个时钟周期。请回答：

（1）每次成功读取 1 字节，CPU 需要执行多少条指令？耗时多少微秒？
（2）每输入 1 字节，CPU 用于轮询的时间占比是多少？（提示：轮询可能多次才成功。）
（3）如果该设备改用 DMA 方式，每输入 1000 字节才发生一次 DMA 中断，中断处理程序每次执行 5000 条指令。则 CPU 用于该设备 I/O 的时间占比变为多少？
（4）基于上述计算，简述为什么现代操作系统中对块设备普遍采用 DMA 方式，而对键盘/鼠标这类低速率字符设备仍可采用中断驱动但不采用轮询。

**标准答案**：

（1）成功路径：读取状态(2) + 判断(1) + 读取数据(3) = 6 条指令；耗时 = 6 × 1 ns = 6 ns = 0.006 μs。
（2）每 10 μs 设备准备好 1 字节。在这 10 μs 内 CPU 执行轮询循环若干次。每次轮询循环（未就绪路径）：读状态(2) + 判断(1) + 跳转(1) = 4 条 = 4 ns。最多轮询 10 μs / 4 ns = 2500 次。实际 CPU 执行时间约 = 4 ns × 轮询次数 + 6 ns。按期望 2500 次估算 ≈ 10 μs，占比 ≈ 100%；若严格"每 10 μs 设备准备好 1 字节且 CPU 轮询到"，CPU 几乎全时间轮询，占比 ~100%。
（3）DMA：每 10 ms（1000 字节 × 10 μs）一次中断；中断处理 5000 指令 = 5000 ns = 5 μs；占比 = 5 / 10000 = 0.05%。
（4）轮询占用 CPU 太高；中断开销对低速设备可接受；DMA 对高速块设备至关重要。

**答案解析**：

**（1）单次成功读取的指令数与耗时**

CPU 主频 1 GHz → 1 时钟周期 = 1 ns。

成功路径：
- 读取设备状态寄存器：2 条指令 → 2 ns
- 判断是否就绪：1 条 → 1 ns（此时判断为就绪）
- 读取数据寄存器并存入缓冲区：3 条 → 3 ns
- 合计：**6 条指令 = 6 ns = 0.006 μs**

**（2）轮询时间占比**

设备每 10 μs 产出 1 字节。在这 10 μs 内 CPU 反复轮询：

- 未就绪轮询循环：读状态(2) + 判断(1) + 跳转(1) = **4 条指令 = 4 ns**
- 最后一次成功读取：**6 条指令 = 6 ns**

在 10 μs（10000 ns）内：CPU 大致轮询 (10000 − 6) / 4 ≈ 2498 次未命中 + 1 次成功。

10 μs 内 CPU 总执行指令数 ≈ 2498 × 4 + 6 ≈ 10000 ns = 10 μs。

占比 ≈ 10 μs / 10 μs = **100%**。

**极端结论**：在轮询方式下，CPU 几乎把全部时间用于反复读取设备状态，没有剩余时间执行其他任务。这就是为什么轮询（忙等）方式只在嵌入式最小系统中偶尔使用，通用操作系统不用它做常规 I/O。

**（3）DMA 方式的占比**

每 1000 字节一次 DMA 中断：
- 1000 字节设备准备时间 = 1000 × 10 μs = 10 ms = 10,000 μs = 10,000,000 ns
- DMA 中断处理指令数 = 5000 → 耗时 = 5000 ns = 5 μs

占比 = 5 μs / 10,000 μs = **0.05%**。

**（4）轮询、中断、DMA 的适用场景**

从上述计算可以直观看到：

1. **轮询（忙等）不可用于通用操作系统**：它把 CPU 完全占用来等待设备，占比接近 100%，系统几乎无法做其他工作。轮询的使用场景仅限：
   - 极其简单的嵌入式系统（无多任务）；
   - 设备响应极快（纳秒级），不需要 CPU 长时间等待；
   - 极低功耗待机状态下的简单事件处理。

2. **中断驱动适合低速字符设备**：键盘（~10 字符/秒）、鼠标（~几百事件/秒）产生事件的频率非常低，即使每次中断 0.1 ms 开销，占比仍低于 0.01%。中断驱动让 CPU 在设备空闲时执行其他任务，效率远高于轮询。

3. **DMA 适合高速块设备**：磁盘（每秒数百 MB）、高速网络（1 Gb/s ~ 100 Gb/s）、显卡、SSD 等如果按字/字节级中断，CPU 会被中断完全吞没。DMA 把数据攒成一块（4 KB、64 KB、甚至 MB 级）再通知一次，中断频率降低几个数量级，CPU 占比从接近 100% 降到 < 1% 甚至 < 0.1%，显著提升系统吞吐率。

4. **通道/IOMMU 进一步解放 CPU**：在大型机/服务器中，通道（channel）和 I/O MMU 把"构造多个 DMA 传输序列"的工作也从 CPU 转移给专用处理器，CPU 只需下发一条启动指令，后续整个 I/O 队列由通道独立完成。

**为什么低速字符设备不用 DMA？**：DMA 有设置开销（写 DMA 控制器寄存器、映射缓冲区、处理完成中断等），对单字符或几十字节的小数据不值得——开销远大于数据传输本身。对键盘/鼠标这类事件稀疏、数据量小的设备，中断驱动是效率与简单性的最佳折衷。

**出处**：王道《操作系统》第五章；汤子瀛《计算机操作系统》第五章

### 题 19

**题干**：回答下列关于 I/O 软件层次结构与设备分配的问题：

（1）画出 I/O 软件的典型层次结构图（从用户层到硬件），并简要说明每层职责。
（2）什么是设备独立性（设备无关性）？它为用户和系统各带来什么好处？
（3）什么是设备控制器、设备驱动程序、通道？三者之间有什么关系？
（4）设备分配时应考虑哪些因素？为什么要引入设备分配表（Device Allocation Table）？
（5）解释"独享设备"、"共享设备"、"虚拟设备（SPOOLing）"的区别，并各举一个典型例子。

**标准答案**：

（1）从上到下：用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。
（2）应用程序使用逻辑设备名请求 I/O，由操作系统映射到物理设备。好处：简化应用、便于热插拔/更换设备、提高设备利用率。
（3）设备控制器 = 硬件（控制具体设备）；驱动程序 = 软件（与控制器对话）；通道 = 专用 I/O 处理器（执行通道程序，可控制多个控制器）。
（4）因素：设备类型、优先级、是否可抢占、是否共享、是否需互斥；设备分配表记录设备-进程关系、状态、驱动入口等。
（5）独享：同一时刻只能由一个进程使用（打印机）；共享：可被多个进程同时访问（磁盘）；虚拟：SPOOLing 把独享设备改造成逻辑共享（打印机输出井）。

**答案解析**：

**（1）I/O 软件层次结构**

```
┌──────────────────────────────┐
│     用户层 I/O 软件           │  printf/scanf/fopen/read/write
│  (库函数 + 系统调用接口)      │  spooling 守护进程
├──────────────────────────────┤
│    设备独立性软件（设备无关） │  逻辑设备名映射、设备命名、保护
│                              │  缓冲、块分配、错误报告
├──────────────────────────────┤
│    设备驱动程序              │  读/写控制器寄存器、设置 DMA
│                              │  响应设备中断、抽象硬件差异
├──────────────────────────────┤
│    中断处理程序              │  保存/恢复现场、调用驱动中断服务
│                              │  处理设备特殊事件
├──────────────────────────────┤
│       硬件（设备 + 控制器）   │  键盘/磁盘/网卡 + 控制器/DMA
└──────────────────────────────┘
```

各层职责：
- **用户层 I/O 软件**：向应用程序提供统一的文件式 I/O 接口（如 `read/write/open/close`）和标准库函数（如 `printf`、`fread`）。spooling 守护进程也在这一层。
- **设备独立性软件**：处理与具体设备无关的通用功能——逻辑设备名到物理设备的映射、设备命名与保护、缓冲、错误报告、块设备的块分配与管理。
- **设备驱动程序**：与具体控制器通信。包含启动设备、设置寄存器、处理中断、将高层请求（读若干块）翻译为控制器可理解的具体命令序列。每类设备对应一个驱动。
- **中断处理程序**：由驱动程序注册到内核，响应设备中断（如 DMA 完成、错误、字符到达）。通常由汇编开头保存/恢复寄存器，C 代码处理具体事件。
- **硬件**：设备本身（机械/电子部件）+ 设备控制器 + DMA 控制器 + 总线。

**（2）设备独立性（Device Independence）**

**定义**：应用程序使用**逻辑设备名**（如 `/dev/lpt0`、`PRN:`、`LPT1`）请求 I/O，操作系统在运行时根据当前配置把逻辑名映射到具体物理设备（如"第三台并口打印机"）。应用程序**不硬编码物理地址**。

**好处**：

- **对用户/应用程序**：
  - 应用程序不绑定具体硬件，更换设备（如把打印机从并口升级为 USB）不需要重新编译。
  - 用户可以用别名或环境变量选择设备（如 `PRINTER=hp5`）。
  - 简化编程：同一套 `open/read/write` 接口适用于几乎所有设备。

- **对操作系统**：
  - 方便添加新设备与驱动程序：新驱动注册后应用程序即可使用，无需修改内核其他部分。
  - 便于负载均衡：多个同类型设备可按负载选择最合适的一个服务请求。
  - 支持热插拔（USB、PCIe Hotplug）：设备动态加入/移除时系统可动态更新映射表。
  - 便于虚拟化：在虚拟机中，逻辑设备名可以指向宿主机提供的虚拟设备。

**（3）设备控制器、驱动程序、通道的关系**

- **设备控制器（Controller）**：硬件，介于 CPU/总线 与 I/O 设备之间。包含命令寄存器、状态寄存器、数据缓冲寄存器，负责把 CPU 的命令翻译成设备可理解的信号（如向磁盘发"寻道到磁道 X"），也把设备状态翻译成 CPU 可读的信息。
- **设备驱动程序（Driver）**：软件，运行在内核态。它知道如何操作控制器寄存器，能理解控制器返回的状态码，把高层请求（如"读取磁盘块 12345"）翻译为一系列对控制器寄存器的写入和读取；并在中断时解释控制器状态、完成请求。
- **通道（Channel）**：更高级的硬件——一种小型专用 I/O 处理器（常见于 IBM 大型机、部分嵌入式和高性能系统）。CPU 构造一串通道命令（CCW，Channel Command Word）在内存中，然后用一条"启动通道"指令把执行权交给通道；通道独立执行通道程序，控制多个控制器和设备，完成后中断 CPU。通道比 DMA 更进一步：DMA 只传输连续数据块，通道可以执行包含分支、循环、多段传输的复杂程序。

**三者关系**：
```
CPU ──发命令──→ 通道 ──通道程序──→ 设备控制器1 ──→ 设备A
                        │
                        └──────────→ 设备控制器2 ──→ 设备B
```
驱动程序由 CPU 执行，构造通道程序或 DMA 参数，指挥通道/控制器去操作实际设备。

**（4）设备分配应考虑的因素**

- **设备类型**：字符设备/块设备/网络设备；是否需要独占访问。
- **优先级**：高优先级进程（如实时任务）应优先获得设备，可能抢占低优先级进程已占用的设备（可抢占设备）。
- **是否可抢占**：磁盘等块设备可抢占（切换到其他请求后可继续），打印机等设备不可抢占（必须打印完一份文档才能换下一份）。
- **设备共享性**：磁盘可被多个进程同时访问（需通过文件系统协调）；打印机必须互斥。
- **设备状态**：是否忙、是否故障、是否需要重新初始化。
- **死锁避免**：按固定顺序申请设备，或银行家算法避免循环等待。

**为什么要引入设备分配表（DAT/SDT）？**

设备分配表（Device Allocation Table，也叫系统设备表 SDT、每个进程一张的进程设备表 PDT，以及 DCT/控制器表 COCT/通道表 CHCT 等）是操作系统跟踪设备状态与使用者的数据结构。没有它：

- 无法判断某设备当前是否空闲、是否被进程占用；
- 无法快速从设备号查到对应驱动程序入口；
- 无法检测并防止死锁（无法回溯进程-设备占用关系）；
- 无法在进程退出时自动释放未关闭的设备。

DAT 是设备管理的数据基础设施，类似 PCB 之于进程管理、页表之于内存管理。

**（5）独享设备 / 共享设备 / 虚拟设备**

- **独享设备（Exclusive Device）**：物理上同一时刻只能由一个进程使用的设备。进程必须一直占用到任务完成，中途不可被其他进程打断。**典型例子**：打印机、磁带机、早期卡片阅读机。
- **共享设备（Shared Device）**：可以被多个进程"同时"访问的设备——多个进程的请求可以交错排队处理，设备在它们之间切换而不破坏数据。**典型例子**：磁盘（多个进程可以各读自己的文件）、网卡。
- **虚拟设备（Virtual Device，SPOOLing）**：通过软件把一台独享设备改造为若干台"逻辑上的同类设备"，让多个用户/进程感觉自己独占一台。核心机制：在磁盘上设置输入井和输出井。用户进程把打印任务写入输出井（可并发），由专用守护进程按顺序把井中数据发送给实际打印机。**典型例子**：打印机 SPOOLing（UNIX 的 lpd、Windows 的打印后台处理服务）。

三者关系：SPOOLing 把"独享设备"在用户眼中变成了"共享的虚拟设备"。

**出处**：汤子瀛《计算机操作系统》第五章；王道《操作系统》第五章

### 题 20

**题干**：某磁盘请求序列（按磁道号）为：55, 58, 39, 18, 90, 160, 150, 38, 184。当前磁头位于 100 号磁道，且刚刚处理完来自 120 的请求（即上一个服务方向是从 120 → 100，向低磁道方向）。

分别使用以下调度算法，计算磁头移动的总柱面数（仅按绝对值累加），并按性能从高到低排序：

（1）FCFS（先来先服务）
（2）SSTF（最短寻道时间优先）
（3）SCAN（电梯算法，取当前方向继续）
（4）C-SCAN（循环扫描，当前方向走到尽头后直接跳到另一端最近的请求再继续同方向）
（5）LOOK / C-LOOK（走到最后一个请求即换向/回头，不走到磁盘物理边界）

（6）简要评价各算法的公平性与性能，并说明为什么 LOOK/C-LOOK 在现代磁盘调度中被广泛使用。

**标准答案**：

给出当前位置 100，方向"刚刚从 120 到 100"→ 当前方向向低磁道。请求集合 {18, 38, 39, 55, 58, 90, 150, 160, 184}。

（1）FCFS：按顺序 55→58→39→18→90→160→150→38→184；移动 = 45+3+19+21+72+70+10+112+146 = 498。
（2）SSTF：每次选最近。100→90→58→55→39→38→18→150→160→184；移动 = 10+32+3+16+1+20+132+10+24 = 248。
（3）SCAN（向低，直到 0 再回头向高）：100→90→58→55→39→38→18→0→150→160→184；移动 ≈ 10+32+3+16+1+20+18+150+10+24 = 284。
（4）C-SCAN（向高走到尽头后跳回最低请求再继续向高；本题可另设方向）：100→150→160→184→END→18→38→39→55→58→90；或按当前方向继续向低：100→90→58→55→39→38→18→0→跳 184→160→150；移动 = 10+32+3+16+1+20+18+~184+24+10 = 约 338。取决于具体方向设定。
（5）LOOK（走到最后一个请求即回头）：向低 100→90→58→55→39→38→18；换向向高 18→150→160→184；移动 = 10+32+3+16+1+20+132+10+24 = 248。（与 SSTF 在此例一致）
（6）LOOK/C-LOOK 性能接近 SSTF 且无饥饿问题，不做无意义"走到磁盘尽头"的额外移动，被广泛采用。

**答案解析**：

**请求集合（已排序）**：18, 38, 39, 55, 58, 90, 150, 160, 184（共 9 个请求）。
当前磁头：100。上一步从 120 来 → 正在向低磁道方向移动。

**（1）FCFS（先来先服务）**

服务顺序：55 → 58 → 39 → 18 → 90 → 160 → 150 → 38 → 184。
各段移动：
- 100→55 = 45
- 55→58 = 3
- 58→39 = 19
- 39→18 = 21
- 18→90 = 72
- 90→160 = 70
- 160→150 = 10
- 150→38 = 112
- 38→184 = 146

总移动 = 45+3+19+21+72+70+10+112+146 = **498**。

FCFS 公平（按到达顺序）但性能最差，没有利用寻道优化。

**（2）SSTF（最短寻道时间优先）**

每步选距离当前磁头最近的请求。

- 当前 100：最近请求 = 90（10）
- 当前 90：最近 = 58（32）或 150（60）→ 选 58
- 当前 58：最近 = 55（3）
- 当前 55：最近 = 39（16）
- 当前 39：最近 = 38（1）
- 当前 38：最近 = 18（20）
- 当前 18：最近 = 55（37，已处理），未处理最近 = 150（132）
- 当前 150：最近 = 160（10）
- 当前 160：最近 = 184（24）

服务顺序：100 → 90 → 58 → 55 → 39 → 38 → 18 → 150 → 160 → 184。
总移动 = 10 + 32 + 3 + 16 + 1 + 20 + 132 + 10 + 24 = **248**。

SSTF 寻道距离很短（接近最优），但可能导致饥饿（如果不断有靠近当前位置的请求到达，远处请求会被无限推迟）。

**（3）SCAN（电梯算法）**

按当前方向（向低磁道）服务沿途请求，直到磁盘最小磁道，再换向（向高磁道）服务。假设磁盘最小磁道为 0，最大 200。

- 当前 100，向低 → 90 → 58 → 55 → 39 → 38 → 18 → 0
- 换向向高 → 150 → 160 → 184

各段移动：
- 100→90 = 10
- 90→58 = 32
- 58→55 = 3
- 55→39 = 16
- 39→38 = 1
- 38→18 = 20
- 18→0 = 18
- 0→150 = 150
- 150→160 = 10
- 160→184 = 24

总移动 = 10+32+3+16+1+20+18+150+10+24 = **284**。

SCAN 公平（保证请求在有限次换向内被服务），避免饥饿，但多走了 0→18 和最后从 0 跳回 150 的 150 段额外距离（因为 18 之后已经没有更低请求）。

**（4）C-SCAN（循环扫描）**

按一个方向服务沿途请求直到尽头，然后直接跳回另一端第一个请求（跳过中间无请求区域），再继续同方向。本题设定"一直向高"或"一直向低"。两种实现：

方案 A（一直向高）：100 → 150 → 160 → 184 → 200（尽头） → 跳回 18 → 38 → 39 → 55 → 58 → 90
- 移动 = 50 + 10 + 24 + 16 + 182 + 20 + 1 + 16 + 3 + 32 = **354**（从 200 跳回 18 的那 182 不寻道，但磁头实际要移动，题目要求"移动柱面数"——所以跳跃也计入）。

方案 B（一直向低）：100 → 90 → 58 → 55 → 39 → 38 → 18 → 0（尽头）→ 跳回 184 → 160 → 150
- 移动 = 10 + 32 + 3 + 16 + 1 + 20 + 18 + 184 + 24 + 10 = **318**。

C-SCAN 的优势在于"从一端返回时不服务中间请求"，使得请求被服务的等待时间更均匀（不像 SCAN 会有"长-短-长"波动），但总移动距离通常比 SCAN 更长。

**（5）LOOK（电梯的"看一下是否还有请求"优化）**

SCAN 的改进：不走到物理尽头，只走到当前方向上最后一个请求即换向。

- 当前方向向低：100 → 90 → 58 → 55 → 39 → 38 → 18（已是最低请求）
- 换向向高：18 → 150 → 160 → 184

总移动 = 10 + 32 + 3 + 16 + 1 + 20 + 132 + 10 + 24 = **248**。

本例中 LOOK 与 SSTF 总距离相同，但路径不同（SSTF 在处理低段后直接跳 150 也与 LOOK 等价）。一般 LOOK 略逊于 SSTF 但差距很小。

**C-LOOK**：C-SCAN 的 look 版本。向高走到最后一个请求（184）后直接跳回最低请求（18）再继续向高。
- 100 → 150 → 160 → 184 → 18 → 38 → 39 → 55 → 58 → 90
- 移动 = 50+10+24+166+20+1+16+3+32 = **322**。

**（6）评价与现代磁盘调度**

**公平性排序**：FCFS ≈ C-LOOK > SCAN ≈ LOOK > SSTF。
- FCFS 绝对公平（先到先服务），但寻道距离长。
- C-LOOK 使每个请求的等待时间更均匀（无论在哪个磁道，最坏情况都是一次跨整盘的往返）。
- SCAN/LOOK 较公平，但刚错过方向的请求要等待一次完整换向。
- SSTF 不公平，远处请求可能饥饿。

**性能（总移动距离）排序**：SSTF ≈ LOOK ≈ C-LOOK > SCAN > C-SCAN > FCFS。
- LOOK/C-LOOK 通常比 SCAN/C-SCAN 少走"到物理尽头"的多余距离。

**为什么 LOOK/C-LOOK 在现代磁盘中被广泛使用？**

1. **接近最优寻道**：LOOK 的总寻道距离与 SSTF 很接近，在实际负载下几乎同等性能。
2. **无饥饿问题**：LOOK 保证请求在有限次换向内被服务（最坏 2 次换向），不会像 SSTF 那样让远处请求无限等待。
3. **不做无意义寻道**：LOOK 在换向时只走到最后一个请求位置，避免 SCAN 走到物理边界的多余移动（现代磁盘有数千到数万磁道，那段空走不可忽视）。
4. **与磁盘缓存良好配合**：现代磁盘内部已有几十 MB 缓存，LOOK 的顺序访问模式有利于缓存预读（read-ahead）。
5. **实现简单**：维护当前磁头位置 + 当前方向 + 两个已排序请求队列（方向两侧各一个），每次从方向一侧取下一个请求；换向只需交换方向。
6. **现代 SSD 的特殊性**：SSD 没有机械磁头，寻道概念弱化，调度算法简化为 FIFO + 合并相邻请求（NCQ/NVMe 队列）。LOOK 对传统旋转磁盘依然重要，对 SSD 意义减小。

**出处**：王道《操作系统》第四章磁盘调度；Silberschatz《Operating System Concepts》磁盘调度章节
