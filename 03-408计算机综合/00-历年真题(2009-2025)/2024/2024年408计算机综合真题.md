### 1. 时间复杂度

设某算法的语句执行次数为$T(n)=3n^3+2n^2+5n+1$，则该算法的时间复杂度为

A. $O(n)$ &nbsp;&nbsp;&nbsp; B. $O(n^2)$ &nbsp;&nbsp;&nbsp; C. $O(n^3)$ &nbsp;&nbsp;&nbsp; D. $O(n^4)$

**【答案】C**

**【深度解析】**

**【第一步：审题与条件提取】**
- 已知条件：语句执行次数函数 $T(n)=3n^3+2n^2+5n+1$
- 问题目标：求时间复杂度
- 关键信息：时间复杂度只看最高次幂项，且忽略系数

**【第二步：思路探索】**
拿到这道题，我首先想到：
→ 时间复杂度是比较函数增长趋势
→ 当 n 趋于无穷大时，最高次幂项起主导作用
→ 系数不影响复杂度级别

我容易犯的错误是：
❌ 看系数3，认为是 $O(3n^3)$
❌ 不确定是否只取最高次幂

正确分析：
→ $T(n)$ 中最高次幂是 $n^3$
→ 其他项（$n^2$, $n$, 常数）在 n 很大时相对可以忽略
→ 所以时间复杂度为 $O(n^3)$

**【第三步：规范求解】**
时间复杂度计算规则：
1. 忽略所有低次幂项
2. 忽略最高次幂的系数
3. 只保留最高次幂

$T(n) = 3n^3 + 2n^2 + 5n + 1$

取最高次幂：$n^3$
忽略系数：3

所以 $O(n^3)$

**【第四步：答案确认】**
- 结果合理：最高次幂决定增长趋势
- 量纲正确：复杂度用大O表示
- 关键点：时间复杂度只与增长最快的项有关

### 2. 线性表

在单链表中，增加一个头结点的目的是

A. 使单链表至少有一个结点
B. 标识表结点中首结点的位置
C. 方便运算实现
D. 元素可以直接定位

**【答案】C**

**【深度解析】**

**【第一步：审题与条件提取】**
- 已知条件：单链表（带头结点）
- 问题目标：头结点的作用
- 关键信息：头结点是链表的第一个结点（可能不存储有效数据）

**【第二步：思路探索】**
拿到这道题，我这样想：
→ 单链表有带头结点和不带头结点两种形式
→ 头结点的数据域通常不存储有效数据
→ 头结点的主要作用是简化操作

为什么不选A？
→ 头结点不存储数据，不是为了"使链表至少有一个结点"

为什么不选B？
→ 头结点不直接标识首结点位置

为什么不选D？
→ 链表不支持随机访问，不能直接定位元素

正确分析：
→ 头结点使得对第一个结点的操作与对其他结点的操作一致
→ 插入/删除操作不需要特殊处理第一个结点
→ 简化代码实现，减少边界条件判断

**【第三步：规范求解】**
单链表不带头结点的情况：
- 插入第一个结点需要特殊处理
- 删除第一个结点需要特殊处理
- 代码中需要大量判断 p == L->next

单链表带头结点的情况：
- 头结点始终存在，作为"哨兵"
- 所有结点的插入删除操作统一
- 不需要边界判断，代码更简洁

**【第四步：答案确认】**
- 结果合理：头结点是操作上的便利
- 关键点：头结点不存储数据，是辅助结点
- 易错点：头结点不是用来标识首结点位置的

### 3. 栈的应用

表达式$A+B*(C-D)-E/F$的后缀表达式为

A. $ABCD-*+EF/-$ &nbsp;&nbsp;&nbsp; B. $ABCD-*+EF/-$  
C. $ABCD-*+EF/-$ &nbsp;&nbsp;&nbsp; D. $ABCD-*+EF/$

**【答案】A**

**【深度解析】**

**【第一步：审题与条件提取】**
- 已知条件：中缀表达式 $A+B*(C-D)-E/F$
- 问题目标：转换为后缀表达式（逆波兰式）
- 关键信息：后缀表达式中运算符在操作数后面

**【第二步：思路探索】**
拿到这道题，我这样想：
→ 中缀转后缀需要使用栈
→ 遇到操作数直接输出
→ 遇到运算符根据优先级和栈状态决定

运算符优先级（从高到低）：
1. 括号 ()
2. 一元运算符
3. 乘除 * /
4. 加减 + -

左括号处理：
→ 入栈
→ 右括号：弹出直到遇到左括号

**【第三步：规范求解】**
转换过程：

| 位置 | 符号 | 操作 | 输出 |
|------|------|------|------|
| 1 | A | 输出 | A |
| 2 | + | 入栈 | A |
| 3 | B | 输出 | AB |
| 4 | * | 栈顶+优先级高，入栈 | AB |
| 5 | ( | 入栈 | AB* |
| 6 | C | 输出 | AB*C |
| 7 | - | 入栈 | AB*C( |
| 8 | D | 输出 | AB*CD |
| 9 | ) | 弹栈到( | AB*CD- |
| 10 | - | 弹栈中的*，再入栈- | AB*CD-* |
| 11 | E | 输出 | AB*CD-*E |
| 12 | / | 栈顶-优先级低，入栈 | AB*CD-*E |
| 13 | F | 输出 | AB*CD-*EF |
| 结束 | - | 弹栈所有 | AB*CD-*EF/- |

最终后缀表达式：**ABCD-*+EF/-**

**【第四步：答案确认】**
- 结果合理：后缀表达式中运算符在操作数后面
- 关键点：括号内的运算先完成
- 易错点：运算符顺序不是简单的从左到右

A. 3 &nbsp;&nbsp;&nbsp; B. 4 &nbsp;&nbsp;&nbsp; C. 5 &nbsp;&nbsp;&nbsp; D. 6

**【答案】A**

**【深度解析】**

**【第一步：审题与条件提取】**
- 已知条件：广义表 $A=(a, (b, c), (d, (e, f)))$
- 问题目标：广义表的长度
- 关键信息：广义表的长度是"最外层"元素的个数

**【第二步：思路探索】**
拿到这道题，我这样想：
→ 广义表是线性表的推广
→ 线性表的元素可以是原子或子表
→ 长度计算：数最外层有多少个元素

广义表的结构：
- 原子：不可分的基本单位
- 子表：用括号括起来的广义表

**【第三步：规范求解】**
分析广义表 $A=(a, (b, c), (d, (e, f)))$ 的结构：

A的最外层元素有3个：
1. **a** - 原子
2. **(b, c)** - 子表
3. **(d, (e, f))** - 子表

所以长度 = 3

注意：长度不是元素总数
→ 如果数所有原子：a, b, c, d, e, f = 6个

**【第四步：答案确认】**
- 结果合理：最外层有3个元素
- 关键点：广义表长度 = 最外层逗号分隔的元素个数
- 易错点：混淆"元素个数"和"原子个数"

### 6. 图的连通性

一个有20个结点的无向图，最少有()条边才能保证该图是连通图

A. 19 &nbsp;&nbsp;&nbsp; B. 190 &nbsp;&nbsp;&nbsp; C. 180 &nbsp;&nbsp;&nbsp; D. 170

**【答案】A**

**【深度解析】**

**【第一步：审题与条件提取】**
- 已知条件：20个结点的无向图
- 问题目标：保证连通最少需要的边数
- 关键信息：连通图是任意两个结点都存在路径的图

**【第二步：思路探索】**
拿到这道题，我这样想：
→ 连通图要求所有结点都连通
→ 最少边的情况应该是生成树
→ 生成树有 n-1 条边

为什么不选B、C、D（190, 180, 170）？
→ 这些数字像是计算 n(n-1)/2（完全图的边数）
→ 完全图有 20×19/2 = 190 条边
→ 但题目问的是"最少"边数

正确分析：
→ 连通图的最小边数对应生成树
→ 生成树是连通且边数最少的图
→ 有 n 个结点的树有 n-1 条边

**【第三步：规范求解】**
连通图的最小边数：

**生成树的性质**：
- 连通
- 无环（不存在回路）
- 边数 = 结点数 - 1

对于 n = 20 个结点：
最小边数 = n - 1 = 20 - 1 = 19 条

验证：
→ 18条边最多连接19个结点
→ 19条边可以连接所有20个结点并形成树
→ 少于19条边一定不连通

**【第四步：答案确认】**
- 结果合理：树是连通且边数最少的图
- 关键点：生成树的边数 = n - 1
- 易错点：与完全图的边数混淆

### 7. 拓扑排序

**【第一步：审题与条件提取】**
- 已知条件：AOV网和拓扑排序相关知识
- 问题目标：找出错误说法
- 关键信息：拓扑排序的基本概念和性质

**【第二步：思路探索】**

→ AOV网（Activity On Vertex）：顶点表示活动的网
→ 拓扑排序的前提是有向无环图（DAG）
→ 如果有环，无法进行拓扑排序
→ A正确

**B. 拓扑排序是唯一的**
→ 这是错误的！
→ 拓扑排序的结果可能不唯一
→ 例如：两个入度为0的顶点，顺序可以互换
→ B错误

**C. 拓扑排序算法的时间复杂度为$O(n+e)$**
→ 拓扑排序通常用Kahn算法
→ 需要遍历所有顶点和边
→ 时间复杂度 O(n + e) 正确
→ C正确

**D. AOV网中不能出现环**
→ 如果有环，环内的顶点入度永远不为0
→ 无法进行拓扑排序
→ D正确

**【第三步：规范求解】**
拓扑排序的Kahn算法：
```
1. 计算所有顶点的入度
2. 将入度为0的顶点入队
3. while 队不空:
   a. 取出顶点v，输出
   b. 删除v的所有出边，更新相邻顶点入度
   c. 入度变为0的顶点入队
```

拓扑排序可能不唯一的例子：
```
A → B
A → C
B → D
C → D
```
拓扑序列可以是：A B C D 或 A C B D

- 关键点：拓扑排序的结果不一定唯一
- 易错点：认为拓扑排序是唯一确定的

### 23. 奈奎斯特准则

在无噪声情况下，若信道带宽为4kHz，则最大码元传输速率为

**【第二步：思路探索】**

→ 在无噪声情况下，最大码元速率 = 2 × 信道带宽

其中：

代入计算：
$$R_{max} = 2 × 4000 = 8000 \text{ Baud}$$

注意：Baud（波特）是码元传输速率的单位

- 如果每个码元携带n比特信息，则比特率 = n × 波特率

### 26. 伙伴算法（操作系统）

下列算法中，每次回收分区时仅合并大小相等的空闲分区的是（）。

A.伙伴算法 &nbsp;&nbsp;&nbsp; B.最佳适应算法 &nbsp;&nbsp;&nbsp; C.最坏适应算法 &nbsp;&nbsp;&nbsp; D.首次适应算法

**【答案】A**

**【深度解析】**

**【第一步：审题与条件提取】**
- 已知条件：内存分配算法
- 问题目标：找出"仅合并大小相等的空闲分区"的算法
- 关键信息：伙伴算法的特点

**【第二步：思路探索】**
动态分区分配算法分析：

**首次适应（First Fit）**：
→ 分配第一个满足大小的空闲分区
→ 回收时合并所有相邻空闲分区 ❌

**最佳适应（Best Fit）**：
→ 分配最小的满足大小的空闲分区
→ 回收时合并所有相邻空闲分区 ❌

**最坏适应（Worst Fit）**：
→ 分配最大的空闲分区
→ 回收时合并所有相邻空闲分区 ❌

**伙伴算法（Buddy System）**：
→ 按2的幂次方分配内存
→ 回收时只能合并"大小相等"的伙伴块
→ 伙伴块：同一块分裂产生的两个块 ✓

**【第三步：规范求解】**

伙伴算法示例：
```
初始：内存大小2^k

分配大小为2^j的块时：
1. 查找大小为2^j的空闲块
2. 若找到，分配
3. 若找不到，查找2^(j+1)的块
4. 若找到，分裂成两个2^j的伙伴块
5. 重复直到找到可分配的块

回收时：
1. 标记块为空闲
2. 检查伙伴块是否也空闲且大小相等
3. 若相等，合并成更大的块
4. 重复直到不能合并
```

关键特点：
→ 伙伴块必须是同一块分裂产生
→ 大小必须相等
→ 地址有特定关系（低位为0或1）

**【第四步：答案确认】**
- 结果：伙伴算法
- 关键点：伙伴算法的合并条件是"大小相等的伙伴块"
- 易错点：混淆伙伴算法与传统动态分区分配的合并策略

### 47. 网络协议分析（10分）

甲乙两台主机建立TCP连接，初始序号为1000。甲向乙发送数据200字节后，甲发送FIN段请求断开连接。

**(1)** 此时甲发送的FIN段的序号是多少？
**(2)** 如果甲的拥塞窗口cwnd=1 MSS，传输10个RTT后，cwnd变为多少？（假设没有发生拥塞）
**(3)** TCP可靠传输是如何实现的？

**【答案】**

**(1)** FIN段序号=1200
**(2)** TCP拥塞窗口变化
**(3)** TCP可靠传输机制

**【深度解析】**

**【第一步：审题与条件提取】**
- 已知条件：TCP连接，初始seq=1000，发送200字节数据后发送FIN
- 问题目标：FIN序号、拥塞窗口变化、可靠传输机制
- 关键信息：TCP序号机制和拥塞控制

**【第二步：思路探索】**
**(1) FIN序号**
→ FIN段的序号 = 最后一个数据字节的序号 + 1
→ 发送200字节后，下一个序号是1000+200=1200
→ FIN序号 = 1200

**(2) 拥塞窗口**
→ 假设慢启动门限ssthresh足够大
→ 初始cwnd=1 MSS
→ 慢启动阶段每RTT翻倍
→ 到达门限后进入拥塞避免，缓慢增长

**(3) 可靠传输机制**
→ 序号、确认、超时重传、流量控制、拥塞控制

**【第三步：规范求解】**

**(1) FIN段序号**

甲发送200字节数据：
- 数据字节序号：1000 ~ 1199
- FIN序号 = 1200（下一个期望的字节序号）

**(2) 拥塞窗口变化（假设TCP Reno/Tahoe）**

初始：cwnd = 1 MSS

慢启动阶段（每RTT翻倍）：
- RTT1：cwnd = 1 → 2 MSS
- RTT2：cwnd = 2 → 4 MSS
- RTT3：cwnd = 4 → 8 MSS
- RTT4：cwnd = 8 → 16 MSS

假设ssthresh = 16 MSS

- RTT5：到达门限，进入拥塞避免，每次+1
- RTT5：cwnd = 16 → 17 MSS
- RTT6：cwnd = 17 → 18 MSS
- RTT7：cwnd = 18 → 19 MSS
- RTT8：cwnd = 19 → 20 MSS
- RTT9：cwnd = 20 → 21 MSS
- RTT10：cwnd = 21 → 22 MSS

传输10个RTT后，cwnd = 22 MSS

**(3) TCP可靠传输机制**

1. **序号机制**：
   - 每个字节都有序号
   - 数据段包含起始序号

2. **确认机制（ACK）**：
   - 接收方确认收到的数据
   - 确认序号表示期望收到的下一个字节

3. **超时重传**：
   - 发送方设置定时器
   - 超时未收到确认则重传

4. **流量控制**：
   - 滑动窗口
   - 接收方通过窗口大小控制发送速率

5. **拥塞控制**：
   - 慢启动
   - 拥塞避免
   - 快速恢复

**【第四步：答案确认】**
- 结果：FIN序号1200，cwnd=22 MSS
- 关键点：FIN序号是最后一个数据序号+1
- 易错点：混淆慢启动和拥塞避免阶段
