# 笔试：编译原理

## 一、编译概述

### 题目 1：编译程序的结构与各阶段功能

**题目**：简述编译程序的基本组成结构和各阶段的主要功能，并画出编译程序的典型流程图。

**标准答案**：

**编译程序（编译器）**：是一种将高级语言（源语言）编写的程序翻译成等价的低级语言（目标语言，如汇编语言或机器语言）程序的系统软件。

**编译程序的典型阶段**：

| 阶段 | 主要功能 | 输入 | 输出 |
|------|---------|------|------|
| **1. 词法分析**（Lexical Analysis） | 扫描源程序字符流，识别出具有独立含义的最小语法单位——单词（Token） | 源程序字符串 | 单词序列（Token 流） |
| **2. 语法分析**（Syntax Analysis） | 根据语言的语法规则，将单词序列分解为各类语法单位（表达式、语句、程序等），分析语法结构 | Token 流 | 语法分析树 / 抽象语法树（AST） |
| **3. 语义分析**（Semantic Analysis） | 审查源程序的语义错误，收集类型信息，进行类型检查和类型转换 | 语法树 | 带语义信息的语法树 |
| **4. 中间代码生成**（Intermediate Code Generation） | 将源程序转换为一种介于源语言和目标语言之间的内部表示形式 | 带语义信息的语法树 | 中间代码（如三地址码、四元式） |
| **5. 代码优化**（Code Optimization） | 对中间代码进行变换，使生成的目标代码更高效（时间/空间） | 中间代码 | 优化后的中间代码 |
| **6. 目标代码生成**（Target Code Generation） | 将中间代码转换为特定机器的目标代码（汇编或机器语言） | 优化后的中间代码 | 目标代码（汇编/机器码） |

**编译程序流程图**：

```
        ┌──────────┐   Token    ┌──────────┐   语法树   ┌──────────┐
源程序 →│ 词法分析 │──────────→│ 语法分析 │──────────→│ 语义分析 │
        └──────────┘            └──────────┘            └──────────┘
                                                              ↓
                                                        带语义的语法树
        ┌──────────┐   目标代码   ┌──────────┐   中间代码   ┌──────────┐
        │目标代码生成│ ←────────── │ 代码优化 │ ←────────── │中间代码生成│
        └──────────┘               └──────────┘               └──────────┘
              ↓
           目标代码
```

**表格管理（符号表）**：贯穿编译全过程，记录标识符的名字、类型、作用域等信息。

**错误处理**：在各阶段检查和处理源程序中的错误，报告错误信息，保证编译能继续进行。

### 题目 2：编译程序与解释程序的区别

**题目**：比较编译程序和解释程序的工作方式及特点。

**标准答案**：

| 对比项 | 编译程序（Compiler） | 解释程序（Interpreter） |
|--------|----------------------|------------------------|
| **工作方式** | 先将源程序完整翻译为目标代码，然后执行目标代码 | 逐条翻译源程序语句，翻译一条立即执行一条 |
| **输出** | 产生独立的目标程序文件 | 不产生目标程序文件，直接在解释器中运行 |
| **执行速度** | 快（编译后执行，无需再翻译） | 慢（每次运行都要翻译） |
| **存储空间** | 需要额外存储空间存放目标代码 | 无需额外空间，但运行时占用内存较大 |
| **跨平台性** | 目标代码依赖硬件平台，不可移植 | 解释器可跨平台，源程序可直接在不同平台运行 |
| **调试支持** | 较差（需要重新编译） | 较好（可以单步执行，查看中间状态） |
| **典型代表** | C、C++、Pascal、Rust | BASIC（早期）、Python、JavaScript、Shell |
| **特点** | 高效、适合性能敏感的程序 | 灵活、易于开发和调试 |

**混合方式（Just-In-Time Compilation, JIT）**：
- 先将源程序翻译为中间代码（如 Java 字节码、.NET IL）
- 运行时由虚拟机解释执行或动态编译为机器码执行
- 结合了编译和解释的优势
- 典型代表：Java、C#、JavaScript（V8 引擎）

## 二、词法分析

### 题目 3：正则表达式 → NFA → DFA → 最小化 DFA

**题目**：设字母表 Σ = {a, b}，给定正则表达式 r = (a|b)\*abb
(1) 写出该正则表达式表示的语言
(2) 构造识别该语言的 NFA（使用 Thompson 构造法）
(3) 将 NFA 转换为 DFA（使用子集构造法 / ε-闭包）
(4) 最小化 DFA

**标准答案**：

**(1) 正则表达式表示的语言**

L(r) = {以 abb 结尾的所有 a, b 串}

即 L = {abb, aabb, babb, aaabb, ababb, baabb, bbabb, ...}（包括所有长度 ≥ 3 且以 abb 结尾的字符串）

**(2) 构造 NFA（Thompson 构造法）**

使用 Thompson 构造法，逐部分构建：

1. "a" 的 NFA: (1) --a--> (2)
2. "b" 的 NFA: (3) --b--> (4)
3. "a|b" 的 NFA: 并联两个子 NFA
4. "(a|b)*" 的 NFA: 添加 ε 循环
5. "abb" 的 NFA: (5) --a--> (6) --b--> (7) --b--> (8)
6. 连接 "(a|b)*" + "abb"

完整 NFA 状态图（编号 0-8）：
```
          ┌───────────────────────────────────┐
          ε                                    ε
          ↓                                    ↑
   ┌─→ [0] ──ε→ [1] ─┐a ┌[2]┐ b ┌[3]┐ b ┌[4]┐
   │     ↑      │     │ │   │    │   │    │   │
   │     └──ε───┘     →│   ├──→│   ├──→│[终]│
   └───────ε──────────┘│   │    │   │    │   │
                        └───┘ b  └───┘    └───┘
```
其中 [4] 是终态（接受状态）。

**(3) 子集构造法（ε-闭包）转换为 DFA**

- ε-closure({0}) = {0, 1, 2}（初态，记为 A）

处理 A = {0, 1, 2}:
- A 经 a: ε-closure(move(A, a)) = ε-closure({2, 3}) = {2, 3}（记为 B）
- A 经 b: ε-closure(move(A, b)) = ε-closure({2}) = {2}（记为 C）

处理 B = {2, 3}:
- B 经 a: ε-closure(move(B, a)) = {2, 3} = B
- B 经 b: ε-closure(move(B, b)) = {2, 4} = D（含终态 4，是终态）

处理 C = {2}:
- C 经 a: ε-closure(move(C, a)) = {2, 3} = B
- C 经 b: ε-closure(move(C, b)) = {2} = C

处理 D = {2, 4}:
- D 经 a: ε-closure(move(D, a)) = {2, 3} = B
- D 经 b: ε-closure(move(D, b)) = {2} = C

**DFA 状态转移表**：

| 状态（NFA 状态集） | a | b | 终态 |
|-------------------|---|---|------|
| A = {0, 1, 2} | B | C | 否 |
| B = {2, 3} | B | D | 否 |
| C = {2} | B | C | 否 |
| D = {2, 4} | B | C | 是 ✓ |

**(4) DFA 最小化（Hopcroft 算法）**

初始划分（按终态/非终态）：
- Π₀ = {{A, B, C}, {D}}

进一步划分 {A, B, C}：
- 对输入 a: A→B, B→B, C→B（都在同一组，不分）
- 对输入 b: A→C, B→D, C→C
  - B 的目标是 D（在 {D} 组）
  - A, C 的目标是 C（在 {A,B,C} 组）
  - 所以 B 可以被分离

Π₁ = {{A, C}, {B}, {D}}

进一步划分 {A, C}：
- 对 a: A→B, C→B（都在 {B} 组）
- 对 b: A→C, C→C（都在 {A,C} 组）
- 无法再分

**最小化 DFA**（合并 A 和 C）

状态：{A,C}、B、D

| 状态 | a | b | 终态 |
|------|---|---|------|
| {A,C} | B | {A,C} | 否 |
| B | B | D | 否 |
| D（终态） | B | {A,C} | 是 ✓ |

最小化 DFA 图示：
```
        b                   b
   ┌─────────┐      ┌──────────────┐
   ↓         │      ↓              │
 [A/C] ──a→ [B] ──b→ [D（终态）] ─a→ [B]
   ↑                           │
   └───────────b───────────────┘
```

**解析**：

**重要概念**：
- **ε-闭包（ε-closure）**：从某状态出发，经过任意条 ε 弧（包括 0 条）能到达的状态集合
- **ε-NFA**：允许 ε 跳转的有限自动机（便于构造）
- **DFA**：确定的有限自动机，对每个状态和每个输入符号，有且仅有一个转移
- **NFA 与 DFA 等价**：任何 NFA（包括 ε-NFA）都存在等价的 DFA（L(NFA) = L(DFA)）
- **正则表达式、NFA、DFA 的等价性**：三者描述的语言类完全相同——正则语言

**Thompson 构造法**：
- 对 ε：只有初态和终态的 NFA
- 对单个字符 a：初态 --a→ 终态
- 对 r₁|r₂：并联两个子 NFA（ε 跳转连接）
- 对 r₁r₂：串联两个子 NFA（r₁ 的终态与 r₂ 的初态合并）
- 对 r*：添加 ε 循环（可以回到起点或跳过）

**子集构造法（Subset Construction）**：
- 核心思想：用 NFA 状态集合作为 DFA 的单个状态
- ε-closure(I)：I 中状态经任意 ε 可达的所有状态
- move(I, a)：从 I 中状态经 a 弧可直接到达的状态
- DFA 状态 = ε-closure(move(DFA 状态, 字符))

**Hopcroft 最小化算法**：
- 思想：不断细化划分，将等价（不可区分）的状态合并
- 两个状态等价当且仅当：对每个输入符号，它们转移到同一组状态
- 初始划分：终态组 vs 非终态组
- 反复细化直到划分不再变化
- 最小化 DFA 在同构意义下唯一

### 题目 4：词法分析器设计

**题目**：设计一个识别 Pascal 语言中整数、实数和标识符的词法分析器。要求：
(1) 写出相应的正则表达式
(2) 设计状态转换图
(3) 说明如何处理关键字（保留字）与标识符的冲突

**标准答案**：

**(1) 正则表达式**

字母 letter = a | b | c | ... | z | A | B | ... | Z
数字 digit  = 0 | 1 | 2 | ... | 9

- **标识符**：letter(letter|digit)\*
  - 由字母开头，后跟字母或数字组成的串

- **无符号整数**：digit⁺（一个或多个数字）

- **无符号实数**：digit⁺ . digit⁺ ( (e|E) (+|-|ε) digit⁺ )?  |  digit⁺ (e|E) (+|-|ε) digit⁺
  - 如：123.45, 0.5, 123e10, 123E-5, 1.23e+4

**(2) 状态转换图**

综合识别整数/实数的状态图（简化版）：
```
                digit                 digit                   E/e
  [开始] ──digit→ [1] ──digit→ [2（接受整数）] ──E/e→ [4]
                │             │
                │非digit     │其他
                │             │
                └. →[3]──digit→[5（接受实数）]──digit→[5]──E/e→[4]
                                                     │
                                                     └其他 → [终态，回退]

  [4] ──+/-/digit→ [6] ──digit→ [7（接受实数，含指数）]
                           │
                           └其他 → [终态，回退]
```

**标识符识别**：
```
                letter/digit
  [开始] ──letter→ [1] ──letter/digit→ [2（接受标识符）]
                     │
                     └其他 → [终态，回退]
```

**(3) 关键字与标识符的冲突处理**

**问题**：关键字（如 "begin", "end", "if", "then", "else" 等）本身也是合法的标识符，需要区分。

**处理方法**：

**方法 1：查表法（最常用）**

初始化时将所有关键字存入一张"关键字表"（哈希表或有序表），识别出标识符后，去关键字表中查找：
- 若找到：该标识符是关键字，返回相应的关键字类别
- 若未找到：该标识符是普通用户定义的标识符

示例（Pascal）：
```
关键字表：{
    "begin"  → 关键字_BEGIN,
    "end"    → 关键字_END,
    "if"     → 关键字_IF,
    "then"   → 关键字_THEN,
    "else"   → 关键字_ELSE,
    "while"  → 关键字_WHILE,
    ...
}

识别过程：
1. 识别出字符串 "begin"
2. 在关键字表中查找 "begin"
3. 找到 → 返回 Token（关键字_BEGIN, "begin"）

识别出字符串 "myvar"：
1. 在关键字表中查找 "myvar"
2. 未找到 → 返回 Token（标识符, "myvar"）
```

**方法 2：状态图法（将关键字单独识别）**

在状态转换图中为每个关键字设置单独的识别路径，识别关键字时直接进入关键字状态。

缺点：关键字数量多时状态图过于复杂，不实用。

**方法 3：最长匹配原则 + 查表**

词法分析器遵循"最长匹配原则"（Maximal Munch），每次读取能识别出的最长字符串作为 Token，识别出后查表确认类型。

**例子**：
- 对于 "ifx"：最长匹配得到 "ifx"，在关键字表中查不到 → 识别为标识符
- 对于 "if x"：空格是分隔符，先识别 "if" → 在关键字表中找到 → 关键字_IF

## 三、语法分析

### 题目 5：上下文无关文法（CFG）与二义性

**题目**：给定文法 G:
```
E → E + E | E * E | (E) | i
```
其中 i 表示标识符或常量。
(1) 证明该文法是二义的
(2) 给出句子 i + i * i 的两个不同的语法分析树
(3) 给出与该文法等价的无二义文法（规定 * 优先于 +，且均为左结合）

**标准答案**：

**(1) 二义性证明**

**二义性定义**：如果一个文法存在某个句子对应两棵不同的语法树（或存在两个不同的最左推导 / 最右推导），则称这个文法是二义的。

对于句子 `i + i * i`，可以有两种不同的最左推导：

**推导 1**（先扩展第一个 E 为 E+E）：
```
E ⇒ E + E
  ⇒ i + E
  ⇒ i + E * E
  ⇒ i + i * E
  ⇒ i + i * i
```

**推导 2**（先扩展第一个 E 为 E*E）：
```
E ⇒ E * E
  ⇒ E + E * E
  ⇒ i + E * E
  ⇒ i + i * E
  ⇒ i + i * i
```

由于存在两个不同的最左推导产生同一句子，该文法是**二义的**。

**(2) 两棵不同的语法树**

**语法树 1**（+ 比 * 先运算 → (i+i)*i）：
```
        E
      / | \
     E  +  E
     │    / | \
     i   E  *  E
         │     │
         i     i
```

**语法树 2**（* 比 + 先运算 → i+(i*i)）：
```
        E
      / | \
     E  +  E
     │    / | \
     i   E  *  E
         │     │
         i     i
```

两棵树结构不同，但产生的叶子序列相同，证明了二义性。

**(3) 等价的无二义文法**

思想：引入不同优先级别的非终结符，规定优先级和结合性。
- 低优先级（+）：E 表达式
- 中优先级（*）：T 项
- 最高优先级（括号、原子）：F 因子

**无二义文法**：
```
E → E + T | T       （表达式 = 表达式 + 项 或 就是项）
T → T * F | F       （项 = 项 * 因子 或 就是因子）
F → (E) | i         （因子 = (表达式) 或 标识符/常量）
```

**验证句子 i + i * i 的唯一最左推导**：
```
E ⇒ E + T
  ⇒ T + T
  ⇒ F + T
  ⇒ i + T
  ⇒ i + T * F
  ⇒ i + F * F
  ⇒ i + i * F
  ⇒ i + i * i
```

对应的**唯一语法树**：
```
        E
      / | \
     E  +  T
     │    / | \
     T   T  *  F
     │   │     │
     F   F     i
     │   │
     i   i
```

此时 * 在树的下层，先被计算；+ 在树的上层，后被计算。符合 "* 优先于 +"。

**左结合性验证**：句子 i + i + i

推导：E ⇒ E+T ⇒ E+T+T ⇒ T+T+T ⇒ F+T+T ⇒ i+F+T ⇒ i+i+F ⇒ i+i+i

语法树结构：左侧 E+T 在下层，先计算 (i+i)，再与右边的 i 相加，即 ((i+i)+i)，符合左结合。

**解析**：

**文法二义性要点**：
1. **二义性的根源**：文法中缺少优先级和结合性的规定
2. **无二义性不可判定**：不存在通用算法来判定一个文法是否二义（这是不可判定问题）
3. **解决二义性的方法**：
   - 改写文法（本题使用的方法）
   - 规定优先级和结合性（在 YACC/Bison 等工具中使用）
   - 使用消歧规则（如最近嵌套匹配 if-else）

**优先级与产生式的关系**：
- 离开始符号越远（在语法树越下层）的非终结符，优先级越高
- 左递归产生式（如 E → E + T）实现左结合
- 右递归产生式（如 E → T + E）实现右结合

### 题目 6：LL(1) 分析法

**题目**：给定文法 G:
```
S → a A | b B | c
A → a A | d
B → b B | e
```
(1) 计算每个产生式的 FIRST 集和 FOLLOW 集
(2) 构造预测分析表（LL(1) 分析表）
(3) 判断该文法是否为 LL(1) 文法
(4) 分析输入串 "aad" 是否为该文法的句子（给出分析步骤）

**标准答案**：

**(1) 计算 FIRST 集和 FOLLOW 集**

**FIRST 集**（可从产生式右部第一个推出的终结符集合）：

- S → aA: FIRST(aA) = {a}
- S → bB: FIRST(bB) = {b}
- S → c: FIRST(c) = {c}
- A → aA: FIRST(aA) = {a}
- A → d: FIRST(d) = {d}
- B → bB: FIRST(bB) = {b}
- B → e: FIRST(e) = {e}

**FOLLOW 集**（跟随在非终结符后的终结符集合，以及 #）：

- **FOLLOW(S)**: S 是开始符号，# ∈ FOLLOW(S) = {#}
- **FOLLOW(A)**: A 出现在 S → aA 右部末尾和 A → aA 右部末尾
  - FOLLOW(S) ⊆ FOLLOW(A)（A 在末尾）
  - FOLLOW(A) = {#}
- **FOLLOW(B)**: B 出现在 S → bB 右部末尾和 B → bB 右部末尾
  - FOLLOW(S) ⊆ FOLLOW(B)
  - FOLLOW(B) = {#}

**总结**：

| 非终结符 | FIRST | FOLLOW |
|---------|-------|--------|
| S | {a, b, c} | {#} |
| A | {a, d} | {#} |
| B | {b, e} | {#} |

**(2) 构造 LL(1) 预测分析表 M[A, a]**

规则：对每个产生式 A → α：
1. 对 ∀a ∈ FIRST(α)，M[A, a] = A → α
2. 若 ε ∈ FIRST(α)，则对 ∀b ∈ FOLLOW(A)，M[A, b] = A → α

分析表（行 = 非终结符，列 = 输入符号）：

| | a | b | c | d | e | # |
|---|---|---|---|---|---|---|
| S | S→aA | S→bB | S→c | | | |
| A | A→aA | | | A→d | | |
| B | | B→bB | | | B→e | |

**(3) 判断是否为 LL(1) 文法**

LL(1) 文法的充要条件（对每个非终结符 A 的任意两个不同产生式 A → α | β）：
1. FIRST(α) ∩ FIRST(β) = ∅
2. 若 ε ∈ FIRST(β)，则 FIRST(α) ∩ FOLLOW(A) = ∅

验证：
- S 的产生式 FIRST 集两两不交：{a} ∩ {b} = ∅, {a} ∩ {c} = ∅, {b} ∩ {c} = ∅ ✓
- A 的产生式 FIRST 集：{a} ∩ {d} = ∅ ✓
- B 的产生式 FIRST 集：{b} ∩ {e} = ∅ ✓
- 均不含 ε，条件 2 自动满足 ✓

**结论**：该文法是 LL(1) 文法。

**(4) 分析输入串 "aad"**

使用栈式分析器（分析栈初始 [#, S]，输入串 "aad#"）：

| 步骤 | 分析栈 | 剩余输入 | 动作（产生式/匹配） |
|------|--------|---------|-------------------|
| 0 | #S | aad# | 初始状态 |
| 1 | #Aa | aad# | S → aA（栈顶 S，输入 a） |
| 2 | #A | ad# | 匹配 a（弹出栈顶 a，输入指针前进） |
| 3 | #Aa | ad# | A → aA（栈顶 A，输入 a） |
| 4 | #A | d# | 匹配 a |
| 5 | #d | d# | A → d（栈顶 A，输入 d） |
| 6 | # | # | 匹配 d |
| 7 | # | # | 栈顶 = # = 当前输入，接受！ ✓ |

**分析成功**，"aad" 是该文法的句子。

推导过程验证：S ⇒ aA ⇒ aaA ⇒ aad

**解析**：

**LL(1) 分析器工作原理**：
- 使用一个栈保存分析过程中的非终结符和终结符
- 每次决策：
  1. 栈顶是终结符：与输入匹配，出栈并前进指针
  2. 栈顶是非终结符 A，当前输入为 a：查表 M[A, a]，用产生式右部替换 A（逆序入栈）
- 成功条件：栈 = # 且 输入 = #

**LL(1) 的含义**：
- L（Left to right）：从左到右扫描输入
- L（Leftmost derivation）：产生最左推导
- 1：向前查看 1 个输入符号即可确定动作

### 题目 7：LR 分析法与移进-归约分析

**题目**：给定文法 G:
```
(0) S' → S
(1) S → S + T
(2) S → T
(3) T → T * F
(4) T → F
(5) F → (S)
(6) F → i
```
(1) 构造该文法的 LR(0) 项目集规范族
(2) 构造 SLR(1) 分析表
(3) 使用分析表分析句子 "i + i * i" 的分析过程

**标准答案**：

**(1) 构造 LR(0) 项目集规范族**

**项目（Item）**：在产生式右部的某个位置放置一个圆点，表示已分析部分和待分析部分的分界。

**闭包（Closure）**：如果 I 是项目集，A → α·Bβ ∈ I，则将所有 B 的产生式 B → ·γ 添加到 I，重复直到 I 不再变化。

**转换函数 GO(I, X)**：GO(I, X) = Closure({A → αX·β | A → α·Xβ ∈ I})

**项目集规范族**（关键部分）：

**I₀ = Closure({S' → ·S})**
```
S' → ·S
S → ·S+T
S → ·T
T → ·T*F
T → ·F
F → ·(S)
F → ·i
```

**I₁ = GO(I₀, S) = Closure({S' → S·, S → S·+T})**
```
S' → S·          （接受项目）
S → S·+T
```

**I₂ = GO(I₀, T) = Closure({S → T·, T → T·*F})**
```
S → T·
T → T·*F
```

**I₃ = GO(I₀, F) = Closure({T → F·})**
```
T → F·
```

**I₄ = GO(I₀, '(') = Closure({F → (·S)})**
```
F → (·S)
S → ·S+T
S → ·T
T → ·T*F
T → ·F
F → ·(S)
F → ·i
```

**I₅ = GO(I₀, i) = Closure({F → i·})**
```
F → i·
```

**I₆ = GO(I₁, '+') = Closure({S → S+·T})**
```
S → S+·T
T → ·T*F
T → ·F
F → ·(S)
F → ·i
```

**I₇ = GO(I₂, '*') = Closure({T → T*·F})**
```
T → T*·F
F → ·(S)
F → ·i
```

**I₈ = GO(I₄, S) = Closure({F → (S·), S → S·+T})**
```
F → (S·)
S → S·+T
```

**I₉ = GO(I₆, T) = Closure({S → S+T·, T → T·*F})**
```
S → S+T·
T → T·*F
```

**I₁₀ = GO(I₇, F) = Closure({T → T*F·})**
```
T → T*F·
```

**I₁₁ = GO(I₈, ')') = Closure({F → (S)·})**
```
F → (S)·
```

GO(I₄, T) = I₂, GO(I₄, F) = I₃, GO(I₄, '(') = I₄, GO(I₄, i) = I₅
GO(I₆, F) = I₃, GO(I₆, '(') = I₄, GO(I₆, i) = I₅
GO(I₇, '(') = I₄, GO(I₇, i) = I₅
GO(I₈, '+') = I₆
GO(I₉, '*') = I₇

**(2) 构造 SLR(1) 分析表**

**FOLLOW 集**：
- FOLLOW(S') = {#}
- FOLLOW(S) = {+, ), #}
- FOLLOW(T) = {+, *, ), #}
- FOLLOW(F) = {+, *, ), #}

**SLR(1) 分析表构造规则**：
1. 若 A → α·aβ ∈ Iₖ 且 GO(Iₖ, a) = Iⱼ，则 ACTION[k, a] = sⱼ（移进 j）
2. 若 A → α· ∈ Iₖ，则对 ∀a ∈ FOLLOW(A)，ACTION[k, a] = rⱼ（用第 j 条产生式归约）
3. 若 S' → S· ∈ Iₖ，则 ACTION[k, #] = acc（接受）
4. GOTO[k, A] = j（若 GO(Iₖ, A) = Iⱼ）

**ACTION 表**：

|------|---|---|---|---|---|---|
| 0 | s5 | | | s4 | | |
| 1 | | s6 | | | | acc |
| 2 | | r2 | s7 | | r2 | r2 |
| 3 | | r4 | r4 | | r4 | r4 |
| 4 | s5 | | | s4 | | |
| 5 | | r6 | r6 | | r6 | r6 |
| 6 | s5 | | | s4 | | |
| 7 | s5 | | | s4 | | |
| 8 | | s6 | | | s11 | |

| 11 | | r5 | r5 | | r5 | r5 |

**GOTO 表**（非终结符转移）：

| 状态 | S | T | F |
|------|---|---|---|

| 4 | 8 | 2 | 3 |
| 6 | | 9 | 3 |
| 7 | | | 10 |

**(3) 分析句子 "i + i * i"**

分析步骤（仅状态栈 + 动作）：

| 步骤 | 状态栈 | 输入 | 动作 |
|------|--------|------|------|
| 0 | 0 | i+i*i# | 初始 |
| 1 | 0,5 | +i*i# | ACTION[0,i] = s5（移进 i） |
| 2 | 0,3 | +i*i# | ACTION[5,+] = r6（F→i 归约） → GOTO[0,F] = 3 |
| 3 | 0,2 | +i*i# | ACTION[3,+] = r4（T→F 归约） → GOTO[0,T] = 2 |
| 4 | 0,1 | +i*i# | ACTION[2,+] = r2（S→T 归约） → GOTO[0,S] = 1 |
| 5 | 0,1,6 | i*i# | ACTION[1,+] = s6（移进 +） |
| 6 | 0,1,6,5 | *i# | ACTION[6,i] = s5（移进 i） |
| 7 | 0,1,6,3 | *i# | ACTION[5,*] = r6（F→i 归约） → GOTO[6,F] = 3 |
| 8 | 0,1,6,9 | *i# | ACTION[3,*] = r4（T→F 归约） → GOTO[6,T] = 9 |
| 9 | 0,1,6,9,7 | i# | ACTION[9,*] = s7（移进 *） |
| 10 | 0,1,6,9,7,5 | # | ACTION[7,i] = s5（移进 i） |
| 11 | 0,1,6,9,7,10 | # | ACTION[5,#] = r6（F→i 归约） → GOTO[7,F] = 10 |
| 12 | 0,1,6,9 | # | ACTION[10,#] = r3（T→T*F 归约） → GOTO[6,T] = 9 |
| 13 | 0,1 | # | ACTION[9,#] = r1（S→S+T 归约） → GOTO[0,S] = 1 |
| 14 | 0,1 | # | ACTION[1,#] = acc（接受） ✓ |

**分析成功**！

**解析**：

**LR 分析法的优势**：
1. **适用范围广**：比 LL(1) 能处理更多文法（包括左递归文法）
2. **分析效率高**：线性时间 O(n)
3. **查错能力强**：能准确指出错误位置
4. **自动构造工具**：YACC/Bison 等工具可自动生成 LR 分析器

**各种 LR 分析方法的比较**：

| 方法 | 能力 | 分析表大小 | 特点 |
|------|------|-----------|------|
| LR(0) | 最弱 | 小 | 只看圆点位置，不看 FOLLOW |
| SLR(1) | 较强 | 中等 | 使用 FOLLOW 集处理归约-归约冲突 |
| LR(1) | 最强 | 大 | 每个项目带向前看符号 |
| LALR(1) | 较强 | 中等 | 合并 LR(1) 的同心项目集，YACC/Bison 使用 |

### 题目 8：属性文法与语法制导翻译

**题目**：给定简单表达式文法：
```
E → E₁ + T    { E.val = E₁.val + T.val }
E → T          { E.val = T.val }
T → T₁ * F    { T.val = T₁.val * F.val }
T → F          { T.val = F.val }
F → (E)        { F.val = E.val }
F → digit      { F.val = digit 的值 }
```
(1) 说明上述语义规则定义的是综合属性还是继承属性
(2) 给出表达式 "3 + 4 * 5" 的带注释的语法分析树
(3) 扩展该文法以生成三地址码

**标准答案**：

**(1) 属性类型判定**

**综合属性**：属性值由子节点的属性值计算得到（自下而上传递信息）

**继承属性**：属性值由兄弟节点和父节点的属性值计算得到（自上而下传递信息）

**判定**：本题中 E.val 由 E₁.val 和 T.val 计算，T.val 由 T₁.val 和 F.val 计算，F.val 由 E.val 或 digit 的值计算。所有属性都依赖于**子节点**的属性。

**结论**：所有属性都是**综合属性**，这是一个 **S-属性文法**。

**(2) 表达式 "3 + 4 * 5" 的带注释语法树**

```
                  E .val = 23
              /   │   \
             E    +    T .val = 20
          .val=3    / │  \
             │     T  *   F .val=5
             │  .val=4     │
             T     F       5
          .val=3 .val=4
             │     │
             F     F
          .val=3 .val=4
             │     │
             3     4
```

计算过程（自下而上）：
1. F → 3: F.val = 3
2. T → F: T.val = 3
3. E → T: E.val = 3
4. F → 4: F.val = 4
5. T → F: T.val = 4
6. F → 5: F.val = 5
7. T → T*F: T.val = 4 × 5 = 20
8. E → E+T: E.val = 3 + 20 = 23

**最终结果**：E.val = 23

**(3) 扩展为生成三地址码**

添加属性：
- **.place**：保存表达式值的地址（变量名或临时变量名）
- **.code**：生成的三地址码序列
- **newtemp()**：生成新的临时变量 t₁, t₂, ...

| 产生式 | 语义规则 |
|--------|---------|
| E → E₁ + T | E.place = newtemp()<br>E.code = E₁.code ‖ T.code ‖ (E.place = E₁.place + T.place) |
| E → T | E.place = T.place<br>E.code = T.code |
| T → T₁ * F | T.place = newtemp()<br>T.code = T₁.code ‖ F.code ‖ (T.place = T₁.place * F.place) |
| T → F | T.place = F.place<br>T.code = F.code |
| F → (E) | F.place = E.place<br>F.code = E.code |
| F → digit | F.place = digit.lexval<br>F.code = ""（空序列） |

**表达式 "3 + 4 * 5" 的三地址码**：
```
t₁ = 4 * 5
t₂ = 3 + t₁
```

### 题目 10：基本块划分与代码优化

**题目**：给定以下三地址码序列：
```
(1) i = 1
(2) if i > 10 goto (15)
(3) t1 = 2 * i
(4) t2 = a[t1]
(5) t3 = 2 * i
(6) t4 = b[t3]
(7) t5 = t2 + t4
(8) sum = sum + t5
(9) i = i + 1
(10) if i <= 10 goto (3)
(11) t6 = avg * 10
(12) t7 = sum / 10
(13) avg = t7
(14) goto (16)
(15) sum = 0
(16) ...
```
(1) 划分基本块
(2) 指出可以进行哪些局部优化

**标准答案**：

**基本块（Basic Block）**：程序中一段顺序执行的语句序列，只有一个入口和一个出口。

**基本块划分算法**：
1. **确定首指令（Leader）**：
   - 程序第一条语句
   - 条件/无条件转移的目标语句
   - 紧跟在条件/无条件转移之后的语句
2. **构建基本块**：每个基本块由一个首指令开始，包含直到下一个首指令之前的所有语句

**(1) 划分基本块**

**首指令**：(1), (3), (11), (15), (16)

**基本块**：

**B1**：(1)(2)
```
(1) i = 1
(2) if i > 10 goto (15)
```

**B2**：(3)-(10)（循环体）
```
(3) t1 = 2 * i
(4) t2 = a[t1]
(5) t3 = 2 * i
(6) t4 = b[t3]
(7) t5 = t2 + t4
(8) sum = sum + t5
(9) i = i + 1
(10) if i <= 10 goto (3)
```

**B3**：(11)-(14)
```
(11) t6 = avg * 10
(12) t7 = sum / 10
(13) avg = t7
(14) goto (16)
```

**B4**：(15)
```
(15) sum = 0
```

**B5**：(16)（后续代码）

**(2) 可以进行的局部优化**

| 优化类型 | 发现 | 优化说明 |
|---------|------|---------|
| **公共子表达式消除** | B2 中 `t1 = 2*i` 和 `t3 = 2*i` 计算相同值 | 只计算一次，后续复用 t1 |
| **死代码消除** | B3 中 `t6 = avg * 10`，t6 未被后续使用 | 可删除 t6 的赋值语句 |
| **强度削弱** | B2 中 `2*i` 每次循环可改为 `t += 2` | 将乘法变为加法，速度更快 |
| **复写传播** | `t5 = t2 + t4` 后 `sum = sum + t5` 可合并 | 简化为 `sum = sum + t2 + t4` |
| **循环不变量外提** | 如果循环中有值不变的表达式 | 移到循环外计算一次 |

**优化后 B2（简化）**：
```
(3) t = 2 * i              // 循环入口时计算一次
(4) t2 = a[t]
(6) t4 = b[t]              // 复用 t，消除 t3
(8) sum = sum + t2 + t4    // 消除 t5
(9) i = i + 1
(+) t = t + 2              // 强度削弱：2*i 改为增量
(10) if i <= 10 goto (3)
```

**解析**：

**常见代码优化技术**：
1. **局部优化**（基本块内）：公共子表达式消除、死代码消除、常量折叠、复写传播
2. **循环优化**（跨基本块）：代码外提、强度削弱、删除归纳变量、循环展开
3. **全局优化**：基于数据流分析的全局公共子表达式消除、全局复写传播

### 题目 11：符号表

**题目**：什么是符号表？符号表需要记录哪些信息？简述符号表的组织方式和查找方法。

**标准答案**：

**符号表（Symbol Table）**：是编译程序中用于记录源程序中各个标识符的有关信息的数据结构。它在编译的各个阶段都要被频繁地访问和更新，是编译程序中最重要的数据结构之一。

**符号表需要记录的信息**：

| 信息项 | 说明 | 示例 |
|--------|------|------|
| **名字（Name）** | 标识符的字符串 | "count", "x" |
| **类型（Type）** | 标识符的类型 | int, real, char, 数组, 指针, 函数 |
| **种类（Kind）** | 标识符的种类 | 变量名、常量名、过程名、函数名、类名 |
| **作用域（Scope）** | 标识符有效范围 | 全局、局部（哪个函数/块中） |
| **存储类别（Storage）** | 存储方式 | static, auto, register, extern |
| **地址（Address）** | 相对/绝对地址 | 栈偏移量、数据段地址 |
| **大小（Size）** | 占用的存储空间（字节数） | int 占 4 字节 |
| **其他属性** | 根据语言需要的其他属性 | 维数（数组）、参数个数（函数）、访问权限等 |

**符号表的组织方式**：

1. **线性表**：简单的数组或链表存储
   - 优点：实现简单
   - 缺点：查找速度慢（O(n)），适合小型程序

2. **有序表 + 二分查找**：按标识符名字排序
   - 优点：查找速度较快（O(log n)）
   - 缺点：插入操作较慢（需要移动元素）

3. **哈希表（Hash Table）**：最常用的方法
   - 优点：平均查找/插入速度快（O(1)）
   - 缺点：需要设计好的哈希函数，处理冲突

4. **二叉搜索树（BST）/ 平衡树（AVL, 红黑树）**：
   - 优点：有序，查找、插入、删除速度均衡（O(log n)）
   - 缺点：实现较复杂

**作用域的处理**：

符号表需要支持嵌套作用域，通常采用**栈式结构**或**层次表**：

```
全局作用域 ──→ 函数作用域 ──→ 块作用域
{count, x}    {y, z}         {temp}
```

当进入一个新作用域时：在符号表中添加新的一层
当退出一个作用域时：删除该层的所有符号

**查找策略**（最近嵌套原则）：
从最内层作用域开始查找，找到即返回；找不到则向外层继续查找。

## 六、运行时存储组织与错误处理

### 题目 12：活动记录与栈式存储分配

**题目**：简述过程（函数）调用时活动记录的结构和主要内容。说明递归过程如何通过栈式存储实现。

**标准答案**：

**活动记录（Activation Record）**：当一个过程（函数）被调用时，用于存放该过程的局部数据和相关信息的连续存储块。过程每次执行（激活）都会产生一个新的活动记录。

**活动记录的典型结构**：

```
   高地址（栈底方向）
   ┌────────────────────────────────────┐
   │  临时变量区（Temp Variables）      │ ← 表达式计算的临时变量
   ├────────────────────────────────────┤
   │  局部数据区（Local Data）          │ ← 过程内声明的局部变量
   ├────────────────────────────────────┤
   │  机器状态区（Machine Status）      │ ← 寄存器值、PC 等（调用前保存）
   ├────────────────────────────────────┤
   │  访问链（Access Link）             │ ← 指向静态外层活动记录（嵌套过程用）
   ├────────────────────────────────────┤
   │  控制链（Control Link）            │ ← 指向调用者的活动记录（动态外层）
   ├────────────────────────────────────┤
   │  返回值区（Return Value）          │ ← 函数返回值（若有）
   ├────────────────────────────────────┤
   │  实参区（Actual Parameters）       │ ← 调用者传递的实参
   ├────────────────────────────────────┤
   │  返回地址（Return Address）         │ ← 调用结束后返回的指令地址
   └────────────────────────────────────┘
   低地址（栈顶方向，SP 指向） ← 栈指针 SP
```

**运行时栈的结构**：

```
       主程序调用 P，P 调用 Q，Q 递归调用 Q

        ┌──────────────┐
        │  主程序AR     │
        ├──────────────┤
        │  P的活动记录  │ ← P 被主程序调用
        ├──────────────┤
        │  Q的活动记录  │ ← Q 被 P 调用
        ├──────────────┤
 SP →  │  Q的活动记录  │ ← Q 递归调用自己（新实例）
        └──────────────┘
```

**递归过程的实现原理**：

以阶乘函数 `factorial(n)` 为例：
```c
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

调用 `factorial(3)` 的执行过程：

1. **调用 factorial(3)**
   - 建立活动记录 AR1（参数 n=3）
   - 判断 n>1，需要计算 3 × factorial(2)

2. **调用 factorial(2)**
   - 建立活动记录 AR2（参数 n=2）
   - 判断 n>1，需要计算 2 × factorial(1)

3. **调用 factorial(1)**
   - 建立活动记录 AR3（参数 n=1）
   - 判断 n≤1，返回 1

4. **返回并撤销 AR3**
   - AR2 使用返回值 1，计算 2 × 1 = 2，返回 2

5. **返回并撤销 AR2**
   - AR1 使用返回值 2，计算 3 × 2 = 6，返回 6

6. **返回并撤销 AR1**
   - 整个调用结束，结果 6 返回给调用者

**栈状态示意**：
```
调用 factorial(3)    调用 factorial(2)    调用 factorial(1)    开始返回

    ┌──────┐            ┌──────┐            ┌──────┐            ┌──────┐
    │main  │            │main  │            │main  │            │main  │
    ├──────┤            ├──────┤            ├──────┤            ├──────┤
    │f(3)  │ ←SP        │f(3)  │            │f(3)  │            │f(3)  │←返回6
    └──────┘            ├──────┤            ├──────┤            └──────┘
                        │f(2)  │ ←SP        │f(2)  │ ←结果2      (空)
                        └──────┘            ├──────┤
                                              │f(1)  │ ←SP
                                              └──────┘ ←结果1
```

**关键要点**：
- 每次调用都建立**新的活动记录**（即使是同一个函数递归调用自己）
- 活动记录包含本次调用的**局部数据和参数**（各次调用互不干扰）
- 通过**控制链**形成调用关系链（谁调用谁）
- 调用结束后活动记录被撤销（出栈）
- 栈式分配天然支持递归调用

**存储分配策略比较**：

| 策略 | 适用场景 | 分配时机 | 回收时机 | 支持递归 |
|------|---------|---------|---------|---------|
| **静态分配** | 静态变量、全局变量 | 编译时确定 | 程序结束 | 否 |
| **栈式分配** | 局部变量、函数调用 | 过程调用时 | 过程返回时 | 是 |
| **堆式分配** | 动态数据结构、动态对象 | 显式分配（new/malloc） | 显式释放（delete/free）或 GC | 是 |

### 题目 13：编译错误处理

**题目**：编译程序中可能出现哪些类型的错误？简述各类错误的检测时机和处理策略。

**标准答案**：

**编译错误分类**：

| 错误类型 | 发生阶段 | 说明 | 示例 |
|---------|---------|------|------|
| **词法错误** | 词法分析阶段 | 字符流中出现不符合单词构成规则的字符或序列 | 非法字符 `@`、`$`；不封闭的引号 |
| **语法错误** | 语法分析阶段 | 单词序列不符合语法规则（语法结构错误） | 缺少分号、括号不匹配、关键字拼写错误 |
| **语义错误** | 语义分析阶段 | 程序在语法上正确，但在意义上有错误 | 类型不匹配、未声明变量、函数参数不匹配 |
| **逻辑错误** | （通常运行时发现） | 算法设计错误，程序可以运行但结果不正确 | 循环条件写错、计算公式错误 |
| **警告（Warning）** | 各阶段 | 非致命错误，可能存在问题但可以继续编译 | 变量未使用、有符号与无符号比较 |

**错误检测时机和处理策略**：

**1. 词法错误**
- **检测时机**：词法分析器扫描字符流时
- **检测方法**：当前缀无法匹配任何单词模式时
- **处理策略**：
  - 跳过错误字符，报告错误位置和信息
  - 继续扫描，避免因为一个错误中断整个编译
  - 例：遇到非法字符 `@`，跳过该字符并报告

**2. 语法错误**
- **检测时机**：语法分析器分析单词序列时
- **检测方法**：分析表中没有对应条目，或无法按语法规则继续分析
- **处理策略（错误恢复）**：
  - **紧急恢复（Panic Mode）**：跳过输入符号直到遇到同步符号（如分号、关键字），从该点继续分析
  - **短语级恢复**：在出错位置插入或删除一些符号，使分析可以继续
  - **错误产生式**：预先设计一些错误处理的产生式，匹配常见错误模式
  - **全局纠正**：尝试最小修改代价使输入串变为合法（代价高，较少用）

**3. 语义错误**
- **检测时机**：语义分析阶段，通常伴随语法分析进行
- **检测方法**：类型检查时发现类型不兼容、符号表中找不到标识符等
- **处理策略**：
  - 报告错误位置和详细错误信息
  - 为错误符号假设一个合理类型（如 error 类型），使后续分析可以继续
  - 同一错误避免重复报告

**4. 警告（Warning）**
- **处理策略**：报告但不终止编译，提醒程序员注意潜在问题
- 部分编译器提供选项控制警告级别

**错误报告的要素**：
- **位置信息**：源文件行号、列号（精确指出错误位置）
- **错误类型**：词法/语法/语义错误
- **错误描述**：清晰描述问题
- **上下文信息**：周围的代码片段（有助于理解）

**示例错误报告**：
```
Error at line 15, column 8: syntax error
       int x = ;            // 赋值符号后缺少表达式
           ^
Warning: variable 'temp' declared but never used (line 20)
Error at line 25: type mismatch: cannot assign 'string' to 'int'
       x = "hello";
           ~~~~~~~
```
