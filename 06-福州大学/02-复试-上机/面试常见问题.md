### 1. 数据结构与算法

**1. 什么是时间复杂度和空间复杂度？请举例说明O(1), O(n), O(logn), O(nlogn), O(n²)。**

时间复杂度描述算法运行时间随输入规模增长的变化趋势，空间复杂度描述算法所需内存空间的增长趋势。

- **O(1)**：访问数组元素 `arr[i]`，哈希表查找
- **O(logn)**：二分查找、平衡二叉搜索树操作、堆的上浮/下沉
- **O(n)**：线性查找、单层循环遍历
- **O(nlogn)**：快速排序平均情况、归并排序、堆排序
- **O(n²)**：冒泡排序、选择排序、插入排序

**出处**：福大2023年复试面试题

**2. 请比较快速排序、归并排序、堆排序的优缺点和适用场景。**

| 排序算法 | 时间复杂度 | 空间复杂度 | 稳定性 | 特点 |
|---------|-----------|-----------|--------|------|
| 快速排序 | 平均O(nlogn)，最坏O(n²) | O(logn)递归栈 | 不稳定 | 原地排序，常数因子小，实际最快 |
| 归并排序 | 稳定O(nlogn) | O(n) | 稳定 | 稳定排序，适合链表，外部排序 |
| 堆排序 | 稳定O(nlogn) | O(1) | 不稳定 | 最坏情况仍O(nlogn)，适合Top-K问题 |

**适用场景**：
- 快排：一般情况首选，数据量大时效率最高
- 归并：需要稳定性、数据存储在磁盘（外部排序）
- 堆排：内存极度受限、Top-K问题、优先队列

**3. 什么是哈希表？如何解决哈希冲突？**

哈希表通过哈希函数将关键字映射到数组索引，实现O(1)平均查找时间。

**解决哈希冲突的方法**：

1. **链地址法（拉链法）**：每个槽位维护一个链表，冲突元素挂在同一链表上
   - 优点：简单，不会产生二次冲突
   - 缺点：需要额外空间存储链表指针
   - 应用：Java HashMap、C++ unordered_map

2. **开放地址法**：在哈希表本身寻找下一个空槽
   - **线性探测**：依次检查下一个位置，容易产生聚类
   - **二次探测**：`h(key) + i²`，减少聚类
   - **双重哈希**：使用第二个哈希函数确定步长

3. **再哈希法**：准备多个哈希函数，冲突时换一个哈希函数

**出处**：福大2022年复试面试题

**4. 请说明二叉搜索树、AVL树、红黑树的区别。**

- **二叉搜索树(BST)**：左子树所有节点值 < 根节点值 < 右子树所有节点值。最坏情况退化为链表O(n)。

- **AVL树**：严格平衡的BST，任意节点左右子树高度差不超过1。
  - 插入/删除后通过旋转（LL/RR/LR/RL）维护平衡
  - 查找效率高O(logn)
  - 缺点：插入删除频繁时旋转开销大

- **红黑树**：近似平衡的BST，通过颜色约束保证最长路径不超过最短路径的2倍。
  - 规则：根黑、红节点子节点必黑、任一节点到叶节点黑节点数相同
  - 查找O(logn)，插入删除通过变色+旋转维护
  - 比AVL树旋转更少，插入删除性能更好

**应用**：C++ std::map/multimap（红黑树），Linux进程调度CFS（红黑树）

**出处**：福大2024年复试面试题

**5. 图的两种存储方式及其适用场景？**

1. **邻接矩阵**：二维数组 `adj[i][j]` 表示顶点i到j是否有边/权重
   - 空间：O(V²)
   - 检查边是否存在：O(1)
   - 遍历所有边：O(V²)
   - 适用：稠密图（边数接近V²）

2. **邻接表**：每个顶点维护一个链表/数组存储邻接顶点
   - 空间：O(V + E)
   - 检查边是否存在：O(degree(v))
   - 遍历所有边：O(V + E)
   - 适用：稀疏图（大多数实际场景）

**扩展**：还有邻接多重表（无向图节省空间）、十字链表（有向图）

**出处**：福大2023年复试面试题

**6. Dijkstra算法和Floyd算法分别解决什么问题？有什么区别？**

- **Dijkstra算法**：单源最短路径，要求边权重非负
  - 基于贪心策略，每次选距离源点最近的未访问顶点
  - 普通实现：O(V²)；堆优化：O(ElogV)
  - 不能处理负权边

- **Bellman-Ford算法**：单源最短路径，可以处理负权边
  - 检测负环：第V轮仍能松弛则存在负环
  - 时间复杂度：O(VE)

- **Floyd算法**：多源最短路径（任意两点间最短路径）
  - 基于动态规划：`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`
  - 时间复杂度：O(V³)，空间O(V²)
  - 可以处理负权边（但不能有负环）

- **SPFA算法**：Bellman-Ford的队列优化版本，实际效果好

**出处**：福大2024年复试面试题

**7. 什么是动态规划？请举例说明并描述三要素。**

动态规划（DP）是通过把原问题分解为相对简单的子问题的方式求解复杂问题的方法。

**三要素**：
1. **定义状态**：明确 `dp[i]` 或 `dp[i][j]` 表示什么含义
2. **状态转移方程**：如何从之前的状态推导出当前状态
3. **初始化和边界条件**：确定初始状态值

**经典例子**：最长递增子序列(LIS)
- 状态：`dp[i]` = 以第i个元素结尾的LIS长度
- 转移：`dp[i] = max(dp[j] + 1)` for all j < i and nums[j] < nums[i]
- 初始化：`dp[i] = 1`

**其他经典问题**：背包问题、最长公共子序列(LCS)、编辑距离、打家劫舍

**出处**：福大2024年复试面试题

**8. 什么是栈和队列？请分别给出两个应用实例。**

**栈（Stack）**：后进先出(LIFO)的线性结构
- 应用1：表达式求值与括号匹配（中缀转后缀、逆波兰式）
- 应用2：函数调用栈（保存返回地址和局部变量）
- 应用3：深度优先搜索(DFS)
- 应用4：撤销操作(Undo)

**队列（Queue）**：先进先出(FIFO)的线性结构
- 应用1：广度优先搜索(BFS)
- 应用2：任务调度（如操作系统进程调度）
- 应用3：缓冲区（如生产者-消费者模型）

**扩展**：
- **双端队列(deque)**：两端均可插入删除
- **优先队列(priority_queue)**：按优先级出队，底层堆实现

**9. 什么是KMP算法？相比朴素匹配有什么优势？**

**朴素匹配**：每次失配后，模式串只向后移动一位，主串指针回溯。
- 时间复杂度：最坏O(n*m)

**KMP算法**：通过预处理模式串生成next数组（失败函数），记录模式串中每个位置的最长相等前缀后缀长度。失配时模式串可以跳过已知匹配的部分，主串指针永不回溯。

```
next数组含义：next[i] = 模式串前i+1个字符中最长相等真前缀和真后缀的长度
```

- 预处理next数组：O(m)
- 匹配过程：O(n)
- 总时间复杂度：O(n + m)

**适用场景**：文本编辑器查找、DNA序列匹配、搜索引擎

**出处**：福大2024年复试面试题

**10. 什么是B树和B+树？为什么MySQL索引使用B+树？**

**B树**：多路平衡搜索树，每个节点可存储多个关键字和子节点指针。
- 降低树高，减少磁盘I/O次数
- 每个节点存储：(关键字，数据记录/指针)

**B+树**：B树的变体
- 非叶子节点只存索引（关键字+子节点指针），不存数据
- 叶子节点存储所有关键字+数据，并通过链表连接
- 叶子节点有序，方便范围查询

**为什么MySQL用B+树不用B树/红黑树**：
1. **更低的树高**：1000阶B+树，百万级数据只需2-3层
2. **磁盘友好**：每个节点大小=磁盘页(4K/8K/16K)，每次I/O读一个节点
3. **范围查询高效**：叶子节点链表连接，区间查询只需遍历叶子
4. **查询更稳定**：每次查询都走到叶子节点

**出处**：福大2024年复试面试题

### 2. 操作系统

**11. 进程和线程有什么区别？**

| 对比项 | 进程 | 线程 |
|-------|------|------|
| 定义 | 资源分配的最小单位 | CPU调度的最小单位 |
| 资源 | 拥有独立的内存空间和系统资源 | 共享所属进程的资源 |
| 切换开销 | 大（切换页表和内核栈） | 小（只需切换寄存器和栈） |
| 通信方式 | 管道、消息队列、共享内存、信号量、Socket | 共享内存（需同步） |
| 健壮性 | 进程间相互独立，一个崩溃不影响其他 | 同一进程内线程共享资源，一个崩溃导致整个进程崩溃 |
| 上下文切换 | 需要切换页目录和内核栈 | 只需保存和恢复寄存器 |

**进程 = 资源分配单位，线程 = 执行单位。一个进程至少有一个线程。**

**12. 什么是死锁？死锁产生的四个必要条件是什么？如何避免和解决死锁？**

**死锁定义**：多个进程因循环等待对方占有的资源而永久阻塞的状态。

**四个必要条件（Coffman条件）**：
1. **互斥(Mutual Exclusion)**：资源只能被一个进程使用
2. **请求与保持(Hold and Wait)**：进程持有资源同时请求新资源
3. **不可剥夺(No Preemption)**：资源不能被强行剥夺，只能自愿释放
4. **循环等待(Circular Wait)**：形成资源请求循环链

**解决策略**：

1. **死锁预防**：破坏必要条件之一
   - 破坏请求与保持：一次性请求所有资源
   - 破坏不可剥夺：请求失败时释放已占有资源
   - 破坏循环等待：资源按序号顺序申请

2. **死锁避免**：银行家算法，动态检查是否处于安全状态

3. **死锁检测与解除**：允许死锁发生，检测后解除
   - 检测：资源分配图检测环路
   - 解除：撤销进程（按优先级/代价）或剥夺资源

4. **忽略**：鸵鸟算法（大多数系统如Linux采用）

**出处**：福大2024年复试面试题

**13. 什么是虚拟内存？有什么作用？**

**虚拟内存**：将内存抽象为一个比实际物理内存大得多的地址空间，每个进程拥有独立的虚拟地址空间。通过硬件MMU（内存管理单元）将虚拟地址翻译为物理地址。

**核心机制**：
- **分页(Paging)**：虚拟内存和物理内存划分为固定大小的页（通常4KB）
- **请求调页(Demand Paging)**：只在需要时才将页面载入内存
- **页面置换(Page Replacement)**：内存不足时选择牺牲页换出到磁盘

**页面置换算法**：FIFO、LRU（最近最少使用）、OPT（最优置换）、Clock算法

**作用**：
1. **扩大内存容量**：可以运行大于物理内存的程序
2. **进程隔离**：每个进程独立地址空间，互不干扰
3. **简化编程**：程序员无需关心物理内存布局
4. **提高内存利用率**：只加载需要的页面
5. **共享机制**：通过页表映射实现共享库

**出处**：福大2023年复试面试题

**14. 进程调度算法有哪些？各有什么特点？**

1. **先来先服务(FCFS)**：按到达顺序调度
   - 优点：简单公平；缺点：平均等待时间长，短作业可能长时间等待

2. **短作业优先(SJF)**：选择估计运行时间最短的作业
   - 理论最优平均等待时间；但需要预知运行时间，可能导致饥饿

3. **最短剩余时间优先(SRTF)**：SJF的抢占式版本
   - 新短作业到来时可能抢占当前进程

4. **时间片轮转(RR)**：每个进程分配一个时间片，用完则切换
   - 公平，响应快；时间片太小则切换开销大，太大则退化为FCFS

5. **优先级调度**：按优先级调度
   - 非抢占式/抢占式；可能导致低优先级饥饿；解决：老化(aging)

6. **多级反馈队列(MLFQ)**：多个队列，不同优先级和时间片
   - 新进程入最高优先级队列；用完时间片则降级；I/O密集型保持高优先级
   - 综合RR和优先级，兼顾响应时间和吞吐量

7. **CFS（Linux完全公平调度器）**：红黑树实现，按虚拟运行时间调度
   - 每个进程按权重分配CPU时间

**出处**：福大2024年复试面试题

**15. 什么是文件系统？文件的物理结构有哪些？**

**文件系统**：操作系统中负责管理和存储文件信息的软件机构。常见：ext4, NTFS, FAT32, xfs, btrfs。

**文件的物理结构（文件在磁盘上的存储方式）**：

1. **顺序（连续）分配**：文件数据存在连续磁盘块中
   - 优点：顺序访问速度快，实现简单
   - 缺点：外部碎片，文件增长困难

2. **链接分配**：每个文件是磁盘块链表，每个块存数据+下一块指针
   - 优点：无碎片，文件动态增长容易
   - 缺点：随机访问慢，指针占用空间
   - **FAT（文件分配表）**：显式链接，FAT表集中存储指针，解决随机访问问题

3. **索引分配**：为每个文件分配索引块，索引块存储数据块指针数组
   - 优点：支持直接访问，无外部碎片
   - 缺点：索引块开销
   - **多级索引**：索引块太大时引入一级/二级/三级间接索引（UFS/ext4采用）
   - **混合索引**：直接块+一级间接+二级间接+三级间接（经典inode结构）

4. **ext4的方式**：extent（区段）方式，记录连续块范围，比传统索引更高效

**出处**：福大2024年复试面试题

**16. 请说明程序的编译、链接、装载过程。**

**编译过程**（C语言为例）：
```
源代码(.c) → 预处理(.i) → 编译(.s汇编) → 汇编(.o目标文件) → 链接 → 可执行文件
```
1. **预处理**：处理#include、#define、#ifdef，删除注释，生成.i文件
2. **编译**：将C代码翻译成汇编代码，生成.s文件
3. **汇编**：将汇编代码翻译成机器指令，生成.o目标文件（ELF格式）
4. **链接**：将多个目标文件和库文件合并，解析外部引用，生成可执行文件

**链接的两种方式**：
- **静态链接**：链接时将库代码复制到可执行文件
  - 优点：不依赖库环境，运行时无需加载
  - 缺点：可执行文件大，更新库需要重新编译
- **动态链接**：运行时才加载共享库
  - 优点：可执行文件小，库可共享，更新方便
  - 缺点：运行时需要加载，存在版本依赖

**装载过程**：
- 操作系统读取可执行文件(ELF/PE)
- 创建虚拟地址空间，建立页表
- 将代码段和数据段映射到内存
- 将PC指向入口点（_start/main），开始执行

**17. 什么是中断？中断和异常有什么区别？**

**中断(Interrupt)**：由外部设备（如键盘、鼠标、磁盘、网卡）产生的异步事件，打断CPU当前执行。

**异常(Exception)**：由CPU内部产生的同步事件，如除零、缺页、非法指令。

**系统调用**：用户程序主动发起的请求，通过软中断(int 0x80/syscall指令)进入内核态。

**区别**：

| | 中断 | 异常 | 系统调用 |
|--|------|------|---------|
| 产生来源 | 外部硬件 | CPU内部指令执行 | 应用程序主动请求 |
| 同步/异步 | 异步（不可预测） | 同步（与指令执行相关） | 同步（主动触发） |
| 是否可屏蔽 | 大多可屏蔽 | 不可屏蔽 | 不可屏蔽 |
| 处理方式 | 中断服务例程(ISR) | 故障/陷阱/终止 | 内核态服务例程 |

**中断处理流程**：
1. 保存当前CPU上下文（PC、寄存器）
2. 根据中断号查中断向量表，跳转到中断服务例程
3. 执行中断服务例程
4. 恢复上下文，继续被中断的程序

**出处**：福大2024年复试面试题

**18. 什么是缓冲区溢出？如何防范？**

**缓冲区溢出**：向缓冲区写入超过其容量的数据，多余数据覆盖相邻内存，可能覆盖返回地址从而控制程序执行流。

**经典示例**：strcpy, gets, sprintf等不检查长度的C库函数

**防范措施**：

1. **使用安全函数**：用strncpy, snprintf, fgets代替gets等
2. **栈保护(Canary/Stack Smashing Protector)**：在栈中返回地址前放置特殊值，返回前检查是否被覆盖
3. **地址空间随机化(ASLR)**：程序加载地址随机，使shellcode难以定位
4. **数据执行保护(DEP/NX)**：栈和堆标记为不可执行

**19. 什么是IO多路复用？select/poll/epoll有什么区别？**

**IO多路复用**：单线程监听多个文件描述符，当某个描述符就绪时通知程序处理。实现高并发无需多线程。

**三种实现的比较**：

| 特性 | select | poll | epoll |
|------|--------|------|-------|
| 数据结构 | fd_set位图 | pollfd数组 | 红黑树+链表 |
| 最大连接数 | 通常1024(FD_SETSIZE) | 无限制 | 无限制 |

| 时间复杂度 | 每次调用O(n) | 每次调用O(n) | 注册O(1)，获取就绪O(1) |
| 适用场景 | 连接数少且都活跃 | 同select | 大量连接但只有少数活跃（高并发场景） |

**20. 请说明常见的进程间通信(IPC)方式。**

1. **管道(Pipe)**：半双工，单向通信，用于有亲缘关系的进程
   - 匿名管道：pipe()创建，fork后父子进程共享
   - 命名管道(FIFO)：mkfifo创建，可用于无亲缘关系进程

2. **消息队列(Message Queue)**：消息链表，有消息类型和优先级
   - 优点：消息可独立处理，不依赖读写顺序
   - 缺点：大小限制，消息需要复制两次

3. **共享内存(Shared Memory)**：多个进程映射同一块物理内存
   - 最快的IPC方式（无需内核介入数据传递）
   - 需要配合信号量/互斥锁进行同步

4. **信号量(Semaphore)**：用于进程/线程间同步和互斥
   - 二值信号量（互斥锁）、计数信号量
   - P/V操作（wait/signal）

5. **套接字(Socket)**：最通用的IPC，可跨主机通信
   - TCP(面向连接)、UDP(无连接)、Unix域套接字(本机高性能)

6. **信号(Signal)**：异步通知机制
   - 如SIGKILL(9), SIGTERM(15), SIGINT(2)

**选择建议**：
- 本机高性能：共享内存+信号量
- 跨主机：Socket
- 简单命令传递：管道/消息队列
- 异步事件：信号

### 3. 计算机网络

**21. TCP三次握手过程？为什么不是两次或四次？**

**三次握手（客户端主动打开，服务器被动打开）**：

```
Client                       Server
  │ SYN(seq=x)                 │
  │──────────────────────────▶│
  │                            │
  │ SYN+ACK(seq=y, ack=x+1)   │
  │◀──────────────────────────│
  │                            │
  │ ACK(seq=x+1, ack=y+1)     │
  │──────────────────────────▶│
  │                            │
  │ ESTABLISHED                │ ESTABLISHED
```

**为什么不是两次握手？**：
1. **无法确认客户端接收能力**：两次握手后服务器认为连接已建立，但客户端可能未收到SYN+ACK，或客户端已关闭。
2. **可能导致无效连接消耗资源**：历史滞留SYN报文可能导致服务器误开连接。
3. **无法防止重复连接**：旧SYN到达可能建立错误连接。

**为什么不是四次？**：
三次握手已经可以确认双方收发能力（Client确认Server收发，Server确认Client收发），四次冗余。

**注意**：SYN洪水攻击（SYN Flood）利用三次握手机制，发送大量伪造源IP的SYN包，服务器分配TCB等待ACK耗尽资源。防御：SYN Cookies。

**22. TCP四次挥手过程？为什么TIME_WAIT需要2MSL？**

**四次挥手**：
```
Client                       Server
  │ FIN(seq=u)                 │
  │──────────────────────────▶│ Client进入FIN_WAIT_1
  │                            │
  │ ACK(ack=u+1)               │
  │◀──────────────────────────│ Server进入CLOSE_WAIT，Client进入FIN_WAIT_2
  │                            │
  │ FIN(seq=v)                 │
  │◀──────────────────────────│ Server发送FIN
  │                            │
  │ ACK(ack=v+1)               │
  │──────────────────────────▶│ Client进入TIME_WAIT，Server关闭
  │                            │
  │ 2MSL后关闭                 │
```

**为什么需要TIME_WAIT（2MSL等待）？**：

1. **确保最后一个ACK能被对方收到**：如果服务器没收到最后的ACK，会重发FIN。如果客户端直接关闭，重发的FIN会收到RST，服务器报错。2MSL足够ACK到达或服务器重传FIN到达。

2. **让本次连接所有报文段从网络中消失**：防止新连接收到旧连接的延迟报文段（四元组复用）。

3. **保证连接可靠关闭**：给双方足够时间完成清理。

**MSL（Maximum Segment Lifetime）**：报文段最长生存时间，RFC建议2分钟，Linux通常30秒。

**相关问题**：CLOSE_WAIT过多（服务器未close），TIME_WAIT过多（短连接频繁关闭）。

**24. HTTP和HTTPS有什么区别？HTTPS的工作原理？**

**主要区别**：

| 特性 | HTTP | HTTPS |
|------|------|-------|
| 端口 | 80 | 443 |
| 加密 | 明文传输 | TLS/SSL加密 |
| 安全性 | 无 | 机密性、完整性、身份认证 |
| 证书 | 不需要 | 需要CA证书 |
| 性能 | 快 | 稍慢（加密解密开销） |
| URL前缀 | http:// | https:// |

**HTTPS = HTTP + TLS/SSL**

**TLS握手过程**（简化版TLS 1.2）：
1. **Client Hello**：客户端发送支持的加密套件、随机数
2. **Server Hello**：服务器选择加密套件，发送自己的随机数、证书
3. **客户端验证证书**：验证证书链完整性、域名、有效期
4. **客户端生成Pre-Master Secret**：用服务器公钥加密后发送
5. **双方计算会话密钥**：Client Random + Server Random + Pre-Master Secret = Master Secret → 导出会话密钥
6. **Finished消息**：双方用会话密钥加密握手消息交换，验证加密通道

**HTTPS提供的安全保障**：
- **机密性**：对称加密（AES）保护传输内容
- **完整性**：MAC/HMAC验证数据未篡改
- **身份认证**：证书+非对称加密(RSA/ECDSA)验证服务器身份
- **前向保密**：使用临时密钥交换(ECDHE/DHE)，长期密钥泄露不影响历史通信

**TLS 1.3改进**：一次RTT握手、0-RTT恢复、删除不安全算法。

**25. 什么是TCP拥塞控制？有哪些算法？**

**拥塞控制**：防止过多数据注入网络，避免网络中间节点过载。通过调节发送方发送速率实现。

**四个核心算法**（经典TCP Reno）：

1. **慢启动(Slow Start)**：cwnd(拥塞窗口)从1/MSS开始，每收到一个ACK加倍（指数增长）
   - 目的：快速探测网络容量
   - 直到cwnd达到ssthresh（慢启动阈值）

2. **拥塞避免(Congestion Avoidance)**：cwnd超过ssthresh后线性增长（每个RTT增加1个MSS）
   - 加法增大(AI)：谨慎增加窗口
   - 乘法减小(MD)：出现丢包时cwnd减半

3. **快重传(Fast Retransmit)**：收到3个重复ACK立即重传，不等超时
   - 快速响应丢包，减少等待时间

4. **快恢复(Fast Recovery)**：3个重复ACK后cwnd=ssthresh=cwnd/2，进入拥塞避免
   - 避免超时导致的cwnd骤降为1

**更先进的拥塞控制算法**：
- **Reno**：经典实现，对丢包敏感
- **NewReno**：改进Reno，处理部分ACK问题
- **CUBIC**：Linux默认，丢包后窗口恢复更快，适合高带宽延迟网络
- **BBR**：Google提出，基于模型测量带宽和RTT，不依赖丢包信号
- **Vegas**：基于RTT变化预测拥塞，在丢包前减速

### 4. 数据库

**27. 什么是事务？ACID四个特性是什么？**

**事务(Transaction)**：数据库执行的最小逻辑工作单元，其中的操作要么全部执行，要么全部不执行。

**ACID四大特性**：

1. **原子性(Atomicity)**：事务是不可分割的最小工作单元
   - 所有操作要么全部提交成功，要么全部失败回滚
   - 实现：undo log（回滚日志）记录修改前的数据

2. **一致性(Consistency)**：事务执行前后数据库保持一致状态
   - 约束（主键、外键、唯一约束）不被破坏
   - 业务规则（如转账后总额不变）保持

3. **隔离性(Isolation)**：多个事务并发执行时相互隔离
   - 防止事务间相互干扰
   - 通过锁机制和MVCC实现四种隔离级别

4. **持久性(Durability)**：事务提交后对数据库的修改永久保存
   - 即使系统崩溃也不丢失
   - 实现：redo log（重做日志）先写磁盘，保证崩溃恢复

**MySQL InnoDB对ACID的实现**：
- 原子性：undo log
- 持久性：redo log + force log at commit
- 隔离性：锁 + MVCC
- 一致性：事务机制 + 数据库约束

**28. 数据库的四种隔离级别？分别解决什么问题？**

**并发事务可能产生的问题**：
1. **脏读(Dirty Read)**：读取了其他事务未提交的数据
2. **不可重复读(Non-repeatable Read)**：同一事务内，两次读取同一数据结果不同（其他事务更新并提交）
3. **幻读(Phantom Read)**：同一事务内，两次查询同一范围，结果行数不同（其他事务插入/删除）

**四种隔离级别**（从低到高）：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 实现方式 |
|---------|------|-----------|------|---------|
| 读未提交(Read Uncommitted) | ✅有 | ✅有 | ✅有 | 基本无 |
| 读已提交(Read Committed) | ❌无 | ✅有 | ✅有 | 锁+MVCC，每次SELECT创建新ReadView |
| 可重复读(Repeatable Read) | ❌无 | ❌无 | ✅理论有/MySQL无 | MVCC，事务内使用同一ReadView |
| 可串行化(Serializable) | ❌无 | ❌无 | ❌无 | 全表锁/串行执行 |

**MySQL默认**：REPEATABLE READ，但通过Next-Key Lock解决了幻读问题。

**Oracle/PostgreSQL默认**：READ COMMITTED。

**29. 什么是索引？索引有哪些类型？B+树索引和哈希索引的区别？**

**索引**：数据库中用于加速查询的数据结构，类似于书的目录。通过索引可以快速定位数据位置，避免全表扫描。

**索引类型**：

1. **按数据结构分**：B+树索引、哈希索引、全文索引、R树（空间索引）
2. **按物理存储分**：聚簇索引（主键索引，数据和索引在一起）、非聚簇索引（二级索引）
3. **按列数分**：单列索引、复合索引（联合索引）
4. **按约束分**：主键索引、唯一索引、普通索引

**B+树索引 vs 哈希索引**：

| 特性 | B+树索引 | 哈希索引 |
|------|---------|---------|
| 数据结构 | B+树 | 哈希表 |
| 等值查询 | O(logn) | 平均O(1) |
| 范围查询 | 支持（叶子节点有序链表） | 不支持 |
| 排序ORDER BY | 支持 | 不支持 |
| 前缀匹配 | 支持 | 不支持（全值匹配） |
| 最左前缀原则 | 适用 | 不适用 |
| 冲突 | 无 | 哈希冲突 |
| MySQL默认 | InnoDB/MyISAM默认 | Memory引擎支持，InnoDB自适应哈希 |

**聚簇索引 vs 非聚簇索引**：
- **聚簇索引**：索引叶子节点就是完整数据行（InnoDB主键）。一张表只有一个聚簇索引。
- **非聚簇索引**：叶子节点存主键值，查询需要回表（先查二级索引得主键，再查聚簇索引得数据）。

**30. SQL语句SELECT的执行顺序？什么是内连接、左连接、右连接、全连接？**

**SELECT语句的逻辑执行顺序**（注意不是编写顺序）：

```
1. FROM / JOIN       → 确定数据源，笛卡尔积
2. ON                → 连接条件过滤
3. WHERE             → 行过滤（不能用聚合函数）
4. GROUP BY          → 分组
5. HAVING            → 分组后过滤（可用聚合函数）
6. SELECT            → 选择列，计算表达式
7. DISTINCT          → 去重
8. ORDER BY          → 排序
9. LIMIT / OFFSET    → 分页
```

编写顺序：`SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT`

**连接类型**：

假设有表A（学生）和表B（成绩）：

1. **内连接(INNER JOIN)**：只返回两表匹配的行
   - 结果 = A ∩ B
   - 不匹配的行被丢弃

2. **左连接(LEFT JOIN)**：返回左表所有行+右表匹配行，右表不匹配列填NULL
   - 结果 = A + (A ∩ B)
   - 用途：查所有学生及其成绩（没成绩的学生也显示）

3. **右连接(RIGHT JOIN)**：返回右表所有行+左表匹配行，左表不匹配列填NULL
   - 结果 = B + (A ∩ B)
   - 其实可以用LEFT JOIN改写（交换表顺序）

4. **全连接(FULL OUTER JOIN)**：返回两表所有行，不匹配处填NULL
   - 结果 = A ∪ B
   - MySQL不直接支持，可用 `LEFT JOIN UNION RIGHT JOIN` 模拟

5. **交叉连接(CROSS JOIN)**：笛卡尔积，结果行数=A行数 × B行数

**9. 你本科学习中遇到的最大困难是什么？怎么解决的？**

>

>

>
> **第二，阅读Linux源码片段**。我在老师指导下阅读了Linux 2.6版本中进程调度的简化实现，虽然代码量不小，但让我对进程切换、调度队列有了具体认识。
>
> **第三，绘制思维导图**。我将操作系统的五大模块（进程、内存、文件、IO、调度）分别画思维导图，梳理概念之间的联系，比如虚拟内存如何与文件系统通过mmap交互。
>
> **第四，刷题巩固**。我做了408操作系统历年真题和课后习题，通过做题发现自己的知识盲区。
>
> 最终我在这门课取得了XX分（如果分数好可以说），更重要的是学会了如何攻克抽象的课程——通过实践+画图+总结来将抽象具体化。
