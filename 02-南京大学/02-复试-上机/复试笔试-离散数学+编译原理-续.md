## 🔴 题目26：回填与代码优化

**题干**：解释编译原理中的"回填"（backpatching）技术，并说明它在布尔表达式和控制流语句翻译中的应用。

**标准答案**：

**1. 回填的概念**

回填（backpatching）是一种在生成中间代码时，将尚未确定的跳转地址暂时留空，待后续确定后再填入的技术。

具体来说：
- 在生成条件跳转语句（如 `if ... goto L`）时，目标标号 L 的地址可能尚未确定
- 此时先产生一个地址字段为空的指令，并将该指令的位置记录在一个"待填链表"中
- 当确定了目标地址后，遍历待填链表，将所有需要跳转到此地址的指令中的地址字段填好

**2. 布尔表达式的翻译**

布尔表达式 `E = E₁ && E₂` 的语义：
- 如果 E₁ 为假，则整个 E 为假，无需计算 E₂
- 如果 E₁ 为真，则继续计算 E₂，由 E₂ 的值决定 E 的值

使用回填技术：
- `E.truelist`：E 为真时需要跳转的指令地址链表
- `E.falselist`：E 为假时需要跳转的指令地址链表

翻译规则（示意）：
```
E → E₁ && E₂
    回填 E₁.truelist 到 E₂ 的第一条指令地址
    E.truelist = E₂.truelist
    E.falselist = 合并 E₁.falselist 和 E₂.falselist

E → E₁ || E₂
    回填 E₁.falselist 到 E₂ 的第一条指令地址
    E.truelist = 合并 E₁.truelist 和 E₂.truelist
    E.falselist = E₂.falselist
```

**3. 控制流语句的翻译**

if 语句：`if (E) S₁ else S₂`

```
计算 E 的代码，产生 E.truelist 和 E.falselist
E 为真时跳转到 S₁ 的开始
E 为假时跳转到 S₂ 的开始
执行 S₁ 的代码
在 S₁ 末尾产生一条无条件跳转到 S 之后的语句
回填 E.truelist 到 S₁ 的第一条指令地址
回填 E.falselist 到 S₂ 的第一条指令地址
```

while 语句：`while (E) S`

```
begin_label: 循环开始的地址
计算 E 的代码
E 为真时跳转到 S 的开始
E 为假时跳转到循环之后
执行 S 的代码
在 S 末尾产生跳转到 begin_label 的指令
回填 E.truelist 到 S 的第一条指令地址
回填 E.falselist 到循环之后的指令地址
```

**4. 具体示例**：翻译 `while (a < b && c > 0) { x = x + 1; }`

```
100: if a < b goto 102    (E₁ 的真转跳)
101: goto 108              (E₁ 的假转跳，即 E 的假转跳)
102: if c > 0 goto 104    (E₂ 的真转跳，即 E 的真转跳)
103: goto 108              (E₂ 的假转跳，即 E 的假转跳)
104: t = x + 1            (S 开始)
105: x = t
106: goto 100             (回到循环开始)
107: ...                  (循环结束)
108: ...
```

回填过程：
- E = E₁ && E₂：E₁.truelist = {100 中的假跳转位置？需要详细记录每条待填指令}
- 实际上每条 if/goto 指令产生时，目标地址字段留空，记录在链表中
- E₁ 为真（a<b）时，应跳转到 E₂ 的开始（102）
- 所以回填 E₁.truelist，使其中指令跳转到 102
- E₂ 为真（c>0）时，应跳转到 S 的开始（104）
- 回填 E₂.truelist，使其中指令跳转到 104
- E₁.falselist 和 E₂.falselist 合并为 E.falselist，都跳转到 108

**详细解析**：
- 回填是一种实用的代码生成技术，避免多次扫描
- 关键数据结构：待填链表（需要回填的指令地址列表）
- makelist(i)：创建只包含 i 的新链表
- merge(p1, p2)：合并链表 p1 和 p2，返回合并后的链表
- backpatch(p, i)：将链表 p 中每条指令的地址字段设置为 i
- 在实际编译器（如 YACC/BISON）中，回填广泛应用于布尔表达式和控制流的翻译

### 题目27：三地址码与类型检查

**题干**：简要说明以下概念：
1. 三地址码（Three-address code）
2. 类型检查（Type checking）

**标准答案**：

**1. 三地址码**

三地址码是一种中间表示形式，每条指令最多包含三个地址（两个操作数和一个结果）。

一般形式：`x = y op z`

其中：
- x 是结果变量的地址
- y 和 z 是操作数的地址（变量名、常量或编译器生成的临时变量）
- op 是运算符（算术、逻辑、关系等）

常见的三地址码类型：

a) **赋值语句**：
```
x = y op z      (二元运算)
x = op y        (一元运算，如取反)
x = y           (复制)
```

b) **跳转语句**：
```
goto L          (无条件跳转到标号 L)
if x goto L    (如果 x 为真则跳转到 L)
if False x goto L (如果 x 为假则跳转到 L)
if x relop y goto L (关系运算后条件跳转)
```

c) **过程调用**：
```
param x₁
param x₂
...
param x_n
call p, n      (调用过程 p，有 n 个参数)
return y       (返回 y)
```

d) **索引赋值**：
```
x = y[i]       (读取数组元素)
x[i] = y       (写入数组元素)
```

e) **地址和指针**：
```
x = &y         (取地址)
x = *y         (间接引用)
*x = y         (间接赋值)
```

示例：翻译 `a + b * c`
```
t₁ = b * c
t₂ = a + t₁
```

**2. 类型检查**

类型检查是语义分析的重要组成部分，确保程序中各操作的类型正确。

主要任务：

a) **表达式的类型推断**：
```
整数 + 整数 → 整数
浮点 + 浮点 → 浮点
整数 + 浮点 → 浮点 (需要类型转换)
数组名[整数] → 元素类型
```

b) **语句的类型检查**：
- 条件表达式的类型必须是布尔类型
- 赋值语句左右两边类型必须兼容
- 函数调用时实参与形参的类型、个数必须匹配

c) **类型转换**：

隐式转换（自动转换）：
```
int → float   (提升精度)
char → int    (字符转整数)
```

显式转换（强制转换）：
```
(int) x       (C 风格)
int(x)        (C++ 风格)
```

d) **类型检查规则示例**：

表达式的类型推断规则（以属性文法形式）：
```
E → E₁ + E₂
    E.type = if E₁.type = int and E₂.type = int then int
             else if E₁.type = float and E₂.type = float then float
             else if E₁.type = int and E₂.type = float then float
             else if E₁.type = float and E₂.type = int then float
             else type_error
```

赋值语句：
```
S → id = E
    if id.type = E.type 或 可隐式转换(E.type, id.type)
    then 类型检查通过
    else 报告类型错误
```

**详细解析**：
- 三地址码是生成目标代码的基础，易于转换为汇编语言
- 临时变量的合理使用和优化是代码优化的重要部分
- 类型检查是确保程序类型安全的关键步骤
- 静态类型语言（如 C, Java）在编译时进行类型检查
- 动态类型语言（如 Python, JavaScript）在运行时进行类型检查
- 现代编译器在类型检查时还会进行类型推断（如 ML, Haskell, Scala, Go 等）

**出处标注**：南大笔试编译原理基础概念题

### 题目28：活跃变量分析

**题干**：说明活跃变量（Live variable）分析的概念、算法和应用。

**标准答案**：

**1. 活跃变量的定义**

变量 x 在程序点 p 是**活跃的**（live），如果：
- 存在从 p 出发的路径
- 在这条路径上 x 的值被使用（读取）
- 且在使用之前没有重新赋值

换句话说，变量在某点活跃意味着它的值在将来可能被用到。

**2. 活跃变量分析的数据流方程**

对每个基本块 B：
- `use[B]`：在 B 中被使用（在被赋值前）的变量集合
- `def[B]`：在 B 中被赋值（在被使用前）的变量集合
- `in[B]`：在 B 入口处活跃的变量集合
- `out[B]`：在 B 出口处活跃的变量集合

数据流方程：
```
in[B] = use[B] ∪ (out[B] - def[B])
out[B] = ∪{in[S] | S 是 B 的后继块}
```

边界条件：对程序的出口块（exit block），`out[exit] = ∅`

**3. 迭代算法**

初始化：对所有基本块 B，`in[B] = ∅, out[B] = ∅`

迭代更新（直到不再变化）：
```
for 每个基本块 B {
    in_old = in[B]
    out_old = out[B]
    out[B] = ∪{in[S] | S 是 B 的后继块}
    in[B] = use[B] ∪ (out[B] - def[B])
    if in[B] = in_old and out[B] = out_old then 收敛
}
```

**4. 示例分析**

代码：
```
1: a = b + c
2: d = a - e
3: f = d + b
4: return f
```

基本块 B（包含语句1-4）：

分析 use 和 def（从后往前分析每个语句）：

- 语句 4: `return f`，use = {f}，def = ∅
- 语句 3: `f = d + b`，use = {d, b}，def = {f}
- 语句 2: `d = a - e`，use = {a, e}，def = {d}  
- 语句 1: `a = b + c`，use = {b, c}，def = {a}

合并后（按块分析 use 和 def）：
- `use[B]`：在 B 中被使用且在该块中使用前未被赋值的变量
  - b 在语句1和3中使用，在1中首次出现前未赋值 → b ∈ use
  - c 在语句1中使用，之前未赋值 → c ∈ use
  - e 在语句2中使用，之前未赋值 → e ∈ use
  - a 在语句2中使用，但在语句1中已赋值 → a ∉ use
  - d 在语句3中使用，但在语句2中已赋值 → d ∉ use
  - f 在语句4中使用，但在语句3中已赋值 → f ∉ use
- `use[B] = {b, c, e}`

- `def[B]`：在 B 中被赋值的变量
  - a 在语句1中被赋值 → a ∈ def
  - d 在语句2中被赋值 → d ∈ def
  - f 在语句3中被赋值 → f ∈ def
- `def[B] = {a, d, f}`

假设这是最后一个块，`out[B] = ∅`（出口处没有变量活跃）：
- `in[B] = use[B] ∪ (out[B] - def[B]) = {b, c, e} ∪ ∅ = {b, c, e}`

解释：在块 B 的入口处，只有 b, c, e 是活跃的（它们的值会被使用）。

**5. 应用**

a) **寄存器分配**：
- 如果变量在某点不活跃，则其寄存器可以被重新分配给其他变量
- 可以最小化寄存器使用数量

b) **死代码消除**：
- 如果变量被赋值后从未被使用（即赋值点后不活跃），则该赋值语句可以删除
- 例如：`x = 5; return y;` 中，如果 x 在后面不被使用，则 `x = 5` 是死代码

c) **代码移动**：
- 将循环不变量（每次循环值不变的表达式）移到循环外
- 需要知道变量在循环外是否活跃

**详细解析**：
- 活跃变量分析是一种向后数据流分析（backward data flow analysis）
- 从程序出口向入口方向传播活跃信息
- 这是编译优化中最基本的数据流分析之一
- 是全局寄存器分配、死代码消除等优化的基础

### 题目29：寄存器分配与代码生成

**题干**：简述代码生成阶段的主要任务和寄存器分配的基本策略。

**标准答案**：

**1. 代码生成的主要任务**

a) **指令选择**（Instruction selection）：
- 将中间代码（三地址码、四元式等）映射为目标机器指令
- 需要考虑指令的效率和优化

b) **寄存器分配**（Register allocation）：
- 将程序变量分配到寄存器或内存
- 目标是最小化内存访问次数，提高性能
- 通常比寄存器指派更复杂（全局分配）

c) **指令排序**（Instruction scheduling）：
- 重新排列指令顺序以避免流水线停顿
- 利用指令级并行性

d) **代码优化**（Code optimization）：
- 局部优化：基本块内的优化
- 全局优化：跨基本块的优化
- 包括：常数合并、死代码消除、强度削弱等

**2. 寄存器分配的基本策略**

a) **简单寄存器分配**（对于局部基本块）：

策略：保持最频繁使用的值在寄存器中

基本思想：
- 维护寄存器描述符（描述每个寄存器当前存放的内容）
- 维护地址描述符（描述变量的值当前在哪里：寄存器、内存、栈...）
- 需要新寄存器时：
  - 如果有空闲寄存器，直接使用
  - 否则需要"溢出"（spill）一个寄存器到内存
  - 选择最少引用的变量（或最远将来才用到的变量）溢出

b) **图着色寄存器分配**（全局分配）：

将寄存器分配问题转化为图着色问题：

**步骤1：构建冲突图（Interference graph）**
- 每个节点表示一个变量或临时变量
- 如果两个变量在程序某点同时活跃（即它们的值都需要保留），则在它们之间连一条边
- 冲突图中相邻的节点不能分配到同一个寄存器

**步骤2：图着色**
- 有 K 个可用寄存器，就是找 K-着色
- 简化算法（简化节点）：
  - 如果存在度数 < K 的节点，将其压栈并从图中删除
  - 如果所有节点度数 ≥ K，选择一个节点溢出（spill）
  - 重复直到所有节点被处理
- 从栈中弹出节点，分配颜色（寄存器号）
- 如果无法分配则插入 spill 代码后重新分析

示例（K=2，即只有2个寄存器可用）：
```
冲突图:
    a --- b
    |     |
    c --- d

节点度数: deg(a)=2, deg(b)=2, deg(c)=2, deg(d)=2
所有节点度数都 ≥ K=2，必须选择一个节点溢出

溢出 d 后：
    a --- b
    |
    c
度数都 < 2，可以分配
```

c) **活跃区间分析**（Live range analysis）：

每个变量的活跃区间 = {程序点 p | 变量在 p 处活跃}

如果两个变量的活跃区间重叠，则它们冲突，不能共用寄存器。

**3. 典型代码生成示例**

三地址码：
```
t₁ = a + b
t₂ = t₁ * c
t₃ = t₂ - d
```

假定有 3 个寄存器 R0, R1, R2 可用：

可能的寄存器分配和代码生成：
```
LD  R0, a     R0 = a
LD  R1, b     R1 = b
ADD R0, R1    R0 = R0 + R1 (即 a + b)   -- t₁ 在 R0
LD  R1, c     R1 = c
MUL R0, R1    R0 = R0 * R1 (即 t₁ * c)  -- t₂ 在 R0
LD  R1, d     R1 = d
SUB R0, R1    R0 = R0 - R1 (即 t₂ - d)  -- t₃ 在 R0
ST  x, R0     x = R0 (保存结果)
```

**4. 影响寄存器分配的因素**

a) **变量的使用频率**：频繁使用的变量应常驻寄存器
b) **变量的活跃范围**：活跃范围短的变量更容易分配
c) **循环结构**：循环内部的变量应该优先分配寄存器
d) **函数调用**：调用者保存（caller-save）和被调用者保存（callee-save）
e) **寄存器的特殊用途**：某些寄存器可能被硬件特殊规定

**5. 溢出策略**

当寄存器不足时，需要将某些变量的值暂时保存到内存：

a) **选择溢出变量**：
- 溢出最少使用的变量
- 溢出在循环外使用的变量
- 溢出计算成本低的变量（即容易重新计算）

b) **溢出代码**：
```
ST  memory_loc, Rx   (保存到内存)
...                  (Rx 被其他变量使用)
LD  Rx, memory_loc   (需要时重新加载)
```

**详细解析**：
- 寄存器分配是代码生成中影响性能的关键环节
- 图着色是一种最优但复杂的全局分配方法，NP-完全问题
- 实际编译器使用启发式算法，如线性扫描寄存器分配（Linear scan）
- 寄存器分配直接影响程序的运行速度，因为寄存器访问比内存快得多

### 题目30：编译优化 - 循环优化

**题干**：列举并说明至少3种循环优化技术。

**标准答案**：

循环优化是编译优化的重要组成部分，因为程序的大部分时间都花费在循环中。以下是主要的循环优化技术：

**1. 循环不变量外提（Loop-invariant code motion / Code hoisting）**

**概念**：将循环中每次迭代结果相同的计算（循环不变量）移到循环外面。

**示例**：

原始代码：
```c
for (i = 0; i < n; i++) {
    x = y * z;      // y*z 不依赖 i，每次计算都一样
    a[i] = x + i;
}
```

优化后：
```c
t = y * z;          // 循环不变量：移到循环前计算一次
for (i = 0; i < n; i++) {
    a[i] = t + i;
}
```

**识别循环不变量**：
- 表达式的操作数都是常数，或
- 表达式的所有定义都在循环外，或
- 表达式的操作数中只有一个定义在循环内，但该定义本身是循环不变量

**实现步骤**：
1. 识别循环不变量语句
2. 检查该语句是否可以移动：
   - 它在循环中只有一个位置
   - 它在循环的每个出口处都被执行
   - 它的目标变量在循环外部不活跃（即循环后不会被使用）
3. 将语句移动到循环的前置块（preheader）

**2. 归纳变量消除（Induction variable elimination / Strength reduction）**

**概念**：归纳变量是指在循环中按固定模式递增/递减的变量。可以用计算更简单的形式替换。

**示例**（强度削弱）：

原始代码：
```c
for (i = 0; i < n; i++) {
    x = i * 4;      // 乘法运算代价较高
    a[x] = b[i];
}
```

优化后（将乘法替换为加法）：
```c
t = 0;              // t = i * 4，初始值
for (i = 0; i < n; i++) {
    a[t] = b[i];
    t = t + 4;      // 加法比乘法快得多
}
```

**示例**（归纳变量消除）：

原始代码：
```c
j = 1;
for (i = 0; i < n; i++) {
    j = 2 * j;      // j = 2^(i+1)，与 i 有线性关系
    a[i] = j;
}
```

如果 i 在循环内不再被使用，可以用 j 替代循环条件：
```c
j = 1;
limit = 2^(n+1);   // 注意：这个例子需要计算limit，可能不总是有利
while (j < limit) {
    ...
    j = 2 * j;
}
```

**3. 循环展开（Loop unrolling）**

**概念**：将循环体复制若干次，减少循环控制开销和增加指令级并行机会。

**示例**：

原始代码：
```c
for (i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

展开4倍后：
```c
for (i = 0; i < n - 3; i += 4) {
    a[i]   = b[i]   + c[i];
    a[i+1] = b[i+1] + c[i+1];
    a[i+2] = b[i+2] + c[i+2];
    a[i+3] = b[i+3] + c[i+3];
}
// 处理剩余元素
for (; i < n; i++) {
    a[i] = b[i] + c[i];
}
```

**好处**：
- 减少循环计数器更新和条件判断的次数（降低循环开销）
- 增加基本块大小，为指令级并行和寄存器分配提供更多机会
- 减少分支预测失败的影响

**代价**：
- 代码体积增大（可能影响指令缓存命中率）
- 如果 n 不是展开因子的倍数，需要处理边界情况

**4. 循环反转（Loop inversion）**

将 `for` 循环改写为 `do-while`，减少一次条件检查。

原始代码：
```c
for (i = 0; i < n; i++) {
    a[i] = 0;
}
```

优化后（当 n > 0 时有效）：
```c
i = 0;
do {
    a[i] = 0;
    i++;
} while (i < n);
```

配合循环展开效果更好。

**5. 循环分块（Loop tiling / Blocking）**

为改善内存访问的局部性（特别是缓存命中），将大数组的访问分成小块。

示例（矩阵乘法）：

原始代码：
```c
for (i = 0; i < N; i++)
    for (j = 0; j < N; j++)
        for (k = 0; k < N; k++)
            C[i][j] += A[i][k] * B[k][j];
```

分块后（块大小 = B）：
```c
for (i = 0; i < N; i += B)
    for (j = 0; j < N; j += B)
        for (k = 0; k < N; k += B)
            // 在一个 B×B 的块内计算
            for (ii = i; ii < i+B; ii++)
                for (jj = j; jj < j+B; jj++)
                    for (kk = k; kk < k+B; kk++)
                        C[ii][jj] += A[ii][kk] * B[kk][jj];
```

**原理**：提高缓存命中率，减少内存访问延迟。对大数组尤为重要。

**6. 循环交换（Loop interchange）**

交换嵌套循环的顺序，改善数组访问的内存局部性。

原始代码（按列访问，缓存不友好）：
```c
for (j = 0; j < N; j++)
    for (i = 0; i < N; i++)
        A[i][j] = B[i][j] + 1;  // 列优先访问，每次跨越一行
```

优化后（按行访问，缓存友好）：
```c
for (i = 0; i < N; i++)
    for (j = 0; j < N; j++)
        A[i][j] = B[i][j] + 1;  // 行优先访问，顺序访问内存
```

**7. 循环融合（Loop fusion / Jamming）**

将两个相邻的、操作相同数组的循环合并为一个，提高缓存命中率。

原始代码：
```c
for (i = 0; i < n; i++)
    a[i] = b[i] + c[i];
for (i = 0; i < n; i++)
    d[i] = a[i] * e[i];   // a 刚被赋值，可能仍在缓存中
```

融合后：
```c
for (i = 0; i < n; i++) {
    a[i] = b[i] + c[i];
    d[i] = a[i] * e[i];   // a[i] 刚计算完，可立即使用
}
```

**8. 循环分裂（Loop fission / Distribution）**

与循环融合相反，将一个循环分裂为多个循环，有时有助于向量并行化。

原始代码：
```c
for (i = 0; i < n; i++) {
    x[i] = a[i] + b[i];
    y[i] = x[i] * c[i];   // y 依赖 x，限制并行
}
```

分裂后（如果目标是并行化）：
```c
for (i = 0; i < n; i++)
    x[i] = a[i] + b[i];   // 可完全并行
for (i = 0; i < n; i++)
    y[i] = x[i] * c[i];   // 可完全并行
```

**详细解析**：
- 循环优化对程序性能影响巨大，因为程序通常90%的时间花在10%的代码上（热点），而热点往往是循环
- 不同的优化技术适用于不同的场景，需要编译器进行成本-收益分析
- 现代编译器（如 GCC, LLVM/Clang）实现了大多数上述优化，通常在 -O2, -O3 级别开启
- 理解这些优化有助于程序员写出更高效的代码，并理解编译器做了什么
