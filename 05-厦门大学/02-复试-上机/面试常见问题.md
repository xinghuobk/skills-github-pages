### 1. 请简述数据结构中栈和队列的区别及应用场景。

**参考答案**：

**栈（Stack）**：后进先出（LIFO）的线性表，只允许在栈顶进行插入删除。
- 操作：push、pop、peek
- 应用：表达式求值、括号匹配、函数调用/递归、DFS、撤销操作

**队列（Queue）**：先进先出（FIFO）的线性表，只允许在队尾插入、队头删除。
- 操作：enqueue、dequeue
- 应用：任务调度、BFS、缓冲区、消息队列、层次遍历

**延伸问题**：循环队列如何判断空满？（方案一：预留一个空位；方案二：用计数器；方案三：设标志位）

### 2. 什么是哈希表？如何解决哈希冲突？

**参考答案**：

**哈希表**：通过哈希函数将关键字映射到表中位置，实现 O(1) 平均查找时间。

**冲突解决方法**：

1. **开放定址法**：冲突时在表中寻找下一个空位置
   - 线性探测：H = (H(key) + i) % m，易产生"聚集"
   - 二次探测：H = (H(key) + i²) % m

2. **链地址法**：将哈希到同一地址的元素链接成链表
   - 优点：无聚集，删除简单
   - 缺点：需要额外指针空间

3. **再哈希法**：使用多个哈希函数，冲突时依次尝试

4. **建立公共溢出区**：冲突元素存入专门的溢出表

**负载因子**：α = 填入元素数 / 哈希表长度。α 越大，冲突概率越高。

### 3. 请比较链表和数组的优缺点。

**参考答案**：

**数组（连续存储）**：
- 优点：随机访问 O(1)、存储密度高、缓存友好
- 缺点：大小固定、插入删除需移动元素 O(n)、可能产生碎片

**链表（链式存储）**：
- 优点：动态大小、插入删除 O(1)（已知位置）、内存利用灵活
- 缺点：不支持随机访问、需额外指针空间、缓存不友好

**应用场景**：频繁插入删除用链表；需要随机访问且大小可预估用数组。

### 4. 什么是二叉搜索树？AVL 树和红黑树的区别？

**参考答案**：

**二叉搜索树（BST）**：左子树所有节点值 < 根节点值 < 右子树所有节点值。中序遍历得有序序列。查找/插入/删除平均 O(log n)，最坏 O(n)。

**AVL 树**：严格平衡 BST，每个节点左右子树高度差不超过 1。
- 插入删除后通过旋转维护平衡
- 查找效率高但插入删除旋转开销较大

**红黑树**：近似平衡 BST，通过颜色标记和五条性质维护平衡。
- 性质：节点非红即黑；根为黑；红节点子必为黑；任一节点到叶子黑节点数相同
- 查找略逊于 AVL，但插入删除旋转次数更少（最多 3 次）
- STL 的 map、set 底层多采用红黑树

### 5. 请解释进程和线程的区别，为什么引入线程？

**参考答案**：

**进程**：资源分配的基本单位，拥有独立地址空间。
**线程**：CPU 调度的基本单位，同一进程内线程共享进程资源。

**主要区别**：
1. 资源拥有：进程拥有资源，线程只拥有少量私有资源（栈、寄存器）
2. 调度：线程是 CPU 调度基本单位
3. 开销：线程创建/切换/销毁的开销远小于进程
4. 并发性：多线程可利用多核并行执行
5. 通信：线程间通过共享内存通信（但需同步）

**引入线程的原因**：提高并发度、减少系统开销、简化通信、提高响应性。

### 6. 什么是死锁？产生条件和解决方法？

**参考答案**：

**死锁**：多个进程因争夺资源而互相等待，若无外力作用都无法推进的现象。

**四个必要条件**：互斥、请求与保持、不剥夺、循环等待

**解决方法**：
1. **预防死锁**：破坏必要条件（一次性请求所有资源；资源编号按序请求等）
2. **避免死锁**：银行家算法，分配资源前检查系统是否安全
3. **检测与解除**：允许死锁发生，检测后撤销进程或剥夺资源
4. **忽略**：鸵鸟策略（个人操作系统）

### 7. 请描述虚拟内存的原理和实现机制。

**参考答案**：

**虚拟内存**：将主存和辅存结合管理，提供比物理内存大得多的地址空间。

**基本思想**：程序执行时只将当前需要的页/段装入内存，不需要的留在外存，需要时动态调入。

**实现方式**：

1. **请求分页**：
   - 基本单位：页（通常 4KB）
   - 页表：记录页号与物理块号的映射
   - 缺页中断：访问的页不在内存时触发
   - 页面置换：内存不足时选择页面调出

2. **请求分段**：以段（逻辑单位）为基本单位

**页面置换算法**：FIFO、LRU、OPT（最佳置换，不可实现，用于比较）

**局部性原理**：虚拟内存的理论基础——时间局部性和空间局部性

### 8. 请比较 TCP 和 UDP 的特点及应用场景。

**参考答案**：

**TCP**：面向连接、可靠传输（确认、超时重传、序号保证顺序）、面向字节流、流量控制、拥塞控制、点对点、首部开销较大（20-60 字节）
- 应用：HTTP/HTTPS、FTP、SMTP、SSH

**UDP**：无连接、不可靠、面向报文、无流量/拥塞控制、支持多播、首部开销小（8 字节）
- 应用：视频会议、实时游戏、VoIP、直播、DNS

### 9. 请描述 TCP 三次握手和四次挥手过程。

**参考答案**：

**三次握手**：
1. 客户端发送 SYN(seq=x)，进入 SYN_SENT
2. 服务器发送 SYN+ACK(seq=y, ack=x+1)，进入 SYN_RCVD
3. 客户端发送 ACK(ack=y+1)，双方进入 ESTABLISHED

**为什么不是两次**：防止已过期连接请求到达服务器；确保双方收发能力正常；同步初始序列号。

**四次挥手**：
1. 客户端发送 FIN(seq=u)，进入 FIN_WAIT_1
2. 服务器发送 ACK(ack=u+1)，进入 CLOSE_WAIT；客户端收到进入 FIN_WAIT_2
3. 服务器发送完剩余数据后发送 FIN(seq=w)，进入 LAST_ACK
4. 客户端发送 ACK(ack=w+1)，进入 TIME_WAIT；服务器收到后关闭
5. 客户端等待 2*MSL 后关闭

**TIME_WAIT 作用**：确保最后一个 ACK 能被对方收到；让网络中残留报文消失。

### 10. HTTP 和 HTTPS 的区别？HTTPS 加密过程？

**参考答案**：

**区别**：HTTP 默认端口 80 明文传输；HTTPS 默认端口 443 SSL/TLS 加密传输，需要数字证书。

**HTTPS 握手过程（简化）**：
1. 客户端发送支持的加密算法列表和 Client Random
2. 服务器选择算法，返回证书（含公钥）和 Server Random
3. 客户端验证证书，生成 Pre-Master Secret，用服务器公钥加密后发送
4. 服务器用私钥解密得到 Pre-Master Secret
5. 双方根据三个随机数计算会话密钥
6. 后续通信使用会话密钥进行对称加密

**加密方式**：非对称加密（RSA 等）用于交换密钥，对称加密（AES 等）用于实际数据传输。

### 11. 请解释数据库事务的 ACID 特性。

**参考答案**：

1. **原子性（Atomicity）**：事务要么全部执行要么全部不执行。由恢复机制保证。
2. **一致性（Consistency）**：事务执行前后数据库保持一致状态。由应用程序和完整性机制保证。
3. **隔离性（Isolation）**：并发事务之间相互隔离。由并发控制机制（锁、MVCC）保证。
4. **持久性（Durability）**：事务一旦提交，修改永久有效。由恢复机制（日志、备份）保证。

**并发问题**：丢失修改、不可重复读、读"脏"数据、幻影读。
**四种隔离级别**：读未提交、读已提交、可重复读、可串行化。

### 12. 什么是索引？B+ 树索引的优势？

**参考答案**：

**索引**：为加速数据查询而建立的数据结构，类似书籍目录。
- 优点：提高查询速度
- 缺点：占用额外存储空间，降低插入/删除/更新速度

**B+ 树特点**：非叶节点只存键值，叶节点存实际数据/指针，所有叶节点通过链表连接形成有序序列。

**B+ 树优势**：
1. 查询稳定（每次查询都走到叶子节点）
2. 范围查询高效（叶节点链表可直接遍历）
3. 顺序访问友好（叶节点有序，适合排序和分组）
4. 树高更小（多路搜索树）
5. 插入删除效率高（节点分裂合并保持平衡）

### 13. 请描述动态规划的核心思想并举例。

**参考答案**：

**动态规划（DP）**：把多阶段决策问题分解为子问题，通过保存子问题结果避免重复计算。

**核心思想**：
1. **最优子结构**：问题最优解包含子问题最优解
2. **重叠子问题**：子问题被多次重复计算
3. **状态转移**：从小规模子问题的解推导出大规模子问题的解

**三要素**：状态定义、状态转移方程、边界条件

**经典示例**：
- 斐波那契数列：dp[n] = dp[n-1] + dp[n-2]
- 0-1 背包问题
- 最长上升子序列（LIS）
- 最长公共子序列（LCS）
- 编辑距离

**与贪心的区别**：贪心每步选当前最优，不保证全局最优；DP 考虑所有可能情况保证全局最优。

### 14. 请比较面向过程和面向对象的编程思想。

**参考答案**：

**面向过程**：以过程（函数）为中心，通过函数调用处理数据。
- 代表语言：C、Pascal
- 优点：简单直观、执行效率较高
- 缺点：难以维护、可扩展性差、复用性低

**面向对象**：以对象为中心，将数据和操作数据的方法封装在一起。
- 三大特性：封装、继承、多态
  - 封装：隐藏实现细节，暴露必要接口
  - 继承：子类继承父类属性和方法，实现复用
  - 多态：同一接口不同实现（重载/重写）
- 代表语言：Java、C++、C#、Python
- 优点：易维护、易扩展、代码复用性高

### 15. 什么是操作系统内核？微内核和宏内核的区别？

**参考答案**：

**内核**：操作系统核心部分，负责管理系统资源（CPU、内存、I/O）、进程/线程调度、文件系统、网络协议等。运行在内核态。

**宏内核**：所有内核功能运行在同一内核空间。
- 代表：Linux、早期 Unix
- 优点：性能高（无需 IPC 开销），实现简单
- 缺点：代码庞大复杂，模块崩溃可能影响整个系统

**微内核**：只保留最核心功能（进程调度、基本内存管理、消息传递），其他功能（文件系统、网络、驱动）作为用户态进程运行。
- 代表：Minix、QNX、Mach
- 优点：可靠性高（各模块独立）、扩展性好、安全性高
- 缺点：性能较低（频繁用户态-内核态切换和 IPC）

**混合内核**：结合两者优点。代表：Windows NT、XNU（macOS/iOS）

### 16. 请解释什么是内存泄漏，如何检测和避免？

**参考答案**：

**内存泄漏**：程序动态分配的内存在使用完毕后未被释放，导致内存持续被占用。

**常见原因**：
1. malloc/new 分配后忘记 free/delete
2. 程序异常退出未执行释放操作
3. 容器持续增长但未清理
4. 循环引用导致引用计数无法清零（智能指针场景）

**检测工具**：
- C/C++：Valgrind、AddressSanitizer
- Java：jmap、MAT、jvisualvm
- Python：memory_profiler、objgraph

**避免方法**：
1. 使用智能指针（C++：unique_ptr、shared_ptr）
2. 遵循"谁分配谁释放"原则
3. 使用 RAII 技术
4. 代码审查关注内存管理
5. 定期压力测试和性能分析

### 18. 什么是 SQL 注入？如何防范？

**参考答案**：

**SQL 注入**：攻击者在输入字段中注入恶意 SQL 语句，利用应用程序对输入验证不足的漏洞，欺骗数据库执行非预期 SQL 命令。

**示例漏洞**：将用户输入直接拼接到 SQL 语句中

```
sql = "SELECT * FROM users WHERE username = '" + userInput + "'"
```

攻击者输入 `' OR '1'='1` 可绕过登录验证。

**防范措施**：
1. **使用参数化查询/预编译语句**：将 SQL 结构和参数分离
2. **使用 ORM 框架**：Hibernate、MyBatis、SQLAlchemy
3. **输入验证和过滤**：白名单验证、长度限制
4. **最小权限原则**：数据库账号只授予必要权限
5. **使用 Web 应用防火墙（WAF）**

### 19. 请描述快速排序的原理、时间复杂度和优缺点。

**参考答案**：

**基本思想**（分治）：
1. 选择一个基准元素（pivot）
2. 将小于基准的放左边，大于基准的放右边（分区 partition）
3. 对左右子数组递归执行

**基准选择**：固定位置、随机选择、三数取中

**时间复杂度**：
- 最好/平均：O(n log n)
- 最坏：O(n²)（分区极不均匀，如已排序数组选首元素为基准）
- 空间复杂度：O(log n) ~ O(n)（递归栈）

**稳定性**：不稳定排序

**优点**：平均性能优秀、原地排序、缓存友好
**缺点**：最坏情况 O(n²)、不稳定

**优化方法**：随机化快速排序、三数取中、小数组用插入排序、三路快排

### 21. 什么是设计模式？举例说明几个常用的设计模式。

**参考答案**：

**设计模式**：软件设计中针对特定场景问题的通用可复用解决方案。

**GoF 23 种设计模式**分三类：

**创建型**（处理对象创建）：
- **单例模式**：确保一个类只有一个实例，提供全局访问点。应用：日志记录器、数据库连接池。
- **工厂方法**：定义创建对象的接口，由子类决定实例化哪个类。
- **抽象工厂**：提供创建一系列相关对象的接口。

**结构型**（处理类和对象组合）：
- **适配器**：将一个类的接口转换成客户期望的另一个接口。应用：新旧接口兼容。
- **装饰器**：动态地给对象添加额外职责。应用：I/O 流。
- **代理**：为其他对象提供代理以控制对它的访问。

**行为型**（处理对象间通信）：
- **观察者**：一对多依赖，对象状态变化时通知所有观察者。应用：事件监听、发布-订阅。
- **策略**：定义一系列算法，将每个算法封装并可互换。应用：排序算法选择、支付方式选择。
- **模板方法**：定义算法骨架，将步骤延迟到子类实现。应用：JUnit、Spring 模板类。

### 22. 请解释 RESTful API 设计原则。

**参考答案**：

**REST（表述性状态转移）**：一种软件架构风格。

**六大核心原则**：
1. **客户端-服务器**：分离 UI 和数据存储
2. **无状态**：服务器不保存客户端状态，每个请求包含所有必要信息
3. **缓存**：响应标记为可缓存或不可缓存，减少网络请求
4. **统一接口**（REST 核心）：资源通过 URI 标识；通过表述操纵资源；自描述消息；超媒体驱动（HATEOAS）
5. **分层系统**：客户端无法判断是否直接连接到最终服务器
6. **按需代码（可选）**：服务器可向客户端传输代码执行

**设计最佳实践**：
- 使用名词表示资源：/users（不是 /getUsers）
- 使用 HTTP 方法表示操作：GET 查询、POST 创建、PUT 更新、DELETE 删除
- 使用 HTTP 状态码表示结果：200 OK、201 Created、400 Bad Request、404 Not Found、500 Internal Server Error
- 使用版本号：/api/v1/users
- 返回 JSON 格式数据
- 使用分页/排序/过滤参数

### 23. 请描述容器化技术（Docker）和虚拟化技术（VM）的区别。

**参考答案**：

**容器**：共享主机 OS 内核，隔离进程和文件系统。轻量级、启动快（秒级）、资源利用率高。代表：Docker。

**虚拟机**：拥有独立的客户 OS，通过 Hypervisor 模拟硬件。重量级、启动慢（分钟级）、隔离性更强。代表：VMware、KVM、VirtualBox。

**容器核心技术**：
- **Namespace**：资源隔离（PID、NET、MNT、UTS、IPC、USER）
- **Cgroups**：资源限制（CPU、内存、IO）
- **UnionFS**：镜像分层和容器文件系统

**Docker 核心概念**：镜像（Image）、容器（Container）、仓库（Registry）

**应用场景**：
- 微服务、CI/CD：Docker + Kubernetes
- 开发环境一致性
- 传统企业应用、需要强隔离场景：虚拟机

### 24. 请描述计算机网络中路由选择算法。

**参考答案**：

**距离向量算法**：每个路由器维护到各目的地的距离向量，定期向邻居发送路由表。Bellman-Ford 算法（RIP 使用）。
- 优点：简单易实现
- 缺点：收敛慢、"坏消息传得慢"、计数到无穷问题

**链路状态算法**：每个路由器将自己的链路状态广播到整个网络，所有路由器拥有相同的完整拓扑图。使用 Dijkstra 算法计算最短路径（OSPF 使用）。
- 优点：收敛快、无循环
- 缺点：实现复杂、开销大

**常见路由协议**：
- **RIP**：距离向量，最大跳数 15，小型网络
- **OSPF**：链路状态，大中型网络
- **BGP**：路径向量，互联网核心路由协议

### 25. 请解释微服务架构和单体架构的区别。

**参考答案**：

**微服务**：将单体应用拆分为一组小的独立服务，每个服务运行在自己的进程中，通过轻量级通信机制（HTTP API）协作。

**核心特征**：按业务拆分、独立部署、独立技术栈、去中心化数据管理、自动化部署（CI/CD、Docker、Kubernetes）

**对比**：

| 维度 | 单体架构 | 微服务架构 |
| :--: | :--: | :--: |
| 部署 | 一个应用包 | 多个服务分别部署 |

**微服务优势**：敏捷开发和部署、独立扩展、故障隔离、技术选型灵活

### 27. 请解释缓存穿透、缓存击穿和缓存雪崩。

**参考答案**：

**缓存穿透**：查询数据库中不存在的数据，缓存中也没有，导致每次查询都要访问数据库。
- 恶意场景：攻击者使用大量不存在的 key 发起请求
- 解决方案：缓存空值（设置较短过期时间）、布隆过滤器、接口层参数校验

**缓存击穿**：某个热点 key 缓存过期的瞬间，大量并发请求同时涌入，直接打到数据库。
- 特点：针对单个热点 key
- 解决方案：互斥锁（只允许一个请求回源重建缓存）、热点数据永不过期、提前预热

**缓存雪崩**：大量缓存 key 在同一时间集体失效，或缓存服务宕机，导致所有请求同时到达数据库。
- 特点：大量 key 同时失效
- 解决方案：过期时间加随机偏移避免同时过期、多级缓存、服务降级/熔断、缓存集群高可用、限流

**最佳实践**：合理设置过期时间、缓存预热策略、缓存监控（命中率、内存、响应时间）、数据库限流保护。

### 28. 什么是消息队列？应用场景和常用技术有哪些？

**参考答案**：

**消息队列（MQ）**：在分布式系统中用于在不同组件/服务之间传递消息的中间件。

**核心作用**：异步处理、应用解耦、流量削峰

**应用场景**：
1. **异步处理**：将非实时耗时操作异步化（发送邮件/短信、生成报表）
2. **应用解耦**：服务间通过消息通信而非直接调用，各服务独立开发部署扩展
3. **流量削峰**：秒杀抢购等高并发场景，保护后端服务不被冲垮
4. **日志收集**：应用日志发送到 MQ，由日志系统消费处理
5. **事件驱动**：一个服务状态变化通知其他服务
6. **分布式事务**：基于消息的最终一致性方案

**常用 MQ 技术**：
- **RabbitMQ**：Erlang 开发，基于 AMQP 协议。可靠性高、路由功能丰富。企业级应用。
- **Kafka**：Apache 顶级项目。高吞吐量、分布式、持久化、适合大数据场景。日志收集、实时数据流。
- **RocketMQ**：Alibaba 开源。高性能、高可靠、支持事务消息、顺序消息。电商、金融、高并发交易。

### 29. 请描述分布式一致性（CAP 定理、BASE 理论）。

**参考答案**：

**CAP 定理**：分布式系统中，一致性（Consistency）、可用性（Availability）和分区容错性（Partition tolerance）三者不可同时满足，最多只能同时满足两个。

1. **一致性（C）**：所有节点在同一时间看到的数据完全一致
2. **可用性（A）**：每个请求都能收到（非错误）响应，但不保证数据最新
3. **分区容错性（P）**：系统在网络分区情况下仍能正常运行

**CAP 三选二**：
- **CP**：保证一致性和分区容错性，拒绝某些请求（可用性降低）。如：MongoDB、HBase、Zookeeper
- **AP**：保证可用性和分区容错性，返回的数据可能不是最新的。如：Cassandra、大多数电商系统
- **CA**：保证一致性和可用性，放弃分区容错。传统关系型数据库（单节点）

**注意**：网络分区在分布式系统中难以避免，所以 P 通常必须保证，实际在 C 和 A 之间权衡。

**BASE 理论**：Basically Available（基本可用）、Soft State（软状态/允许存在中间状态）、Eventually Consistent（最终一致性）。是对大型分布式系统的实践总结。

**最终一致性实现方案**：读时修复、写时修复、反熵（节点定期对比同步）、基于消息队列。
