## 第一部分：专业面试题（30 道）

### 1.1 数据结构与算法

**题目 1**：请解释什么是时间复杂度和空间复杂度，并分析快速排序的平均和最坏时间复杂度。

**参考答案框架**：
- 时间复杂度：算法执行所需的时间量级，用大O表示法描述
- 空间复杂度：算法执行所需的额外空间量级
- 快速排序：平均 O(n log n)，最坏 O(n²)（当已排序或所有元素相同时）
- 空间复杂度：平均 O(log n)（递归栈深度），最坏 O(n)
- 广工上机考察的重点算法：排序、查找、链表、二叉树、图、DP、字符串处理

---

**题目 2**：什么是哈希表？如何解决哈希冲突？请列举至少三种方法。

**参考答案框架**：
- 哈希表（散列表）：通过哈希函数将关键字映射到数组索引，实现 O(1) 平均查找/插入/删除
- 冲突解决方法：
  1. **开放寻址法**：线性探测（Hi = (H(key) + i) mod m）、二次探测、双重哈希
  2. **链地址法**：每个槽位维护一个链表，冲突元素链在同一位置
  3. **再哈希法**：使用多个哈希函数，冲突时换用下一个哈希函数
  4. **建立公共溢出区**：将冲突元素放入专用溢出表
- 延伸问题：负载因子、重哈希时机、Java HashMap 采用链地址法 + 红黑树优化

**题目 3**：请比较数组和链表的优缺点，并说明各自的适用场景。

**参考答案框架**：

| 特性 | 数组 | 链表 |
|------|------|------|
| 内存分配 | 连续内存，固定大小（静态数组）或动态扩容 | 非连续内存，动态分配 |
| 随机访问 | O(1)，支持下标直接访问 | O(n)，需从头遍历 |
| 插入/删除 | O(n)（需移动元素） | O(1)（已知节点位置时） |
| 缓存友好 | 连续内存 → 缓存命中率高 | 分散内存 → 缓存不友好 |
| 空间浪费 | 预留空间可能浪费 | 每个节点需额外指针空间 |

**适用场景**：
- 数组：数据量已知、频繁随机访问、二分查找
- 链表：频繁插入删除、数据量动态变化、需要动态扩容
- 上机编程注意：链表操作注意空指针检查、头结点处理

**题目 4**：什么是二叉搜索树（BST）？它的中序遍历有什么特点？平衡二叉树（AVL）和红黑树有什么区别？

**参考答案框架**：
- BST 定义：左子树所有节点值 < 根节点值 < 右子树所有节点值
- 中序遍历结果：**有序序列**（递增）
- AVL 树：严格平衡，左右子树高度差 ≤ 1，查找效率高但旋转频繁
- 红黑树：近似平衡，通过颜色标记和旋转维护，插入删除效率更高
- 应用：C++ std::map/std::set 使用红黑树；数据库索引用 B+ 树
- 广工上机曾考察：二叉树遍历、BST 插入/查找

**题目 5**：请描述 Dijkstra 算法的思想和实现步骤。它能处理负权边吗？为什么？

**参考答案框架**：
- **思想**：贪心算法，从起点出发，每次选择当前距离最小的顶点，更新其邻接顶点的距离
- **实现步骤**：
  1. 初始化 dist 数组，起点为 0，其他为 ∞
  2. 使用优先队列（最小堆）维护待处理顶点
  3. 每次取出距离最小的顶点 u，标记为已处理
  4. 遍历 u 的所有邻接顶点 v，尝试松弛：dist[v] = min(dist[v], dist[u] + weight(u,v))
  5. 重复直到所有顶点处理完毕
- **时间复杂度**：O((V+E) log V)（优先队列实现）
- **负权边问题**：Dijkstra 不能处理负权边（更不能处理负环）
  - 原因：贪心策略基于"选出的最小距离顶点不会再被更新"的假设，负权边会使这个假设失效
  - 例如：已确定顶点 A 距离为 5，但可能存在路径 A→B→...→A，总权重为负，A 距离可以更小
- **替代方案**：Bellman-Ford（可处理负权边，检测负环）、SPFA（Bellman-Ford 队列优化）

**题目 6**：什么是动态规划（DP）？请说明动态规划的三要素，并举例说明（如 0-1 背包问题）。

**参考答案框架**：
- **动态规划**：将复杂问题分解为子问题，通过保存子问题的解避免重复计算
- **三要素**：
  1. **最优子结构**：问题的最优解包含子问题的最优解
  2. **重叠子问题**：子问题会被多次用到
  3. **状态转移方程**：描述大问题与子问题之间的关系
- **0-1 背包问题**：
  - 定义：dp[i][w] = 前 i 个物品，容量 w 时的最大价值
  - 状态转移：dp[i][w] = max(dp[i-1][w], dp[i-1][w-wᵢ] + vᵢ)
  - 初始化：dp[0][...] = 0, dp[...][0] = 0
  - 空间优化：滚动数组（从后向前遍历）可将空间从 O(nW) 优化到 O(W)
- 广工上机常考 DP 类型：区间 DP、状态压缩 DP、线性 DP

**题目 7**：请解释图的深度优先搜索（DFS）和广度优先搜索（BFS），并比较它们的应用场景。

**参考答案框架**：

| 特性 | DFS | BFS |
|------|-----|-----|
| 策略 | 深度优先，一条路走到黑再回溯 | 广度优先，按层遍历 |
| 数据结构 | 栈（或递归栈） | 队列 |
| 空间复杂度 | O(h)，h 为树/图的深度 | O(w)，w 为树/图的宽度 |
| 路径特性 | 不保证最短 | 无权图保证最短路径 |
| 典型应用 | 拓扑排序、连通分量、回溯、全排列、八皇后 | 最短路径（无权图）、层序遍历、多源 BFS |

- **上机实现要点**：
  - DFS：注意递归深度限制（可能栈溢出，改用迭代）
  - BFS：队列操作 + visited 数组标记已访问
  - 记录路径时需额外维护父节点数组

**题目 8**：什么是拓扑排序？如何实现？它适用于什么样的图？

**参考答案框架**：
- **拓扑排序**：对有向无环图（DAG）的顶点进行线性排序，满足：若存在边 u→v，则 u 在排序中出现在 v 之前
- **应用场景**：课程安排、任务调度、依赖关系处理、编译顺序
- **实现方法**：
  1. **Kahn 算法（BFS 方式）**：
     - 计算所有顶点入度
     - 将入度为 0 的顶点入队
     - 依次出队，加入结果，将其邻接顶点入度减 1，若减为 0 则入队
     - 若结果数 ≠ 顶点数，说明有环
  2. **DFS 方式**：
     - 递归访问，完成时加入栈
     - 检测后向边判断是否有环
     - 最终输出栈的逆序
- **适用图**：有向无环图（DAG），有环图无法拓扑排序

**题目 9**：请简要说明归并排序和堆排序的原理，并比较它们的优缺点。

**参考答案框架**：

| 排序 | 原理 | 时间复杂度 | 空间复杂度 | 稳定性 | 优点 | 缺点 |
|------|------|-----------|-----------|--------|------|------|
| **归并排序** | 分治：分割→排序→合并 | O(n log n) 三种情况 | O(n) | **稳定** | 性能稳定，外部排序友好 | 需要额外空间 |
| **堆排序** | 建堆→依次取出堆顶→调整 | O(n log n) 三种情况 | O(1) | **不稳定** | 原地排序，空间好 | 建堆开销，缓存不友好 |

- **归并排序应用**：外部排序（数据量大无法全部加载到内存）
- **堆排序应用**：操作系统进程调度、优先队列、Top-K 问题
- **快速排序**：平均最快，但最坏 O(n²)，实际工程中使用混合策略（如 TimSort）
- 广工上机可能直接考排序实现或需要排序作为辅助

**题目 10**：什么是字符串匹配的 KMP 算法？它相比朴素匹配有什么优势？

**参考答案框架**：
- **KMP 核心思想**：利用已匹配的部分信息，避免从头重新匹配
- **关键**：预处理模式串，构建 next 数组（失败函数/最长前缀后缀数组）
  - next[i] 表示模式串前 i 个字符组成的子串中，最长相等真前缀和真后缀的长度
- **匹配过程**：
  - 若当前字符匹配，两指针都前进
  - 若失配，主串指针不动，模式串指针根据 next 数组回退
- **时间复杂度**：O(n + m)（n 为主串长度，m 为模式串长度）
- **对比朴素匹配**：
  - 朴素匹配：最坏 O(nm)，每次失配都要从头匹配
  - KMP：最坏仍是线性时间，避免了不必要的回溯
- **上机实现**：注意 next 数组计算的两种实现方式（标准和优化）

### 1.2 操作系统

**题目 11**：什么是进程和线程？它们有什么区别和联系？

**参考答案框架**：

| 特性 | 进程 | 线程 |
|------|------|------|
| 定义 | 资源分配的基本单位 | CPU 调度的基本单位 |
| 资源拥有 | 拥有独立地址空间和资源 | 共享所属进程的资源 |
| 上下文切换 | 切换开销大（切换页表/内核栈） | 切换开销小（仅保存寄存器/栈） |
| 通信方式 | 管道、消息队列、共享内存、信号量、套接字 | 共享内存（需同步机制） |
| 并发性 | 进程间并发 | 进程内线程并发 + 进程间并发 |
| 健壮性 | 一个进程崩溃不影响其他进程 | 一个线程崩溃可能导致整个进程崩溃 |

- **联系**：一个进程可以包含多个线程，线程是进程内的执行单元
- **延伸问题**：多线程 vs 多进程；用户态线程 vs 内核态线程；Linux pthread

**题目 12**：请解释进程调度算法（FCFS、SJF、RR、优先级调度），并比较优缺点。

**参考答案框架**：

| 算法 | 全称 | 原理 | 优点 | 缺点 |
|------|------|------|------|------|
| **FCFS** | 先来先服务 | 按到达顺序执行 | 简单、公平 | 平均等待时间长，短作业可能长时间等待 |
| **SJF/SPN** | 最短作业优先 | 选择执行时间最短的作业 | 平均等待时间最短（理论最优） | 需预估执行时间，长作业可能饿死 |
| **RR** | 时间片轮转 | 按时间片轮流执行 | 公平、响应性好 | 时间片大小选择关键，上下文切换开销 |
| **优先级调度** | Priority | 高优先级优先执行 | 可区分紧急程度 | 低优先级进程可能饿死 |

- **SJF 的变体**：SRTF（最短剩余时间优先，抢占式）
- **优先级调度的问题**：饥饿（饿死）→ 解决方法：老化（随时间提升低优先级）
- **多级反馈队列**：综合多种算法优点，实际系统常用（如 Linux CFS）

**题目 13**：什么是死锁？死锁产生的四个必要条件是什么？如何预防和解除死锁？

**参考答案框架**：
- **死锁定义**：多个进程因互相等待对方占用的资源而无限期阻塞的现象
- **四个必要条件（必要不充分）**：
  1. **互斥**（Mutual Exclusion）：资源不能同时被多个进程使用
  2. **占有并等待**（Hold and Wait）：进程占有资源同时等待其他资源
  3. **不可抢占**（No Preemption）：资源不能被强制剥夺
  4. **循环等待**（Circular Wait）：存在循环的资源等待链
- **死锁预防**（破坏必要条件）：
  - 破坏互斥：使资源可共享（如只读文件）→ 困难
  - 破坏占有并等待：一次性申请所有资源，或申请资源前释放已占有资源
  - 破坏不可抢占：允许系统强制剥夺进程资源
  - 破坏循环等待：对资源顺序编号，按序申请
- **死锁避免**：银行家算法（安全序列检测）
- **死锁检测与恢复**：检测并强制撤销进程或剥夺资源
- **鸵鸟策略**：忽略死锁（如 Linux，靠用户处理）

**题目 14**：请解释虚拟内存的概念、实现原理和优点。

**参考答案框架**：
- **虚拟内存**：为每个进程提供独立、连续、庞大的虚拟地址空间，实际映射到分散的物理内存和磁盘
- **实现原理**：
  1. **分页**（Paging）：将虚拟内存划分为固定大小的页（如 4KB），物理内存划分为页帧
  2. **页表**（Page Table）：记录虚拟页到物理页帧的映射
  3. **地址翻译**：MMU（内存管理单元）将虚拟地址转换为物理地址
  4. **缺页中断**（Page Fault）：访问的页不在内存时，从磁盘加载
  5. **页面置换**：内存满时选择淘汰的页（FIFO、LRU、Clock、OPT）
  6. **TLB（Translation Lookaside Buffer）**：页表缓存，加速地址翻译
- **优点**：
  - 进程地址空间隔离，安全性高
  - 逻辑内存可以大于物理内存（按需调入）
  - 简化内存管理（每个进程看到连续地址空间）
  - 提高内存利用率和系统吞吐量
  - 支持共享库和内存共享
- **延伸**：内存抖动（Thrashing）、工作集模型、Linux 页表结构

**题目 15**：什么是页面置换算法？请比较 FIFO、LRU、最优置换（OPT）的特点。

**参考答案框架**：

| 算法 | 策略 | 特点 | 问题/挑战 |
|------|------|------|----------|
| **FIFO** | 淘汰最早进入的页 | 实现简单 | Belady 异常（增加页帧数，缺页率反而上升） |
| **LRU** | 淘汰最久未使用的页 | 性能较好，接近最优 | 精确实现开销大（需时间戳或链表） |
| **OPT** | 淘汰未来最久不用的页 | 理论最优，缺页率最低 | 无法实现（需预知未来），用作理论对比 |
| **Clock** | 环形扫描引用位为 0 的页 | LRU 近似，开销小 | 第二次机会算法、增强时钟算法 |

- **LRU 近似实现**：时钟算法（CLOCK/NRU），牺牲精度换取性能
- **LRU 精确实现**：哈希表 + 双向链表（O(1) 访问 + O(1) 移动）
- **Belady 异常**：FIFO 特有，说明性能不随资源增加单调递增
- **工作集算法**：考虑进程局部性原理，动态调整分配页数

**题目 16**：请解释文件系统的概念。FAT、NTFS、Ext2/3/4 有什么区别？

**参考答案框架**：
- **文件系统**：操作系统中负责组织、存储、管理文件的模块，提供文件的访问接口（创建、读写、删除、权限）
- **常见文件系统对比**：

| 文件系统 | 特点 | 应用场景 |
|----------|------|---------|
| **FAT16/32** | 简单、无权限、文件大小限制（FAT32 单文件 4GB） | U盘、移动设备、兼容多系统 |
| **NTFS** | 支持权限、加密、压缩、大文件（16TB）、日志 | Windows 默认 |
| **Ext2** | Linux 传统文件系统，无日志 | 早期 Linux，小分区 |
| **Ext3** | Ext2 + 日志，三种日志模式（Journal/Ordered/Writeback） | 旧版 Linux 服务器 |
| **Ext4** | Ext3 升级版，支持更大文件（16TB 文件、1EB 分区）、延迟分配、extents | 主流 Linux 发行版 |
| **XFS** | 高性能日志文件系统，大文件优化，SGI 开发 | 大型服务器、RHEL/CentOS 默认 |
| **ZFS/Btrfs** | 支持快照、校验和、RAID、子卷、写时复制 | 高级存储场景 |

- **文件系统核心数据结构**：超级块、inode、数据块、目录项、位图
- **目录结构**：单级、两级、树形、无环图
- **磁盘调度**：FCFS、SSTF、SCAN、C-SCAN、LOOK

### 1.3 计算机网络

**题目 17**：请解释 OSI 七层模型和 TCP/IP 四层模型，并比较它们。

**参考答案框架**：

| OSI 七层 | 功能 | TCP/IP 对应层 | 典型协议/设备 |
|---------|------|-------------|-------------|
| 7 应用层 | 用户接口、应用服务 | 应用层 | HTTP, FTP, SMTP, DNS, SSH |
| 6 表示层 | 数据格式转换、加密、压缩 | 应用层 | SSL/TLS, JPEG, MPEG |
| 5 会话层 | 会话建立、维护、终止 | 应用层 | RPC, NetBIOS |
| 4 传输层 | 端到端可靠/不可靠传输 | 传输层 | TCP, UDP |
| 3 网络层 | 路由选择、分组转发 | 网络层 | IP, ICMP, ARP, 路由器 |
| 2 数据链路层 | 相邻节点帧传输、差错控制 | 网络接口层 | 以太网, PPP, 交换机 |
| 1 物理层 | 比特流传输、物理媒介 | 网络接口层 | 光纤, 双绞线, 集线器 |

**TCP/IP 四层模型**：应用层 → 传输层 → 网络层 → 网络接口层

**核心区别**：
- OSI 是理论模型（先有模型后有协议），TCP/IP 是实际标准（先有协议后总结模型）
- OSI 将表示层和会话层独立，TCP/IP 合并到应用层
- OSI 强调服务、接口、协议的区分，TCP/IP 更简洁实用

**题目 18**：TCP 和 UDP 有什么区别？各自的应用场景是什么？

**题目 19**：请解释 HTTP 和 HTTPS 的区别，并说明 HTTPS 的工作原理。

**参考答案框架**：

| 特性 | HTTP | HTTPS |
|------|------|-------|
| 全称 | HyperText Transfer Protocol | HTTP over SSL/TLS |
| 端口 | 80 | 443 |
| 安全性 | 明文传输，易被窃听/篡改/冒充 | 加密传输，证书验证 |
| 性能 | 快，无加密开销 | 略慢（握手 + 加密解密开销） |
| URL 前缀 | http:// | https:// |

**HTTPS 工作原理（简化版 TLS 握手）**：
1. **客户端 Hello**：发送支持的加密套件、随机数
2. **服务器 Hello**：选择加密套件，发送证书（含公钥）、随机数
3. **客户端验证**：验证证书合法性（颁发者、有效期、域名）
4. **密钥交换**：客户端生成预主密钥，用服务器公钥加密发送

6. **对称加密通信**：后续使用会话密钥进行对称加密通信

**核心机制**：
- **非对称加密（RSA/ECC）**：用于密钥交换和身份验证
- **对称加密（AES/ChaCha20）**：用于实际数据传输（速度快）
- **证书（PKI/CA）**：验证服务器身份，防止中间人攻击
- **消息摘要（SHA-256）**：保证完整性，检测篡改

**题目 20**：什么是 TCP 的三次握手？为什么不是两次？

**参考答案框架**：

**三次握手过程**：
```
客户端                       服务器
  |  SYN(seq=x)                |
  | -------------------------> |
  |                            |
  |  SYN+ACK(seq=y, ack=x+1)   |
  | <------------------------- |
  |                            |
  |  ACK(ack=y+1)              |
  | -------------------------> |
  |                            |
  （连接建立，开始数据传输）
```

**为什么是三次（不是两次）**：
1. **确认双方收发能力**：
   - 客户端发送 SYN → 证明客户端发送能力正常
   - 服务器收到 SYN 后发送 SYN+ACK → 证明服务器收发能力都正常
   - 客户端收到 SYN+ACK 后发送 ACK → 双方都确认对方能力正常
   - 两次握手只能证明：客户端发送 → 服务器接收/发送，**无法证明客户端能接收**

2. **防止过期的连接请求**：
   - 客户端发送 SYN 后超时重传，旧 SYN 延迟到达
   - 若只有两次握手，服务器收到旧 SYN 后直接建立连接，浪费资源
   - 三次握手允许客户端通过 ACK 确认是否建立本次连接

3. **同步双方序列号**：
   - TCP 是可靠传输，需要双方维护独立的序列号空间
   - SYN 携带初始序列号，需要对方 ACK 确认（双向同步）
   - 两次握手只能同步一个方向的序列号

**为什么不是四次**：
- 三次已经足够，四次冗余。服务器的 SYN 和 ACK 可以合并在一个报文中（SYN+ACK），无需分开发送
- 四次挥手需要分开（FIN 和 ACK）是因为 CLOSE_WAIT 状态，应用可能还有数据要发送

### 1.4 数据库

**题目 22**：什么是事务？ACID 四个特性是什么？如何实现？

**参考答案框架**：

**事务（Transaction）**：数据库管理系统中执行的一个逻辑工作单元，包含一组数据库操作

**ACID 四特性**：

| 特性 | 含义 | 实现方式 |
|------|------|---------|
| **A**tomicity 原子性 | 事务中所有操作要么全部完成，要么全部失败 | **回滚日志（Undo Log）**：记录修改前的值，失败时回滚 |
| **C**onsistency 一致性 | 事务执行前后数据库保持一致性约束 | 应用层逻辑 + 数据库约束（主键、外键、唯一约束、检查约束） |
| **I**solation 隔离性 | 并发事务之间互不干扰，各事务看到一致的数据 | **MVCC（多版本并发控制）**、锁机制（行锁/表锁）、隔离级别 |
| **D**urability 持久性 | 事务提交后，修改永久保存，系统崩溃也不丢失 | **重做日志（Redo Log / WAL）**：先写日志后写数据，崩溃时恢复 |

**MySQL 事务实现**：
- InnoDB 引擎支持事务（MyISAM 不支持）
- Undo Log：实现原子性和 MVCC（读视图）
- Redo Log：实现持久性（WAL，Write-Ahead Logging）
- Binlog：主从复制
- 双写缓冲（Doublewrite Buffer）：防止部分写失败

**题目 23**：请解释数据库的四种隔离级别，以及它们解决的问题。

**参考答案框架**：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 实现方式 |
|---------|------|----------|------|---------|
| **读未提交（Read Uncommitted）** | ✓ | ✓ | ✓ | 基本无隔离 |
| **读已提交（Read Committed）** | ✗ | ✓ | ✓ | 语句级快照（Oracle、SQL Server 默认） |
| **可重复读（Repeatable Read）** | ✗ | ✗ | ✓ | 事务级快照（MySQL InnoDB 默认，实际通过 Next-Key Lock 解决幻读） |
| **可串行化（Serializable）** | ✗ | ✗ | ✗ | 事务串行执行，加锁严格 |

**三个问题定义**：
1. **脏读**：读取了其他事务未提交的数据（事务 B 读取了事务 A 未提交的修改，A 回滚后 B 读到的数据无效）
2. **不可重复读**：同一事务内，同一查询两次执行结果不同（其他事务修改并提交了数据）
3. **幻读**：同一事务内，同一范围查询两次返回的行数不同（其他事务插入/删除了范围内的行）

**不可重复读 vs 幻读区别**：
- 不可重复读：关注 **数据值的变化**（UPDATE）
- 幻读：关注 **行数的变化**（INSERT/DELETE）

**MySQL 实际情况**：
- InnoDB 默认隔离级别是 RR（可重复读）
- RR 级别下通过 **Next-Key Lock（记录锁 + 间隙锁）** 防止幻读
- Serializable 级别性能较差，一般不使用

**题目 24**：什么是数据库索引？B+ 树索引和哈希索引有什么区别？

**参考答案框架**：

**索引**：数据库中用于加速数据查找的数据结构，类似于书籍的目录

**B+ 树索引 vs 哈希索引对比**：

| 特性 | B+ 树索引 | 哈希索引 |
|------|----------|---------|
| 数据结构 | 多路平衡搜索树 | 哈希表 |
| 等值查询 | O(log n) | O(1) 平均 |
| 范围查询 | 支持（叶子节点有序链表） | 不支持 |
| 排序（ORDER BY） | 支持（索引本身有序） | 不支持 |
| 前缀匹配 / 模糊查询 | 支持（LIKE 'abc%'） | 不支持 |
| 最左前缀原则 | 适用 | 不适用 |
| 哈希冲突 | 无 | 有冲突需解决 |
| 适用场景 | 绝大多数场景，MySQL 默认 | 仅适用于等值查询为主的场景（如 Redis、Memcached） |

**B+ 树 vs B 树区别**：
- B+ 树非叶子节点只存索引键，B 树节点存完整数据
- B+ 树叶子节点通过链表相连，便于范围查询
- B+ 树查询必须到叶子节点命中，B 树可能在中间层命中

**索引分类**：
- 主键索引（聚簇索引）：叶子节点存完整数据行
- 二级索引（辅助索引）：叶子节点存主键值
- 联合索引：多个字段组合，遵循最左前缀原则
- 覆盖索引：查询字段全在索引中，无需回表

**索引失效场景**：
- 对索引列使用函数/表达式
- LIKE 以通配符开头（'%abc'）
- 隐式类型转换
- OR 条件中非所有列都有索引
- 范围查询后列失效

**题目 25**：请解释什么是 SQL 注入，并说明如何预防。

**参考答案框架**：

**SQL 注入**：通过在用户输入中注入恶意 SQL 代码，使数据库执行非预期操作的攻击手段

**典型示例**：
```sql
-- 原始查询（假设用户名直接拼接）
SELECT * FROM users WHERE username = '$username' AND password = '$password'

-- 恶意输入：用户名输入 ' OR '1'='1
SELECT * FROM users WHERE username = '' OR '1'='1' AND password = '' -- 结果：恒真，绕过验证
```

**其他注入类型**：
1. **基于布尔的盲注**：通过页面差异判断条件真假（如 `?id=1 AND 1=2`）
2. **基于时间的盲注**：通过 SLEEP() 判断条件真假
3. **UNION 查询注入**：UNION SELECT 从其他表获取数据
4. **堆叠查询注入**：`;` 后追加额外查询
5. **二阶注入**：注入数据存储后被再次使用时触发

**预防方法**：
1. **参数化查询 / 预编译语句（最有效）**：
   ```java
   PreparedStatement pstmt = conn.prepareStatement(
       "SELECT * FROM users WHERE username = ? AND password = ?"
   );
   pstmt.setString(1, username);
   pstmt.setString(2, password);
   ```
2. **输入验证和过滤**：白名单验证（如用户名只允许字母数字）
3. **最小权限原则**：数据库账号只授予必要权限（不使用 root）
4. **WAF（Web 应用防火墙）**：检测并拦截常见注入特征
5. **ORM 框架**：使用 MyBatis、Hibernate 等框架的参数绑定
6. **数据库安全配置**：禁用不必要的函数（如 `LOAD_FILE`、`INTO OUTFILE`）
7. **错误信息脱敏**：不向用户暴露详细数据库错误信息

### 1.5 计算机组成原理

**题目 26**：请解释计算机的存储层次结构，并说明为什么需要这种层次结构。

**参考答案框架**：

```
寄存器（Register）  ── 最快，最小，最贵
   ↓
L1 Cache（CPU 内部）  ── 几 KB 到几十 KB，纳秒级访问
   ↓
L2 Cache             ── 几百 KB 到几 MB
   ↓
L3 Cache             ── 几 MB 到几十 MB，多核共享
   ↓
主存（DRAM/RAM）      ── 几 GB 到几十 GB，纳秒级（~100ns）
   ↓
固态盘（SSD）         ── 几百 GB 到几 TB，微秒级（~100μs）
   ↓
机械盘（HDD）         ── 几 TB，毫秒级（~10ms）
   ↓
磁带/云存储           ── 最慢，最大，最便宜
```

**原理**：程序局部性原理
- **时间局部性**：刚访问的数据不久后可能再次访问 → 放在缓存
- **空间局部性**：访问某地址后，附近地址也可能被访问 → 按块加载

**缓存命中与未命中**：
- CPU 首先在 L1 查找 → L2 → L3 → 主存 → 磁盘
- 每一层未命中都需要到下一层获取，延迟急剧增加
- 缓存一致性协议（MESI）：多核 CPU 保证各核心缓存一致

**为什么需要层次结构**：
- **成本与性能的折中**：快速存储昂贵且容量小，慢速存储便宜且容量大
- **利用程序局部性**：热点数据放在高层，提高平均访问速度
- **分层管理**：每层独立管理，设计简化

**题目 27**：什么是流水线（Pipeline）？请解释流水线冒险及解决方法。

**参考答案框架**：

**流水线**：将一条指令的执行分解为多个阶段，多条指令并行执行，提高 CPU 吞吐量

**经典 5 级流水线（MIPS）**：
1. **IF**（Instruction Fetch）：取指令
2. **ID**（Instruction Decode）：指令译码 + 读寄存器
3. **EX**（Execute）：执行运算/地址计算
4. **MEM**（Memory Access）：访问内存
5. **WB**（Write Back）：结果写回寄存器

**流水线冒险（Hazard）**：

| 冒险类型 | 原因 | 解决方法 |
|---------|------|---------|
| **结构冒险** | 硬件资源冲突（如同时读写同一存储器） | 资源重复（指令缓存/数据缓存分离）、流水线停顿 |
| **数据冒险** | 指令依赖前一条指令结果 | 1. 流水线停顿（插入气泡）<br>2. 数据转发（Forwarding，旁路）<br>3. 编译器调度 |
| **控制冒险** | 分支指令导致流水线需要清空 | 1. 分支预测（静态/动态预测）<br>2. 延迟分支（填充有用指令）<br>3. 预测失败时清空流水线 |

**数据转发示例**：
```
ADD R1, R2, R3   → 结果在 EX 阶段结束时产生
SUB R4, R1, R5   → 需要 R1，通过转发从 EX/MEM 缓冲获取，无需等 WB 阶段
```

**分支预测技术发展**：静态预测（总是取/总是不取）→ 1 位预测器 → 2 位饱和计数器 → 全局/局部/ tournament 预测 → TAGE 预测器（现代处理器）

**流水线深度**：
- 经典 RISC：5-7 级
- Intel Pentium 4：31 级（超长流水线，频率高但效率低）
- 现代处理器：10-20 级 + 乱序执行（ROB） + 超标量（多发射）

### 1.6 软件工程与编程语言

**题目 28**：什么是面向对象编程（OOP）？请解释三大特性（封装、继承、多态）。

**参考答案框架**：

**OOP 定义**：以对象为基本单元，将数据和操作数据的方法封装在一起的编程范式

**三大特性**：

1. **封装（Encapsulation）**：
   - 将数据和操作数据的方法绑定在一起，对外隐藏内部实现细节
   - 通过访问控制（public/private/protected）实现
   - 优点：降低耦合、提高安全性、便于维护
   - 例子：类的私有成员变量 + public getter/setter

2. **继承（Inheritance）**：
   - 子类（派生类）继承父类（基类）的属性和方法，实现代码复用
   - 支持层次化、分类化的设计
   - 单继承（Java、C#） vs 多继承（C++，通过虚继承解决菱形继承问题）
   - 组合优于继承：灵活、低耦合

3. **多态（Polymorphism）**：
   - 同一接口有不同实现方式，调用时根据实际类型选择实现
   - **编译时多态**（静态绑定）：方法重载（overload）、运算符重载
   - **运行时多态**（动态绑定）：方法重写（override）+ 虚函数/抽象类/接口
   - 实现机制：虚函数表（vtable）+ 虚表指针（vptr）

**扩展**：面向对象设计原则（SOLID）：
- S：单一职责原则（Single Responsibility）
- O：开闭原则（Open-Closed，对扩展开放，对修改关闭）
- L：里氏替换原则（Liskov Substitution，子类可替换父类）
- I：接口隔离原则（Interface Segregation，小接口优于大接口）
- D：依赖倒置原则（Dependency Inversion，依赖抽象而非具体）

**题目 29**：请解释什么是设计模式，并列举你熟悉的几种设计模式及其应用场景。

**参考答案框架**：

**设计模式**：软件设计中常见问题的通用、可复用解决方案，是前人经验的总结

**常见设计模式分类及示例**：

**创建型模式**（关注对象创建）：

| 模式 | 用途 | 典型场景 |
|------|------|---------|
| **单例（Singleton）** | 确保一个类只有一个实例，提供全局访问点 | 配置管理器、日志器、数据库连接池 |
| **工厂方法（Factory Method）** | 定义创建对象的接口，让子类决定实例化哪个类 | 需要根据配置/运行时条件选择具体实现 |
| **抽象工厂（Abstract Factory）** | 创建相关联的产品族 | UI 工具包（不同操作系统的按钮/窗口） |
| **建造者（Builder）** | 分步构建复杂对象，分离构建与表示 | 构造函数参数过多、对象配置项复杂 |
| **原型（Prototype）** | 通过复制已有对象创建新对象 | 原型克隆、深拷贝 vs 浅拷贝 |

**结构型模式**（关注对象组合）：
- **适配器（Adapter）**：将一个接口转换为客户期望的另一个接口（类适配器/对象适配器）
- **装饰器（Decorator）**：动态地给对象添加额外职责（继承的灵活替代方案，如 Java IO）
- **代理（Proxy）**：为其他对象提供代理以控制访问（远程代理、虚拟代理、保护代理）
- **外观（Facade）**：为复杂子系统提供统一高层接口

**行为型模式**（关注对象通信）：
- **策略（Strategy）**：定义一系列算法，封装后可互换使用（替代大量 if-else）
- **观察者（Observer）**：一对多依赖，对象状态变化时通知所有观察者（发布-订阅）
- **模板方法（Template Method）**：定义算法骨架，子类实现具体步骤
- **迭代器（Iterator）**：遍历集合元素而不暴露内部表示

**应用建议**：面试时最好能结合自己做过的项目举例说明某个模式的使用，如：
- 项目中用策略模式处理不同的支付方式（支付宝/微信/银联）
- 用观察者模式实现消息通知系统
- 用单例模式管理数据库连接池

**题目 30**：请谈谈你对 Git 的理解，以及你常用的 Git 命令有哪些？请解释 merge 和 rebase 的区别。

**参考答案框架**：

**Git 简介**：分布式版本控制系统（DVCS），由 Linus Torvalds 开发，用于管理源代码历史

**核心概念**：
- **工作区（Working Directory）**：当前操作的文件
- **暂存区（Staging Area / Index）**：git add 后存放的区域
- **本地仓库（Repository）**：git commit 后记录的版本库（.git 目录）
- **远程仓库**：GitHub / GitLab / Gitee 等

**常用命令**：

| 命令 | 用途 |
|------|------|
| `git init` | 初始化仓库 |
| `git clone <url>` | 克隆远程仓库 |
| `git add <file>` / `git add .` | 添加文件到暂存区 |
| `git commit -m "message"` | 提交到本地仓库 |
| `git status` | 查看工作区状态 |
| `git log` / `git log --oneline` | 查看提交历史 |
| `git diff` | 查看差异 |
| `git branch` | 查看/创建/删除分支 |
| `git checkout <branch>` / `git switch <branch>` | 切换分支 |
| `git merge <branch>` | 合并分支 |
| `git rebase <branch>` | 变基操作 |
| `git pull` = `git fetch` + `git merge` | 拉取并合并远程更新 |
| `git push` | 推送到远程仓库 |
| `git stash` | 暂存当前工作进度 |
| `git reset` / `git revert` | 撤销/回退 |
| `git cherry-pick <commit>` | 选择性应用某个提交 |

**merge vs rebase 对比**：

| 特性 | git merge | git rebase |
|------|----------|-----------|
| 原理 | 合并两个分支，产生合并提交 | 将当前分支的提交"移动"到目标分支之后 |
| 历史 | 保留完整分支历史，可能有分叉 | 线性历史，更清晰 |
| 提交数量 | 多一个 merge commit | 重新计算 commit hash |
| 安全性 | 安全，非破坏性操作 | 重写历史，不要在公共分支使用 |
| 冲突处理 | 一次性解决冲突 | 每个提交可能都要处理冲突 |
| 适用场景 | 公共分支合并、保留历史 | 个人分支整理、提交前整理历史 |

**Git Flow 工作流**：
- `main/master`：主分支，稳定版本
- `develop`：开发分支，最新开发进度
- `feature/*`：功能分支
- `release/*`：发布分支，准备发布
- `hotfix/*`：紧急修复分支

**面试小提示**：如果有用过 Git 管理项目的经验，可以谈具体的分支策略、解决冲突的经历

**题目 41**：请谈谈你对"人工智能"或某一当前热门技术的看法和理解。

**参考答案框架**（以人工智能为例，展示思考的深度和广度）：

**AI 的发展阶段**：
- **符号主义**（早期 AI）：基于规则和逻辑推理，如专家系统
- **连接主义**（神经网络）：感知机 → 深度学习 → 大模型
- **行为主义**（强化学习）：从环境交互中学习策略

**当前 AI 的核心进展**：
1. **大语言模型（LLM）**：GPT、Claude、Gemini、LLaMA、Qwen、通义千问
   - 参数量从亿级到万亿级，展现出涌现能力
   - 应用：对话助手、代码生成、内容创作、智能分析
2. **多模态**：文本+图像+音频+视频统一处理（如 GPT-4V、Gemini）
3. **AIGC**：生成式 AI 在绘画、写作、视频生成中的应用
4. **Agent**：基于 LLM 的智能体，能自主规划和执行任务

**AI 面临的挑战**：
1. **幻觉问题**：模型可能生成看似合理但实际错误的内容
2. **可解释性**：深度学习的"黑盒"特性，决策过程难以解释
3. **安全性与对齐**：防止模型被滥用，确保 AI 行为符合人类价值观
4. **算力与能耗**：训练大模型需要大量计算资源
5. **数据质量与版权**：训练数据的质量、版权归属问题

**对研究生学习的启示**：
- 作为计算机专业学生，需要关注 AI 进展，但不盲从热点
- 打好基础（数学、编程、系统能力）比追逐热点更重要
- AI 是工具，如何用好 AI 提升研究/开发效率值得思考
- 可以关注 AI + 具体领域（如 AI for Science、AI + 软件工程、AI + 网络安全）

**注意**：回答热门技术话题要谨慎，避免暴露知识漏洞。如果对该方向不熟悉，不要假装懂，可以诚实说"我对 XX 方向了解不多，但我最近在关注 YY 方向"

**Question 55: Please briefly explain [a fundamental concept]. (E.g., What is TCP/IP? What is Object-Oriented Programming?)**

**参考回答**（以 TCP/IP 为例，英语考察一般问题不会太难，重点考察表达能力）：

```
**What is TCP/IP?**

TCP/IP stands for Transmission Control Protocol / Internet Protocol. It is the fundamental protocol suite that enables communication across the Internet.

**TCP (Transmission Control Protocol)** operates at the transport layer. It provides:
- **Connection-oriented communication**: A connection must be established before data transmission (three-way handshake).
- **Reliable delivery**: TCP ensures that data arrives in order, without loss or duplication. It uses acknowledgment (ACK) and retransmission mechanisms.
- **Flow control**: Prevents a fast sender from overwhelming a slow receiver (sliding window).
- **Congestion control**: Prevents the network from becoming congested.

**IP (Internet Protocol)** operates at the network layer. It provides:
- **Addressing**: Each device gets an IP address (e.g., 192.168.1.1 in IPv4).
- **Routing**: Determines the path for data packets from source to destination across multiple networks.
- **Best-effort delivery**: IP does not guarantee reliability; that is TCP's responsibility.

**How they work together:**
TCP divides data into packets, numbers them, and hands them to IP. IP handles routing these packets across the network. At the destination, TCP reassembles the packets in order and requests retransmission if any are missing.

Together, TCP/IP forms the backbone of modern Internet communication.
```
